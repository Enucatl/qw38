# OPT-152 — Screen vector attention throughout the sub-8K decode region

Status: pending. Dependencies: OPT-135, OPT-150, OPT-151. Coupled IDs: none.
Priority: P1. Plan impact: none.

## Outcome

Close the current 4097–8191 warp-query fallback and test whether llama-style
vector coverage also benefits prefixes below 1024. Reuse the kept OPT-148
consumer; this is a bounded dispatch experiment, not another attention rewrite.
Run against the actual kept or retained parent from OPT-151.

## Evidence and candidates

Read OPT-150's dispatch table, `cuda/attention_decode_path.cuh`, every caller
of `decode_attention_vec128_path_for_position`, graph bucket selection,
`cuda/opt148_short_decode_flash.cuh`, OPT-148 raw evidence, and the shared
testing strategy. Current verified_max=4096 leaves a real fallback above 4K.
Llama's padded K.ne[1] boundary is not Quartz position; retain position>=8192
long dispatch and document that exact threshold parity remains untested.

Freeze exactly two candidate dispatch rules, existing vector arithmetic and
n_parts=16 unchanged; no OPT-130 occupancy sweep:

1. `flash_vec_gap_only_v1`: OPT-148 for positions [1024,8191], warp_query
   below 1024. Target D6144 decode_only.
2. `flash_vec_all_short_v1`: OPT-148 for positions [0,8191]. Targets D512 and
   D6144 decode_only; D128 is a non-regression guard, not a mandatory gain.

Both retain the parent's long consumer and P4096 prefill. Do not increase
verified_max globally in a way that admits other kernels or unsupported shapes.
No new cache, query-preparation fusion, partition tuning or KV dtype change.

## Screen and choice

Check positions 0,1,127,128,511,1023,1024,4095,4096,4097,6144,8190,8191,8192
with real layer 3/7/63 inputs and existing sampled-reference tolerances,
candidate-row visibility, empty/tail partitions and actual graph/eager dispatch.
Add a focused runnable boundary/graph check to the existing diagnostic, not
source-string assertions. Test graph replay crossing 1024,4096 and 8192 with
live device position; host-only selector equality is insufficient.

Screen both rules at D128/D512/D6144, one warmup + three alternating complete
16-layer attention pairs per candidate/shape. Advance at most one candidate.
Prefer all_short only if both its target family means improve and D128 loses
no more than 2%; otherwise gap_only may advance if D6144 improves and unchanged
regions behave as parent. Freeze this choice rule before sampling. If neither
passes, record screened_out and retain parent; do not invent a new threshold.

## Acceptance

For the survivor freeze its already-declared targets and OPT-135
`target_guard_v2` roles: three warmups + ten restored AB/BA pairs, 256 decode
evals. Guard every target's complete_request; guard D128/D2048/D8192/D32768
decode_only and complete_request plus P4096 prefill. For gap_only also guard
D512 decode_only and complete_request. All target L>1, guard L>=0.98, every
decode p95 ratio<=1.05; report 2% materiality separately. No post-hoc promotion
of a neutral target to a guard or second acceptance sitting after failure.

Measure candidate OPT-058 quality exercising the newly admitted region, using
the active frozen budgets; identical historical D2048 NLL alone is insufficient.
Validate prompt/decode handoff, graph/eager equality, cancellation, checkpoint
restoration across new coverage boundaries and existing memory/reserve gates
where graph/workspace changes apply. Preserve long/prefill quality authority.

Deliver `evidence/optimization/opt152-vector-coverage/REPORT.md`, candidate
contracts, actual dispatch records, raw screen/acceptance and one independent
family-time reconstruction. Use existing OPT-148 and OPT-150 tools, shared
tiers, one build, GPU lock and declared deadlines. Compare the admitted regions
with actual selected pinned llama kernels using the same logical frontier and
explicit padding/dtype identities. A keep requires complete quality/state and
whole-engine evidence; missing work is incomplete, not no_opportunity.
Report candidate versus shipping deltas and final dispatch ranges explicitly.
