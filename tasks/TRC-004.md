## Goal and boundaries

Expose the CUDA scheduler's five admitted FP32-visible correctness boundaries
through the existing backend-neutral diagnostic sink, with the same names and
shapes as the scalar trace contract, and prove that their full tensors remain
inside the immutable scalar/oracle-derived gates.

- Constraints: compile the CUDA trace entry point and stable tap literals only
  with `QW38_DIAGNOSTIC_TRACE`; validate the exact filter before model execution;
  force the retained unfused, non-graph path during traced execution; preserve
  the scheduler's candidate-state/frontier-last atomicity; use the pinned CUDA
  13.0.2 SM120 container and installed RTX 5090 for the device gate; do not
  change any value in `pins/scalar_trace_contract.json` or
  `pins/scalar_oracle_tolerances.json`.
- Non-goals: exposing runtime-private GDN, attention, or FFN scratch values that
  are not stable visible boundaries of the fused scheduler; claiming the BF16
  embedding row satisfies the scalar contract's zero-error same-GGUF gate;
  tracing prompt-chunk execution; adding a user-facing CUDA trace command or v1
  bundle driver (owned by pending `EVAL-001`); changing arithmetic, kernels,
  public `Engine`/`Session` APIs, production allocations, graphs, fusion,
  tolerances, authority fixtures, or `plan.md`.
- Plan impact: `none`
- Affected interfaces: a diagnostic-guarded CUDA scheduler entry point accepting
  `internal::TraceFilter`, `internal::TraceSink`, and sink context; exact CUDA
  filters for global `final_norm` and `logits`, and `layer_residual` at layers
  0, 3, and 63. No release or public API changes.

## Implementation decisions

Add a CUDA-specific exact-filter validator and an `execute_token_traced` wrapper
under `QW38_DIAGNOSTIC_TRACE` in `cuda/full_scheduler.h`. The only admitted
filters are `(0, layer_residual)`, `(3, layer_residual)`,
`(63, layer_residual)`, `(global, final_norm)`, and `(global, logits)`, where
`global` is `internal::kTraceAllLayers`. Reject wildcards, mismatched global or
layer scopes, every other registered scalar tap, and a null sink before any GPU
work.

Refactor `cuda/full_scheduler.cu` so the ordinary `execute_token` continues to
call one internal implementation with no trace parameters. In a separately
compiled diagnostic CUDA object, `execute_token_traced` calls that same
implementation with the validated filter and sink, forces
`PointwisePath::kUnfused`, and rejects graphs. At the requested boundary only,
copy the complete device tensor into the existing host candidate-logit buffer,
then call `internal::emit_trace_tensor` with the scalar-pinned name, layer, rank,
shape, and count. Emit exactly once per successful traced token. Propagate copy
or sink failures before attention/GDN candidate state publication and before
the frontier increment. Ordinary execution must retain its current behavior and
outputs.

Replace the scheduler's unguarded four-row `trace_taps_`/`copy_trace_taps`
regression mechanism with the diagnostic sink path. Compile
`cuda/full_scheduler.cu` twice: the existing normal CUDA object for products and
ordinary tests, and a dedicated `QW38_DIAGNOSTIC_TRACE` object only for the full
scheduler trace diagnostic. This makes the trace entry point and stable tap
literals absent from the normal CUDA scheduler object and avoids any production
allocation or per-token trace copy.

Update `cuda/full_scheduler_test.cu` to capture the five filters using the
backend-neutral sink from fresh zero-state sessions for token 42, while one
scalar wildcard run captures the corresponding reference tensors. The native
diagnostic prints, for every tap, count, maximum absolute/relative error, RMS,
cosine, non-finite count, first index exceeding the immutable absolute gate, and
the logit greedy indices. It also proves invalid CUDA filters fail before work,
a deliberate matching-sink failure leaves frontier zero, every successful run
emits exactly one typed view, and scalar/CUDA shapes and values are compared in
full. Python applies the existing `llama_vs_quartz` admissions for the exact five
keys and requires greedy equality; it does not copy thresholds into C++.

Add `pins/cuda_trace_contract.json` to freeze the five-filter subset, scalar
contract/tolerance references, diagnostic build isolation rule, token/position,
and source identities. Add `fixtures/cuda_trace.json` with the measured per-tap
metrics, pass flags, greedy result, failure-path result, device identity, and
explicit proof limits. Refresh `pins/cuda_scheduler_contract.json` source hashes
only because the scheduler/test sources change; do not alter its established
numeric admission.

Document the boundary in a new beginner chapter and connect it from both
indexes and provenance. The implementation and documentation stages may update
`implementation_ledger.md` only for the TRC-004 start/history/evidence/final
status required by the workflow; they must not add or couple another task.
