# OPT-048 — Accelerate full Q6_K vocabulary projection

Status: pending. Dependencies: OPT-044, OPT-046. Primary target: D2048.
Read [the shared protocol](PERFORMANCE-RECOVERY-2026-09-10.md).

## Change

Add a Q6_K integer-dot sibling to OPT-046 in `cuda/quant_mmv.cu` (or its focused
optimized translation unit), keeping the strict packed FP32 implementation.
Reference pinned llama `vecdotq.cuh::vec_dot_q6_K_q8_1` and `mmvq.cu`.
Use the already admitted activation stage; each 256-value weight block has
210 bytes, a half scale, signed subscales and 6-bit values with offset -32.
Implement the format from independent decode fixtures; packed signedness and
the 16-value subscale boundary are correctness-critical. Do not assume every
210-byte block is aligned for a 16-byte load. Use legal unaligned word loads
or a compact lossless repack only if its complete cost/memory is justified.

Start with cooperative 4-warps-per-row DP4A and compare 1/2/4/8 on the exact
248320×5120 output matrix. Include stage, final norm and full FP32 output in
complete timing; include D2H in the whole-engine oracle. Run the small Q6_K
probes too. Keep all vocabulary entries: no top-k-only logits, sampled
vocabulary, approximate argmax or changed public logits behavior.

The historical 1.70 ms category is a bounded secondary win; this task must not
be represented as a route to the entire 24.6 ms decode recovery.
