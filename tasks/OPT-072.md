# OPT-072 — Reevaluate every correctness-based optimization rejection

Status: pending. Dependencies: OPT-059, OPT-069. Coupled IDs: none.
Priority: P0. Target: recover faster implementations excluded by unsuitable
tests while preserving actual correctness. No production pin change here.
Read [the post-069 protocol](PERFORMANCE-RECOVERY-POST-069.md).

## Implementation

1. Inventory OPT-001 through OPT-069 dossiers, raw reports and candidate
   variants inside kept tasks. Include numeric rejection, missing admission,
   exact scalar association, invalid prompt/scorer, missing authority, stale
   object/selector, and genuine layout/nonfinite/state failures. Record original
   test/reference, metric, envelope, source/candidate, latest equivalent path,
   current disposition and concrete next owner. Include OPT-018 historical
   association work, OPT-042/046 Q4, OPT-062/063 admission, and skipped half-scale
   staging. Do not assume that every historical variant needs reinstatement.
2. Classify each entry: already superseded by an admitted equivalent;
   wrong-reference or unsupported numerical rule; incomplete evidence; real
   correctness bug; performance-only rejection; or mixed causes. Confirm the
   actual failure, not just the task's overall done/rejected label. OPT-064/066
   evidence repair belongs to OPT-070; OPT-068's numerical checks passed and
   its measured performance loss is not rescued by tolerance changes.
3. For each remaining correctness-based candidate, reevaluate its smallest
   original failing input against strict output, independently decoded FP64
   original input, FP64 exact staged input, and pinned GPU authority if covered.
   Use current typed staging and source; no historical 30-sample oracle for
   error reproduction. Mark missing production references as unadmitted and
   route Q4 through OPT-074/075. Do not present a partial audit as completed
   reevaluation: every entry needs reproduced evidence, a proven superseding
   equivalence, or a specific unresolved dependency and follow-up.
4. Explicitly compare the original rule with OPT-059's frozen reference-derived
   v2 rule. No candidate-fitted epsilon, no copying synthetic M17/K256 errors
   to real production K. Report whether relaxation changes eligibility and
   which faster implementation it would admit; keep performance unmeasured
   unless valid current complete-cost evidence exists.
5. Audit Q4 Q8_1 consumers as a behavior defect separately from policy. Test
   sums +/-2047, +/-2049, +/-4064; distinguish half(sum(q)), half(sum(x)), and
   exact int32 sums of quantized bytes. A sum(x) producer must not feed a
   sum(q) consumer. Permit a focused typed consumer repair only if necessary
   for the diagnostic; preserve current production Q8/Q6 staging semantics.
6. For an independent legacy numerical candidate not covered by OPT-075–079,
   enumerate its case and one control/candidate screen in this task's contract
   before executing it. Use current full-family replay, at most one candidate
   per phase. Qualifying results are screened-in follow-ups, not automatic
   production keeps. Performance-only losers get a reviewed no-repeat reason.

## Bounded tests and commands

Create `pins/opt072_rejection_review_contract.json` and a machine-readable
review register; reference historical files without modifying them. Host tests
check coverage/disposition and that nonfinite/layout errors cannot be admitted
by numerical headroom. Native reuse: `build/qw38-cuda-opt059-numerics-test` and
existing focused candidate targets, listed exactly per review case.

One `--phase case-ID` is at most two implementations, two relevant shapes,
16 sampled rows x 4 vectors per shape, one execution for correctness; optional
screen is 1+3 whole-family rounds. Dry-run must expand a finite case-ID list
with actual loop counts. The register audit itself has no GPU work.

```sh
uv run pytest -q tests/test_opt072_rejection_review.py
uv run python tools/run_optimization_task.py --task OPT-072 --mode feedback --phase inventory
uv run python tools/run_optimization_task.py --task OPT-072 --mode feedback --phase q4-original-failure
uv run python tools/run_optimization_task.py --task OPT-072 --mode acceptance --phase review
```

Acceptance is review completeness, not a speed claim. Report each old rejection
as still valid, evidence-invalid, numerically eligible, already superseded or
blocked with an owner. Stop GPU work immediately on a real correctness defect;
keep its failing reproducer and route a repair. An actionable entry with no
reproducer/reference/owner prevents a complete verdict. Quality risk is limited
to proposed admission; hard semantic errors are never relaxed.
