# OPT-131 — Fuse one measured residual decode launch chain

Status: pending. Dependencies: OPT-128, OPT-130. Coupled IDs: none.
Priority: P1.

## Outcome

Address a remaining short-kernel dependency chain only if true activity traces
show material request cost after graph/host and attention work. Read OPT-125.
Freeze a parent containing admitted dependencies; no assumed additive gains.

## Implementation

1. Profile the retained parent and identify one adjacent producer/consumer
   chain in `cuda/scheduler_primitives.cu`, `cuda/gdn_step.cu` or
   `cuda/full_scheduler.cu`. Rank avoided launches and intermediate traffic
   on the critical path. Reuse OPT-119's existing norm→Q8 fusion; do not
   recreate it. OPT-109's isolated GDN win and enclosing loss are required
   prior evidence if a GDN chain is chosen.
2. Freeze at most two implementations of that single chain. Preserve
   intermediate rounding and operation order needed by the quality contract;
   explicitly test any fused rounding difference. No weight/KV/state precision
   change, recurrence rewrite, new general fusion framework or full-layer
   persistent kernel.
3. Prove buffer ownership, aliasing and candidate/committed state separation.
   Respect graph dynamic inputs and cancellation boundaries; do not fuse
   across a required cancellation or commit boundary.
4. Screen component, enclosing branch and complete requests. Measure register
   pressure/occupancy where available; saved launches may be offset by slower
   kernels. If graphs already removed the causal gap or the quantified bound
   is negligible, complete with no-material-opportunity and no production edit.

## Acceptance

Apply OPT-125's quality/state/memory/request gates; add focused equivalence
checks for the changed chain and unchanged fallback. Deliver
`evidence/optimization/opt131-decode-chain/REPORT.md` with causal upper
bound, candidate data and retained decision. A kernel-only speedup is not
a keep.
