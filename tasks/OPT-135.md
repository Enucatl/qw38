# OPT-135 — Separate target improvement from guard non-regression

Status: pending. Dependencies: OPT-134. Coupled IDs: none.
Priority: P0. Plan impact: none; prospective internal admission only.

## Outcome

Implement a versioned keep policy in which a context-specific candidate must
improve its declared targets while preserving declared guards. Neutrality on a
guard is acceptable when uncertainty is narrow enough to establish
non-regression. This is not automatic readmission of OPT-130 and does not
change OPT-016, OPT-056, CMP-003 or `plan.md` release requirements.

Ledger acceptance: A tested prospective policy freezes target/guard roles and
matched metrics, admits proven target gains with non-regressing neutral guards,
rejects guard losses and missing evidence, and leaves historical verdicts and
release gates unchanged.

## Frozen policy

Policy ID: `target_guard_v2`. Require explicit opt-in; unknown IDs fail closed.
New OPT-137 uses it. Completed historical tasks continue using their frozen
policy. Diagnostic OPT-136/138 do not perform keep admission.

1. A candidate contract lists disjoint, nonempty `targets` and `guards`, one
   primary metric per target, the dispatch region and unchanged branches,
   required quality/state gates, and all thresholds. Every required workload
   has exactly one role. Freeze and hash this contract before the first screen
   sample. Acceptance must have the same hash. Reject post-hoc role/threshold
   changes; a new contract needs a new candidate ID and fresh samples.
2. Require matching metric identities on each pair: workload/input trajectory,
   prefix, eval count, capacity, metric boundary, sampling/output policy and
   relevant engine configuration except explicitly frozen candidate differences.
   Candidate binary/selector differences are recorded, not required to equal the
   control. Non-finite or non-positive rates, missing or
   duplicated sample IDs, incomplete pairs and changed identities are errors.
3. Screen: one warmup, three paired component rounds; optional one 32-token
   engine pair. Screen only selects a survivor, never admits a keep. At most
   one candidate advances to acceptance under this task's first consumer.
4. Acceptance: three warmups and ten independent paired AB/BA rounds per
   required workload; alternate order, restore identical initial state outside
   the timed interval. Use pairs, not individual tokens, as independent
   statistical observations. No automatic extra samples until significant.
5. For each workload let `x_i = log(candidate_rate_i / control_rate_i)`.
   Compute `g = exp(mean(x))`, `se = sample_sd(x)/sqrt(10)`,
   `L = exp(mean(x) - 1.8331129326536335*se)` and
   `U = exp(mean(x) + 1.8331129326536335*se)`. These are one-sided 95% bounds
   for ten pairs/9 degrees of freedom; do not label [L,U] a two-sided 95% CI.
   For zero variance use L=U=g. Reject any other acceptance sample count for
   this version. Keep the statistical implementation small; no new dependency
   is needed for the fixed critical value.
6. Every target must satisfy `L > 1.0`. Every throughput guard must satisfy
   `L >= 0.98`; never require its CI to exclude 1. An interval [0.99,1.01]
   passes the guard; [0.97,1.03] does not establish non-regression. For every
   decode workload, per-run p95 ITL candidate/control point ratio must be
   <=1.05 in each paired round; report the complete ratios, not a pooled-token
   percentile. Zero/missing p95 on decode is invalid.
7. For decode targets use `decode_only` as primary and `complete_request` as
   an additional guard with the same 0.98 lower-bound floor. Measure prefill
   separately. For a prefill target use `prefill` as primary. Unchanged decode
   regions guard both decode-only and complete-request rates. An arbitrary
   prefill denominator must not erase a real decode gain or hide a request
   regression. Shared report labels retain actual eval and emitted counts.
8. Report `material_2pct = (g >= 1.02)` separately for each target; it is not
   a hidden keep threshold. An improvement smaller than 2% can pass with
   adequate evidence. No aggregate geometric mean can hide a failed required
   target, guard, quality or state gate. All targets must win, so this version
   does not select the best of several target results after sampling.
9. Verdicts: `keep` only when all required evidence is present and passes;
   `reject` for measured quality/state failure or a target with U<=1 or a
   throughput guard with U<0.98 or a p95 violation; `inconclusive` for valid
   intervals that establish neither acceptance nor those measured failures;
   `incomplete` for absent/invalid required evidence. Never promote an
   inconclusive/incomplete result. Retain all reasons when several gates fail;
   precedence is incomplete, reject, inconclusive, keep.
10. Output candidate rate/delta and shipping impact separately. A policy-only
    task has no shipping throughput change. A replay under changed roles is
    labeled counterfactual and cannot alter historical admission.

## Implementation and acceptance

Expose a pure `evaluate(contract, records)` function and CLI:

```sh
uv run python tools/performance_keep_policy.py --contract pins/performance_keep_policy_v2.json --self-check fixtures/opt135_target_guard_policy.json
```

The policy file contains the fixed rules; self-check fixtures contain candidate
contracts and raw paired records with independently calculated expected
decisions. OPT-137 imports the same evaluator; do not copy its formulas into
the runner. The CLI exits nonzero on a mismatched expected decision, reports
each case and writes no historical fixture.

Required tests:

- Target 1.02 and guard 1.00 with narrow CIs -> keep, even though guard L<=1.
- Guard CI crossing 1 but wholly above 0.98 -> pass that guard.
- Target win with definite guard loss below 0.98 -> reject.
- Target CI straddles 1 -> inconclusive, not measured loss or keep.
- Guard CI straddles 0.98 -> inconclusive; equality at 0.98 passes.
- Target L exactly 1 -> not keep; target all ratios 1 -> reject/no gain.
- Target g=1.019 with L>1 -> keep, material_2pct=false.
- Decode target wins but complete-request guard fails -> not keep.
- Aggregate positive with an individual required failure -> not keep.
- p95 >1.05 in any pair -> reject; boundary 1.05 passes.
- Missing quality/state, NaN, zero rate, duplicate/unpaired samples, mixed
  metrics/capacity or count other than ten -> incomplete/nonzero validation.
- Frozen-role hash mismatch and unknown policy ID -> fail closed.
- Historical OPT-130 raw ratios with D2048 target and D128/P4096 guards:
  report the counterfactual per-metric decisions that available raw records
  support. Missing required records remain missing; do not manufacture a
  complete keep from summary means. Preserve old verdict `reject` exactly.
- Existing legacy contract loading and release thresholds stay unchanged.
