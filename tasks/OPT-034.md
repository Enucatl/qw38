### Kernel behavior (frozen)

Retain:

- One warp owns one output row; `blockDim = Warps * 32`; `grid.x = ceil(rows / Warps)`
- `quantize_bf16_q8` (warp max-abs / 127, `roundf`, exact host match)
- Per-lane serial FP32 products with `__fmul_rn` then `__fadd_rn` into `sum`
- Five-step `__shfl_down_sync` tree (`offset = 16,8,4,2,1`); lane 0 stores `output[row]`
- Existing Q4_K / Q6_K decode **equations** (`d * float(scale * quant) - dmin * float(minimum)` for Q4_K; `d * float(scale * quant)` with signed 6-bit `quant-32` for Q6_K). Do not rewrite as `d * scale * quant` in three floats. Do not use DP4A.
- Column visit order per lane: `lane, lane+32, ..., columns-32+lane` which for a 256-value block is indices `lane + i*32` for `i = 0..7`, then the next block. Packed path must consume that same order.
- `selected_mmv_warps` buckets unchanged

Elementwise path (`PackedLoads=false`, production until A/B): today's per-column `decode_weight`. Must remain byte-identical to current `main` when the pin is `elementwise`.

Packed path (`PackedLoads=true`, Q4_K/Q6_K only):

- Outer loop walks `block_index = 0 .. columns/256 - 1`.
- For each 256-value block, **load packed fields and scales once**:
  - Q4_K: `d` and `dmin` (FP16 at bytes 0 and 2), eight 6-bit scale/min pairs from the 12-byte scale field (existing `q4_scale_min` over indices 0..7 once), and the four `qs` bytes this lane needs (`block[16 + group*32 + lane]` for `group = 0..3`).
  - Q6_K: `d` (FP16 at byte 208), the 16 signed scale bytes at offset 192, and this lane's `ql`/`qh` bytes for both 128-value halves.
- Inner loop `i = 0 .. 7` consumes `within = lane + i*32` using already-loaded fields, then the matching Q8 activation `activation[(block_index*256 + within) / 32]`.
- Pad/OOB: production columns are multiples of 256 (existing `launch_quant_mmv` check). No extra `__syncthreads__`. No shared-memory weight tile. No extra global scratch.

Do not change `quant_mmq` (row-wise or MMA). Do not change Q8_0 `quant_mmv`.
