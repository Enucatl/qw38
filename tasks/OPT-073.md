# OPT-073 — Separate engine quality from the authority's arithmetic miss

Status: pending. Dependencies: OPT-058, OPT-069, OPT-072. Coupled IDs: none.
Priority: P0. Target: valid production-quality decisions and cheap release stop.
Read [the post-069 protocol](PERFORMANCE-RECOVERY-POST-069.md).
Quality risk: policy/scoring; no arithmetic kernel changes or speedup claim.

## Implementation

1. Authenticate rendered text, tokenizer IDs, no-thinking assistant boundary,
   output termination and parser for all eight v2 cases. Reproduce 17+25 on
   both engines; B=42 remains the correct answer, A=41 remains wrong. Both
   engines failing does not by itself prove a kernel or scorer bug.
2. Freeze at most four arithmetic diagnostics before measuring a candidate:
   original v2, the same options in one fixed permutation, direct numeric
   completion under the supported template, and one independent paraphrase.
   Human-verifiable answers and parsers are written first. Run both controls,
   at most 16 generated tokens/case. No token mask, no teacher-forced answer,
   no selecting only paraphrases that happen to pass. Retain every result.
3. If rendering/parsing is objectively wrong, fix it in a versioned successor
   with text/ID evidence. If the pinned authority genuinely misses, maintain
   separate verdicts for absolute task accuracy and engine non-regression.
   Proposed internal quality-v3: all reference-correct functional items must
   remain correct; on the known missed item, candidate must either give the
   independently correct answer or preserve the authority behavior within
   frozen logit-error/margin bounds. Other wrong choices are not waived.
   Absolute arithmetic accuracy stays failed when it is failed.
4. Document the versioned rationale and full v2/v3 verdicts side by side before
   using the successor for internal candidate admission. The user authorized
   evaluating documented comparable-accuracy policies, not relabeling OPT-056
   or OPT-016. Do not replace their quality condition or mark them passed;
   any proposed historical gate successor is a separate explicit decision.
5. Keep both 1024-target NLL spans, PPL <=1.01, recurrence drift <=0.02,
   finite full vocabulary and structural state invariants. Freeze reference
   logits/margins on the actual contexts before candidate selection. Missing
   evidence yields incomplete, not pass. Same-input near-tie allowances cannot
   waive a known wrong semantic answer.
6. Fix release preflight: OPT-069 currently checks only the functional token
   count, and proceeds from failed quality into timed oracles. Validate parsed
   answers and each required selected quality verdict. A release attempting
   OPT-056 must stop while its actual quality requirement fails. If diagnostic
   performance under a known baseline failure is useful, make that an explicit
   non-release mode, retain failure, and prohibit release/keep claims.

## Tests and commands

Host tests use original A/B arithmetic answers, whitespace, extra text, missing
authority, wrong tokenizer/template, near-ties, and skipped quality phases.
Reuse `build/qw38-cuda-opt058-quality-baseline-test` and the existing pinned
llama quality oracle. One feedback phase: two engines x four fixed arithmetic
diagnostics x at most 16 generated tokens; another verifies 32 held-out targets
plus all eight functional controls. Model/reference setup is cached. Full NLL
acceptance is separate once, not an implementation-loop multiplier.

```sh
uv run pytest -q tests/test_opt073_quality_policy.py tests/test_opt069_batch_gate.py
uv run python tools/run_optimization_task.py --task OPT-073 --mode feedback --phase arithmetic
uv run python tools/run_optimization_task.py --task OPT-073 --mode feedback --phase preflight
uv run python tools/run_optimization_task.py --task OPT-073 --mode acceptance --phase quality
```

Accept a verified scorer repair or an explicit versioned dual-verdict policy,
complete authority coverage, and a fail-closed release path. Stop kernel blame
without a Quartz/authority discrepancy; stop prompt rewriting if no objective
defect exists. Do not manufacture a universally passing absolute baseline.
