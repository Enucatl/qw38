### Shared-inverse kernels (frozen math)

Add a prompt-only shared-inverse path used when all of these hold:

- `GdnScanPath::kFusedTokenLoop` and fuse path `off`
- production shape `key_heads == 16`, `value_heads == 48`, `key_width == 128`, `value_width == 128`, `convolution_width == 4`
- `token_count >= 2`
- inverse scratch non-null and `scratch_floats >= 2 * token_count * key_heads`
- compile-time inverse pin is `shared`

All other launches, including decode sequential, `token_count == 1`, missing/short scratch, non-production shapes, fuse_conv/fuse_gate/fuse_both, sequential windows, and parallel-associative overlay, keep the current in-loop inverse (`repeated`).

Extract the existing quality inverse math into one `__device__` helper used by both the shared kernel and the repeated warp-column loop so association cannot drift:

```text
query_squares/key_squares: 4-row unroll, q_reg[row]=query[row*32+lane],
  __fadd_rn(__fmul_rn(q,q)), then gdn_warp_sum
query_inverse = 1.0F / sqrtf(query_squares + kGdnQualityL2Epsilon)
                / sqrtf(static_cast<float>(config.key_width))
key_inverse   = 1.0F / sqrtf(key_squares + kGdnQualityL2Epsilon)
```

Do **not** use `rsqrtf`. Do **not** change `+` / `*` association. Do **not** L2-normalize Q/K in place (recurrence continues to scale `q_reg`/`k_reg` by the loaded inverses). Do **not** alter decay, beta, `s_shard`, delta, or attn accumulation.

`prepare_gdn_shared_inverses`:

- Grid `(key_heads, token_count)` = `(16, token_count)`; block `(32)`. One warp owns one `(token, key_head)`.
- Read convolved Q/K from `convolution_output` at the same token-major offsets the warp-column kernel uses.
- Store two FP32 values at `inverses[token * key_heads * 2 + key_head * 2 + {0: query, 1: key}]`.
- Occupancy via `cudaOccupancyMaxActiveBlocksPerMultiprocessor` ≥ 1.

`prepare_recurrence_fused_warp_column_shared`: same grid `(48, 1, 32)` / block `(32, 4)` / `__launch_bounds__(128, 2)` / token loop / S update as the current kernel, except it **loads** `query_inverse`/`key_inverse` from that scratch instead of recomputing squares. Keep the original `prepare_recurrence_fused_warp_column` as the A/B baseline and as production until a keep.
