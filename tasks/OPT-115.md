# OPT-115 — Audit complete-request memory traffic and performance bounds

Status: pending. Dependencies: OPT-113, OPT-114. Coupled IDs: none.
Priority: P0. Diagnostic foundation and shared protocol for OPT-115–124.

## Outcome

Explain the remaining time and bytes in the actual production pipeline and
rank experiments by removable request latency. Separate device GDDR traffic,
L2 reuse, host/device transfers, allocation capacity and one-time loading.
Deliver conditional bounds for this workload, not a proof that llama.cpp is
optimal. This task changes diagnostics only; candidate implementation belongs
to OPT-117–122.

  [contract](../pins/opt113_coupled_stack_gate_contract.json): production
  `post113_selected` is Q4 `llama_q4k_mmvq`, prompt attention `opt111_base`,
  decode attention `hybrid_crossover@1024`, GDN `sequential`, MMQ `fma_async`,
  graphs `ffn_only`. P4096/D128/D2048 are 3064.77/57.297/55.647 tok/s versus
  pinned llama 3227.71/68.614/67.272. These are historical observations, not
  reusable paired controls. Use the complete selector record, not this summary.
- The reconciled [128K ledger](../fixtures/cuda_memory_fit_post_graph.json)
  passes: resident model 18,973,870,432 B, KV 8,589,934,592 B, GDN state/rings
  158,859,264 B, workspace 1,831,836,288 B, reserve 1,610,612,736 B.
  OPT-113's earlier accounting failure was repaired; do not reopen it as OOM.
- [Tensor inventory](../pins/tensor_inventory.json) totals Q4_K 10,341,089,280 B,
  Q8_0 7,155,384,320 B and Q6_K 1,455,820,800 B. These are stored bytes;
  embedding lookup does not read the entire embedding tensor per token.
- [OPT-114](OPT-114.md) reported about 11 ms/token removable launch overhead
  on its older control and failed segment capture. Revalidate both the
  attribution and applicability to post113; wall minus leaf-event sums alone
  cannot identify causal removable overhead.
- [OPT-109](OPT-109.md) won recurrence-only but lost complete GDN. Decode
  [scheduler](../cuda/full_scheduler.cu) already swaps GDN candidate/committed

  the full 8 GiB cache on every token.

## Investigation

1. Authenticate one fresh post113 control and pinned llama
   `cc83d7b4824f73cfdda4dfbb47ee39804f71b328`: binary, source/dirty state,
   GGUF hash, complete selectors, actual launched kernels, capacities, compiler
   flags, graphs, GPU clocks/power and timing boundaries. Reproduce A/A before
   interpreting A/B. Use an exclusive, serialized GPU sitting under the
   existing operational procedure; this dossier does not authorize stopping
   unrelated services. If exclusivity cannot be obtained, report the blocker.
2. Trace P4096, D128 and D2048 plus an ordinary `Session::sync` → sample → eval
   → output loop. Compare benchmark and CLI/server cancellation-poll behavior.
   Include prefill-to-first-token latency, 256 emitted decode tokens, p50/p95
   inter-token latency and total request wall time. Add separately labeled
   D8192/D32768 and bounded D131040+32 probes in a 131072-capacity session.
   Capacity alone is not evidence of reading a populated long cache.
3. Map weight reads, activation/quantization buffers, KV append/read,
   recurrent old/new state, carry/checkpoint copies, output-head/logits,
   token transfers, host sampling, allocations, barriers and graph updates to
   their producers/consumers and lifetimes. Record bytes/request, bytes/token,
   call counts and scope. Identify repeated quantize/dequantize/layout passes,
   FP32/BF16 intermediates and any materialized attention scores.
4. Use available timeline and targeted memory counters on complete execution.
   Distinguish GPU busy time, GPU idle, CPU work overlapped with GPU work,
   dependency waits, synchronization and launch submission. Report event
   unions and unclassified time; avoid adding overlapping intervals. Validate
   counter coverage and profiler perturbation against uninstrumented wall
   timing. If counters are unavailable, label byte estimates and bound their
   uncertainty; do not fabricate hardware measurements.
5. Reconcile tensor-derived compulsory reads with measured DRAM/L2 traffic.
   Compute time bounds using both hardware peak and measured sustainable
   bandwidth for relevant access patterns, with explicit cache assumptions.
   NVIDIA lists 1792 GB/s peak for the RTX 5090 in its
   [Blackwell architecture paper](https://images.nvidia.com/aem-dam/Solutions/geforce/blackwell/nvidia-rtx-blackwell-gpu-architecture.pdf).
   Peak is an optimistic bound, not observed application bandwidth. Separate
   fixed-format and quality-gated lower-bit byte models. Include unpack,
   reductions, compute and serial dependency constraints; use max/critical-path
   reasoning when costs overlap, not a sum of independent peak bounds.
6. Inspect pinned llama and local sibling sources for each ranked mechanism.
   Planning inspected llama HEAD `1945e092030f8668ff93382799502d01490e564d`
   and ds4 HEAD `c238077a87186381bf626cc531bccffe1fef79e7`; neither is silently
   the pinned benchmark authority. Use `../llama.cpp/src/models/qwen35.cpp`,
   its CUDA graph/attention/MMQ code, `../ds4/ds4_cuda.cu` and
   `../ds4/cuda/mmq/`. Record source revision, function, physical dtype,
   actual consumers and transferability. DeepSeek compression/indexer/MoE
   structure is not Qwen's 48-GDN/16-attention architecture.
7. Publish per-task removable-byte/time bounds and uncertainties for OPT-117–122.
   Investigate important unclassified spans before declaring no opportunity.
   Below-resolution opportunities may be deferred with evidence; a missing
   metric or broad family residual is not a measured zero. No kernel retuning
   or new optimization in this task.

## Shared execution and keep protocol for OPT-117–123

- Read this dossier and OPT-116. Reuse existing optimization/quality harnesses;
  create only task-specific instrumentation, contracts and checks needed for
  trustworthy evidence. Freeze candidate list, primary workload, timing
  boundary, quality contract, sample count and stop rules before results.
- OPT-117–119 cover scheduler/intermediate traffic; OPT-120 owns KV encoding,
  OPT-121 weights, OPT-122 recurrent-state encoding. Preserve exact token IDs,
  template, model identity, full causal context and public session semantics.
  No layer/token dropping, speculative decoding, batching, new model or
  generic framework. Precision experiments are authorized by the 2026-09-13
  request; document any admitted architecture-policy exception with a dated
  note during implementation, preserving the original plan and gate records.
- Compare each mechanism against fresh post113 and its actual parent stack.
  Declare the parent explicitly. Graph/ownership work can be a parent for later
  slices only if kept; a rejected prerequisite means use its retained control.
  Freeze combined quality against post113, never a ratcheting sequence of
  already-degraded candidates.
- Use microbenchmarks to debug correctness or explain results. A correct
  plausible pipeline candidate must get a bounded full-engine screen; a leaf
  kernel loss alone cannot veto a hypothesized enclosing win. Equally, no
  isolated/component win admits a keep. Rooted infeasibility, failed quality,
  or a quantified negligible upper bound can stop a candidate before timing.
- Default screening: 3 warmups and 5 paired AB/BA complete-workload runs.
  Final candidate acceptance: 3 warmups and 10 paired AB/BA runs for each
  declared target and P4096/D128/D2048, 256 decode outputs for D128/D2048.
  Freeze any resource-driven long-context count reduction before candidates.
  Report raw wall samples, geometric throughput ratios, paired log-ratio
  one-sided 95% Student-t bounds, p50/p95 and all failures. No extra sampling
  to turn an inconclusive result into a pass. OPT-123 also retains the original
  benchmark protocols for historical outcome fields.
- For a new keep require target throughput ratio lower bound >1.00 versus
  its parent, an improvement larger than measured A/A noise, and point ratios
  >=0.98 on every non-target P/D workload with decode p95 <=1.05 times parent.
  Predeclare whether the target is decode, prefill or long-context requests;
  long-context gains must not be presented as D128/D2048 wins. A memory-only
  improvement is a separately labeled result, not a throughput keep.
- Full OPT-116 candidate quality precedes long acceptance timing. Required
  state tests cover graph/eager same-path results, prompt-to-decode handoff,
  chunk boundaries, cancellation before commit, failure/frontier isolation,
  divergent-prefix replay, repeated save/restore and sampler continuity.
  Packed formats require explicit versioned compatibility and exact same-format
  round trips. Never expand and requantize on restore if it changes the saved
  state. Test retained paths as well as new ones.
- Reconcile persistent and transient peak bytes, repacks, graphs and 128K fit
  with the existing 1.5 GiB reserve. Preserve the source GGUF; replacement
  device encodings must account for preparation peak and duplicate lifetimes.
  Reject candidates that need an unreported dense shadow or raise the cap.
- Deliver separate `kernel_correctness`, `model_quality`, `state_memory`,
  `performance`, `production_kept` and historical release verdicts. A completed
  rejection or evidence-backed no-opportunity disposition satisfies a research
  task. Missing required evidence is inconclusive/blocked, never a pass.
  Retain reproducible negative results and remove rejected production dispatch.
