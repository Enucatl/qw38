### Q8_0 MMA kernel

Extend `cuda/quant_mmq_mma.cuh` (included from `cuda/quant_mmv.cu`; **do not add a Makefile object** and **do not edit `NVCCFLAGS`**) with a `QuantKind::kQ8_0` specialization that reuses the existing 256-thread / 128-output-row / J-in-`{32,64,128}` geometry and the existing BF16→Q8_1 shared-memory staging. Do not create a third MMA translation unit. Do not vendor llama.cpp `mmq.cuh`.

Q8_0 decode (GGUF 34-byte / 32-value blocks, FP16 scale, signed int8 values):

- `columns % 32 == 0` is required; reject otherwise (`cudaErrorInvalidValue`). Production mixer columns are 5120 and 6144.
- Row stride is `(columns / 32) * 34`.
- Each K-step of 32 columns is one Q8_0 block. Pack 32 int8 values into `x_qs` the same way Q4_K packs decoded groups. Store the block scale in `x_dm.x`; `x_dm.y` is unused (no dmin).
- Activation staging stays the existing warp-max / 127 Q8_1 SRAM path. That layout is **not** Quartz `Q8Block` and uses no extra `cudaMalloc`.
- Dot: `mma.sync.aligned.m16n8k32.row.col.s32.s8.s8.s32` then `acc += dA * dB * float(C)` (llama.cpp Q8_0×Q8_1 D4 layout). Output remains token-major FP32 `[prompt_rows, output_rows]`.
- Partial prompt and output tiles are guarded. No padding value is exposed as a result.
- Shared-memory byte formula stays `mma_mmq_shared_bytes(J)`. Occupancy must be ≥ 1 on the winning J.

Provenance in the `quant_mmq_mma.cuh` file header (and `docs/sources.md`): llama.cpp `mmq.cuh` / `mma.cuh` / `mmq-config-ampere.cuh` / `mmq-load-tiles.cuh` / `mmq-vec-dot.cuh` at `cc83d7b4824f73cfdda4dfbb47ee39804f71b328` (MIT, The ggml authors). Mention ds4 `cuda/mmq` only as the ggml-free launcher pattern. Do not copy `../ds4/cuda/mmq/` and do not include ggml headers.

Declare in `cuda/quant_mmv.h`:

- `unsigned int selected_q8_mma_mmq_prompt_tile() noexcept;`
- `cudaError_t launch_q8_mmq_mma(...)`
- `cudaError_t launch_q8_mmq_mma_tile(..., unsigned int prompt_tile, ...)`

`launch_quant_mmq_mma` continues to reject `kQ8_0`. `selected_mma_mmq_prompt_tile()` stays the Q4_K/Q6_K pin (currently 128) and is not reused as the Q8_0 pin.
