   capture actual preprojection activations for layers 0, 3, 31, 32, 62, 63,

   representative real-text inputs from `pins/quality_contract.json`.
   Record position and stage. Do not substitute final hidden for mid-layer
   activations. Save tensor shape/dtype/hash and bounded reusable buffers.
3. Add a diagnostic target to `tools/llama_authority/CMakeLists.txt`, linked
   only against the pinned authority tree. Through ggml CUDA backend operations
   run the same Q4_K gate/up/down, Q8_0 mixer, Q6_K output, norm, GDN, and
   attention shapes. Include input conversion/quantization and fixups; provide
   both identical-input kernels and native-engine component measurements.
   Label Quartz BF16 vs llama F32/Q8_1 and BF16 vs F16 KV differences explicitly.
   Do not pass Quartz Q8Block bytes as llama block_q8_1.
4. Use a separate Nsight Systems capture of both engines to confirm actual
   kernel names, GLU fusion, graph launches, offload, and CPU/GPU waits. Target
   only the largest remaining kernels with Nsight Compute. Record DRAM bytes,
   L2 hit rate, achieved bandwidth, instructions, tensor activity, register
   count/spills, barrier/dependency stalls, and occupancy where available.
   If tools/counters fail, retain the error, obtain CUDA-event component times
   and compiler reports, and explicitly mark missing counters. Do not claim
   bandwidth-bound or compute-bound solely from low occupancy.
5. Generate an executed tensor-role inventory from `pins/tensor_inventory.json`
   and actual dispatch. Sum unique weight bytes per token, count staging/kernel
   launches, and compare byte/time bandwidth estimates to measured traffic.
   Separate vocabulary output from embedding lookup. Report at least one
   paired complete component for every major family; source names alone are
   not completion. If a native fused component cannot be isolated, capture its
   enclosing interval and explain the limit.
