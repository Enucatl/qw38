## Outcome

Measure the pinned llama Q4_K decode implementation itself behind a narrow
Quartz buffer adapter. This distinguishes a failed technique port from a
scheduler/layout limitation and avoids another bespoke unpack/reduction tweak.

## Evidence and rationale

OPT-099 still measures Quartz excess in both FFN legs: 12.11 ms for `ffn_down`
and 11.09 ms for `ffn_gate_up_glu` across the D2048 diagnostic window.
OPT-076, OPT-089, OPT-093, and OPT-102 changed selected parts of Quartz's
integer path, but none compiled and called the pinned `mmvq`/`vecdotq` path
source-faithfully on Quartz-owned buffers. The authority is MIT licensed and
already pinned at `cc83d7b4824f73cfdda4dfbb47ee39804f71b328`.

## Implementation

1. Before integrating with the Quartz scheduler, run the pinned kernel behind
   a narrow matched-input harness. Start both paths from identical BF16
   activations and identical raw GGUF Q4_K weights at the production M/N/K
   shapes. The production control must perform its selected FP32-scale
   `Q8Block` staging and `integer_q8_late` dot path; the pinned candidate must
   perform its native `block_q8_1` staging and MMVQ path. Report staging and dot
   time separately, but use their sum for the primitive go/no-go. The two
   encodings are not interchangeable, and `integer_q8_late` must not be called
   with Q8_1 data. If the source-faithful complete primitive does not win, stop
   with a measured adapter rejection; do not spend a full engine integration
   pass on it.
2. Adapt only the pinned Q4_K × Q8_1 one-vector path and its gate/up fused-GLU
   form. Vendor the minimum required MIT source into a clearly namespaced
   adapter; do not import ggml graph, allocator, tensor, CLI, or model code.
3. Feed raw GGUF `block_q4_K` weights without a replacement device copy. Use
   pinned `block_q8_1` activation semantics, lane mapping, scale/min unpack,
   reduction, launch geometry, and fused-GLU behavior exactly. Provide explicit
   compile-time shape adapters for 5120×17408 and 17408×5120 only.
4. Keep `integer_q8_late`/`paired_integer` callable as control. Do not combine
   the adapter with OPT-093 factoring, OPT-102 aligned metadata, or a new warp
   sweep.
5. Compile the adapter with the same CUDA flags used by the pinned authority and
   retain a strict control build. Record source commit, copied-file hashes,
   local modifications, license header, SASS, registers, spills, occupancy,
   staging bytes, and actual launch identity.
6. If adapting a dependency would materially change pinned arithmetic, stop and
   report the incompatibility rather than silently reimplementing it.

## Verification and evidence

- Add task/iteration contracts, provenance manifest, fixture, native adapter
  parity test, rotating complete-FFN replay, host validator, runner entry, and
  `evidence/optimization/opt110-llama-q4-adapter/REPORT.md`.
- Validate both typed activation producers independently at boundary and
  production K/M shapes, then validate projection outputs against decoded
  CPU/FP64 samples and pinned-llama GPU exports. Cover same-input gate/up
  fusion, down input, tails, zero, nonfinites, and graph/eager execution. The
  evidence must record `Q8Block` control bytes and `block_q8_1` candidate bytes
  separately and prove that no buffer is interpreted as the other type.
- Run the complete current quality suite with candidate NLL; no quality reuse
  solely from the pinned implementation name.
- Performance acceptance is 3+10 rotating 64-layer complete FFN pairs and five
  uninstrumented D128/D2048 32-token pairs, plus one P4096 and 128K guard.

## Acceptance and stop rule

- Require at least 0.50 ms/token complete-FFN saving with a positive paired 95%
  interval, improved D128 and D2048 point throughput, and all existing quality,
  p95, state, graph, and memory gates.
- A faster isolated MMVQ kernel is insufficient if activation staging, GLU, or
  the complete FFN loses. On failure, retain `integer_q8_late` and preserve the
  adapter only as diagnostic evidence.

## Non-goals

No Q8/Q6 expansion, weight requantization, changed GGUF, generic ggml backend,
tile search, tolerance fitted to the candidate, or replacement of llama.cpp as
the independent release authority.
