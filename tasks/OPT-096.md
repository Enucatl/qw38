# OPT-096 — Conditional eight-layer decode graphs
Status: done. Dependencies: OPT-095. Coupled IDs: none.
Priority: P1. Target: capture decode segments only when removable launch overhead is measured.
Read [the post-088 protocol](PERFORMANCE-RECOVERY-POST-088.md).
Quality risk: stale graph parameters, capture-time state mutation or misplaced cancellation can violate atomic sessions.
Instrumentation: unhidden launch/idle wall, graph parameter/capture cost, graph node identity, token ITL/p95, cancellation and memory reserve.

## Outcome

Conditionally capture eight-layer decode segments, or record no-reopen and
retain FFN-only graphs. OPT-055 measured only 0.08555/0.10514 ms idle at
D128/D2048; OPT-087 correctly left this closed. This is an evidence-triggered
new segment path, not an unconditional rerun of the old graph experiment.

## Implementation

1. Create `pins/opt096_decode_graphs_contract.json`, the iteration contract,
   `tools/opt096_decode_graphs.py`, `tests/test_opt096_decode_graphs.py`,
   `fixtures/opt096_decode_graphs.json` and
   `evidence/optimization/opt096-decode-graphs/REPORT.md`. Add
   `cuda/opt096_decode_graphs_test.cu`, native
   `build/qw38-cuda-opt096-decode-graphs-test` and Makefile
   `cuda-opt096-diagnostics`, reusing OPT-055 state/graph helpers and the engine
   probe. Do not implement segments before eligibility passes.
2. Require OPT-090 `graph_reopen_eligible=true`. Confirm on the current OPT-095
   selection with one warmup +three uninstrumented 32-token windows per
   prefix128/2048, measuring host launch gaps in a separate diagnostic trace.
   If removable unhidden overhead is <0.50 ms/token at either prefix, finish
   `no_reopen_overhead_below_trigger`. Do not count overlapping host launch time
   or kernel arithmetic as removable overhead.
3. Exactly two selectors in `cuda/full_scheduler.h`: existing `ffn_only` and
   new `decode_segments8`. Extend `SchedulerGraphs` in
   `cuda/full_scheduler.cu` to eight executable segments, layers0–7 through
   56–63. Capture the admitted decode kernels, including FFN bodies, in each
   segment with stable model/workspace addresses; do not call an already
   captured FFN executable from inside capture. Embedding, final logits and
   final state publication stay at existing boundaries outside segments.
   Poll cancellation at every eight-layer boundary and before final publication.
4. Parameter policy is fixed: reuse `GraphLaunchParams` token/position/frontier/
   2048-row KV bucket fields. Store graph node handles for kernels with changing
   scalar arguments and use `cudaGraphExecKernelNodeSetParams` before replay;
   count those updates in elapsed token time. No per-token graph recreation.
   Grid dimensions dependent on KV bucket are updated at bucket crossings
   before launch; retain at most eight live segment executables. Invalidate
   all segments on model/workspace/source/selectors/shape changes, and make
   capture execute on private restored state without publishing it. If the
   selected kernels cannot meet these fixed semantics, reject this candidate.
5. Structural/same-math cases: two token IDs at one address; positions
   0/1/127/128/2047/2048/4095/4096; reset; capture on two different workspaces;
   cancellation after segments1/4/8; uninterrupted versus save/restore;
   prompt65 followed by decode; final legal 128K position. Compare all logits,
   hidden values, recurrent state, convolution rings and committed KV bitwise
   against the same admitted eager arithmetic and FFN-only graph control.
   Preserve completed frontier on cancellation. Zero additional model weights;
   all graph allocations must fit with ≥1.5 GiB reserve at 128K.
6. Screen control+candidate at D2048+32 with 1+3 restored AB/BA. Run/reuse Q
   by exact-output proof; no numeric relaxation is available for graphs.
   Acceptance component is the full 64-layer decode body, 3+10 restored pairs
   at each prefix, positive CI and ≥0.10 ms/token saving. Then five complete
   engine pairs at D128/D2048+32 with p95, one P4096 guard and state/memory
   acceptance. Include parameter updates, poll callbacks and commit/copy work.
   Select only `decode_segments8` if every gate passes; otherwise `ffn_only`.

## Acceptance

- Fresh ≥0.50 ms/token unhidden overhead at both prefixes is a prerequisite;
  low overhead completes the task as no-reopen.
- Graph/eager is bitwise same-math; state/checkpoint/cancellation and 128K
  reserve pass. Parameter-update overhead cannot be excluded from speed claims.
- Independent verdicts: `kernel_parity_pass`, `model_quality_pass`,
  `performance_pass`, `production_kept`, with D128/D2048+p95 evidence.
- `claims_throughput: true` for conditional acceptance; no-reopen emits false.
