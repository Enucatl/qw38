## Goal and boundaries

Make the existing handbook and source/evidence ledger auditable against the
implementation ledger: every implemented non-educational increment is covered
by a chapter or audit entry that identifies its task, classifies its claims,
states the invariant and failure/proof boundary, and links repository evidence.
Preserve partial and historical evidence as partial or historical rather than
promoting it to release evidence.

- Constraints: treat `plan.md` and `implementation_ledger.md` as authoritative;
  preserve the four claim classes `Measured`, `External`, `Estimated`, and
  `Proposed`; keep the handbook beginner-readable; use repository-relative
  links; retain negative results and explicit proof limits; keep the current
  CUDA-only v1 product boundary distinct from future portability discussion;
  do not change implementation claims merely to make documentation checks pass;
  after the authorized root `README.md` edit is final, refresh only that file's
  SHA-256 entry in the four existing contract `local_sources` maps that already
  authenticate it.
- Non-goals: completing blocked `EVAL-001`; producing QLT-001 quality evidence,
  CMP-001–CMP-003 baseline/comparison results, or the REL-001 release bundle;
  changing runtime code, public APIs, fixtures, performance measurements, model
  artifacts, or `plan.md`; changing pin semantics or any pin value other than
  the four stale `local_sources["README.md"]` digests named below; rewriting the
  foundational handbook.
- Plan impact: `none`
- Affected interfaces: documentation navigation and provenance records, four
  existing README source-integrity metadata entries, plus a pytest
  documentation-maintenance gate; no product/runtime interface changes.

## Implementation decisions

Add `docs/65-documentation-audit.md` as the human-readable coverage record for
DOC-001. It will define what counts as an implemented concept, explain the four
claim labels, and provide a compact coverage table for every non-EDU ledger task
that is `done`, plus rows for active or blocked work that has partial checked-in
implementation. Each row will contain task ID(s), linked handbook location,
claim class, the invariant/failure or proof-limit location, and linked
code/contract/fixture/evidence. ART tasks may be grouped as repository-control
concepts; related tasks that share one chapter may share a row. EDU tasks are
not duplicated because their ledger acceptance and existing chapter links are
the educational coverage evidence. DOC-001 itself will appear in the table so
the check continues to pass after delivery changes its status to `done`.

Add `tests/test_documentation.py` as a stdlib-only pytest gate. It will parse the
ledger task table, require every `done` non-EDU task (including DOC-001 at final

implementation chapter from 13 through the audit chapter to be listed exactly
once in `docs/README.md`, require the source/evidence ledger to be indexed, and
resolve all repository-relative Markdown links in root `README.md` and
`docs/**/*.md`. It will not fetch external URLs, validate remote availability,
or attempt a semantic natural-language linter. The human audit table is the
semantic record; the test guards its mechanically checkable edges.
