## Outcome

Turn the split OPT-103 result into a prefix-aware production selector. Retain
`warp_query` where it won and use the existing `vec128_online` implementation
only where it wins. This task adds no new attention arithmetic.

## Why this has not been tried

OPT-103 required one global candidate to improve both D128 and D2048. Its
component evidence instead showed a possible crossover: `warp_query` won at
D128 (1.600 vs 1.704 ms over 16 layers), while `vec128_online` won at D2048
(9.263 vs 8.873 ms, paired 95% interval 0.016–0.764 ms). The candidate was
therefore rejected even though a runtime prefix selector could preserve the
D128 path and take a reproducible long-prefix win. The component and engine
measurements are separate claims; neither may be substituted for the other.

## Implementation

1. Keep the OPT-103 kernels, arithmetic, `n_parts=16`, KV layout, query
   preparation, and merge unchanged. Add only a context-position selector.
2. Screen thresholds at 512, 1024, 1536, and 2048 committed tokens. Measure
   complete 16-layer attention at positions 128, 512, 1024, 1536, 2048, and
   4096. Include a 128K representative only to verify that the selector falls
   back safely; do not extrapolate an unmeasured threshold to arbitrary lengths.
3. Choose the lowest threshold for which `vec128_online` has a positive paired
   saving at that position and every longer *measured* position through 4096.
   A threshold is not admitted on a point estimate alone. If no threshold
   satisfies the rule, reject without additional sampling.
4. Prove that positions below the selected threshold, and positions outside
   the verified range, dispatch byte-for-byte to the existing `warp_query`
   graph/eager path. A selector branch must not add a kernel, synchronization,
   allocation, or state copy.
5. Record actual path and partition count for every measured position. Retain
   OPT-103 rejection evidence unchanged; this is a new hybrid configuration,
   not a reinterpretation of the old global candidate.

## Acceptance and stop rule

- D128 must select `warp_query`, preserve output identity, and meet the existing
  2% latency/p95 non-regression guard.
- D2048 complete attention must save at least 0.10 ms/token with a positive 95%
  paired interval; D2048 engine point throughput must improve and its
  one-sided regression bound must pass. This small opportunistic win is not
  evidence that the underlying vector stack is solved.
- Quality, state, and memory gates remain unchanged. On any failure, retain
  global `warp_query` and report a measured rejection.

## Non-goals

No new vector kernel, GQA6 retry, KV type change, approximate math, partition
sweep, prompt-attention change, or benchmark/gate redefinition.
