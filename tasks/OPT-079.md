# OPT-079 — Convert prompt attention KV operands once per shared tile

Status: pending. Dependencies: OPT-070, OPT-071, OPT-073. Coupled IDs: none.
Priority: P3, conditional single prefill experiment after decode admission work.
Target: redundant BF16-to-F16 conversion inside prompt attention MMA loops.
Read [the post-069 protocol](PERFORMANCE-RECOVERY-POST-069.md).
Quality risk: low for byte-identical operand reuse; stage lifetime is critical.
Instrumentation: one selected SASS conversion/resource check and family replay.

## Evidence and implementation

1. Confirm OPT-071 finds material remaining P4096 attention time. In the
   selected `f16_async` path, cp.async stages BF16 K/V; `fattn_qk_mma_k16`
   repeatedly converts keys and the P×V fragment loop repeatedly converts
   values to half. This task moves those exact conversions outside reuse loops.
   It does not retry the rejected `gqa6`/`nbatch64` variants or OPT-051's
   precision selection. No-go if compiled code already removes that redundancy
   or measured complete-family headroom is below 5 ms/P4096.
2. Retain existing tile dimensions, two-stage async ring, register softmax,
   stream-K, query preparation and selected F16 arithmetic. After each stage's
   cp.async completion, cooperatively convert each live BF16 K/V operand to
   the same F16 bits once. Reuse the stage's 16-bit storage in place with
   explicitly typed access, or demonstrate an equally bounded shared layout.
   Consumers load F16 packed fragments directly. No global converted KV cache.
3. Enforce stage ownership: no conversion before producer completion, no
   consumer reads before conversion/barrier, and no next asynchronous write
   before the last consumer. Each stage is converted exactly once per load,
   including prologue, reuse, empty/tail and drain. Do not convert an F16 slot
   again as BF16. Keep fallback and candidate/committed-origin handling.
4. Prove F16 operands and complete attention outputs equal the current path
   for unchanged arithmetic. Cover finite BF16 values around half rounding,
   signed zero, underflow and overflow handling; do not add clamping or silently
   extend the admitted range. No change to public BF16 KV, prompt transaction,
   logits, workspace reserve or decode dispatch.
5. Compare one candidate against f16_async control on real P4096 attention
   inputs/cache across 16 layers. Include prep, stage conversion, core, merge,
   gating and KV work at the same boundary. Report conversion instructions,
   shared/register/local usage, and resource losses honestly.

## Tests and commands

Target `build/qw38-cuda-opt079-attention-kv-operands-test`; tests
`tests/test_opt079_attention_kv_operands.py`. Full tiny cases use prompt rows
1/17/33 and KV tiles spanning two ring wraps with distinct sentinels. Real
quality samples: four prompt rows x eight output dimensions x four heads on
calibration layer3 and held-out layer63; full GPU finite/output comparisons.
Feedback is two configurations x (1+3) complete attention rounds at P4096.
Optional sanitizer uses only the tiny stage-lifetime cases.

```sh
uv run pytest -q tests/test_opt079_attention_kv_operands.py
uv run python tools/run_optimization_task.py --task OPT-079 --mode feedback --phase attention
uv run python tools/run_optimization_task.py --task OPT-079 --mode acceptance --phase attention
```

Common 3+10 paired component rounds, five P4096 whole-run pairs, and short
decode guards decide keep. Require >=5 ms/prompt estimated saving. Stop on
stage race, operand mismatch, shared-memory spill/occupancy loss, no measured
conversion reduction or inconclusive complete cost. Do not expand into another
attention tile sweep. Default unchanged on no-go/reject.
