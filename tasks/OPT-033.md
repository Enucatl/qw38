### Kernel behavior (frozen)

Retain:

- Ncols1=16, Ncols2=2, `kFattnNbatchFa=32`, dual-F16 Q, `__launch_bounds__(128, 2)`, `grid.z=2` (`KvParts=2`)
- Q RMSNorm, partial RoPE, dual-F16 Q staging, Q×K MMA, online FP32 max/denominator, causal mask, GQA subgroups, candidate-versus-committed isolation
- Scalar probability×V inner product over the 32-row tile (same `scores[qcol * 32 + krow] * bfloat16(V)` order, same `*` then `+=` under `--fmad=false`)
- Stream-K combine kernel **byte-identical** to today (max/den rescale, gate after combine)
- Score scratch untouched; committed cache not mutated by prepare

Register path (`RegisterAcc=true`):

- Each thread holds a compile-time-sized FP32 array of `kFattnNcols2 * Ncols1 * (kFattnHeadWidth / kNthreads)` accumulators (production: `2 * 16 * 2 = 64` floats).
- All accumulator accesses live in `#pragma unroll` loops whose indices are compile-time constants (`member`, `row`, `dim_slot`). Do not index the array with a runtime-only `active_rows` bound in a way that forces local memory. Loop `row = 0 .. Ncols1-1` always; skip the V add when `row >= active_rows`; write only live rows.
- Initialize accumulators to `0` in registers. Skip the per-tile-start global `vkq[...]=0` stores.
- Per KV tile: `acc = acc * factor`; then the existing scalar V loop into `acc`. Do not load or store `vkq` inside the tile loop.
- After the KV loop, store each live lane once to global `vkq` (`output` for `kv_z==0`, `partial` for `kv_z==1`). Then existing meta write (`tid==0`) and existing combine launch.
- `KvParts==1` templates used by occ2/baseline are not retargeted.

`RegisterAcc=false` remains today's global load/rescale/store. Production pin `global` must be byte-identical to current `main`.
