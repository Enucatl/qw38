# OPT-098 — Combined post-088 outcome gate
Status: pending. Dependencies: OPT-097. Coupled IDs: none.
Priority: P1. Target: one authenticated combined quality and performance sitting against pinned llama.
Read [the post-088 protocol](PERFORMANCE-RECOVERY-POST-088.md).
Quality risk: individually accepted changes can interact; a relaxed successor gate can be mistaken for historical release success.
Instrumentation: effective production launches, complete Q, full uninstrumented P4096/D128/D2048+p95, 2K, checkpoint/cancellation and 128K reserve.

## Outcome

Freeze and measure the combined post-088 production outcome. Report internal
improvement with admitted quality, llama parity and original OPT-056/+5%
separately, including failed outcomes. Completing this task does not require
beating llama and does not authorize inventing another kernel.

## Implementation

1. Create `pins/opt098_batch_gate_contract.json`, the iteration contract,
   `tools/opt098_batch_gate.py`, `tests/test_opt098_batch_gate.py`,
   `fixtures/opt098_batch_gate.json` and
   `evidence/optimization/opt098-batch-gate/REPORT.md`. Reuse
   `tools/opt088_batch_gate.py` measurement helpers without mutating old evidence;
   add `cuda-opt098-diagnostics` using existing quality, state/memory,
   `build/qw38-cuda-prefill-4k-oracle-test` and
   `build/qw38-cuda-decode-oracle-test` targets. Historical oracles are reachable
   only in this task's explicit long release phase, never feedback or ordinary pytest.
2. Freeze `post088_control` to the authenticated OPT-088 selectors and
   `post098_selected` to the final accepted selectors from OPT-089–097. These
   are the only two Quartz configurations; pinned llama is the external
   control. Reject a selection without complete owning-task evidence, any
   rejected-candidate leakage, or source/cache/flags/model mismatch. Actual
   graph launches must agree with selector records, not just header pins.
   Retain `-O2 --fmad=false`, identical GGUF, tokens, vocabulary and power policy.
3. Recheck all corrected positive parity and same-math cases touched by the
   kept combination, including grouped Q8, paired Q4, attention and graph
   identities where selected. No documented-positive-failure exemption. Run
   full Q once on the combined arithmetic, reusing pinned llama/control data
   only with exact identities. Freeze fields `strict_ppl_ratio_max=1.01`,
   `conditional_late_w4_ppl_ratio_max=1.015`,
   `recurrence_incremental_nll_max=0.02`, `allow_incomplete_quality=false`,
   `quality_budget_ratchets=false`, `historical_opt056_unchanged=true`.
4. Report Q against both frozen OPT-084 and authenticated OPT-088 anchors, and
   pinned llama separately. The 1.015 ceiling applies only if final Q4 is the
   exact conceded late_w4 and subsequent changes proved same-math relative to
   that arithmetic. Factored Q4 or new recurrent arithmetic requires strict
   1.01; no transfer of the exception. Preserve all eight task answers and the
   inherited arithmetic failure. New functional/continuation/state failure or
   missing evidence stops release timing and records a quality-blocked outcome.
5. Predeclare one long sitting: matched historical P4096 and decode workloads
   at prefixes128/2048 generating256 tokens, 3 warmups +30 measured samples
   for each configuration/engine/workload, AB/BA whole-run order, raw samples,
   confidence intervals and actual ITL p50/p95. Preserve the OPT-021/032/088
   token sequences, prefix/copy/commit semantics and no-prefix-reuse settings.
   No attribution or counters in these timed runs. Source, binaries, flags,
   graphs, temperature, clocks and 400 W readback go in the sitting manifest.
   If selected equals control, measure that Quartz configuration only once.
6. Run unchanged 2K comparison and state/128K allocation/reserve, checkpoint,
   cancellation and retrieval_128k consistency checks in their named long
   phases. Record ≥1.5 GiB reserve after graph creation, full recurrent/conv/KV
   state and actual cancellation frontier. No one-point 2K result closes the
   OPT-016 ledger owner. Session TTFT is secondary, not a decode replacement.
7. Three independent outcome objects: (a) internal decode gain versus fresh
   OPT-088 control with active quality, paired 95% geometric-mean speed ratio
   lower bound >1, every individual throughput ratio ≥0.95 and every decode
   p95 ratio ≤1.05;
   (b) llama parity, every primary workload Quartz throughput ≥llama and decode
   p95 ≤llama; (c) historical OPT-056/+5%, evaluated only with its unchanged
   owning contract, including original quality, uncertainty/p95 and OPT-016
   prerequisites. Emit false where conditions are unpassed. Report parity
   saving `Tq-Tl` and +5% saving `Tq-Tl/1.05` in clearly named units.
8. If the late concession is active, also confirm D128 and D2048 individually
   have paired speed-ratio lower bounds >1.15 and p95 ≤0.90× the fresh packed
   control. On failure or combined quality regression, restore the last
   fully validated nonconcession selection from task evidence; remove the
   concession and any dependent keeps without valid compatibility evidence.
   Record the exact reverted selectors and `rollback_quality_unverified`
   until that combination's Q passes. Do not publish a rolled-back throughput
   number without measurement. No second full performance sitting in this task.

## Acceptance

- All selected paths have complete parity, quality and keep evidence; combined
  quality/state passes or an explicit blocked/rollback result is recorded.
- P4096, D128, D2048 and raw p95 have complete samples if timing ran, with
  2K/state/memory outcomes and all three historical/successor verdicts separate.
- Independent fields `kernel_parity_pass`, `model_quality_pass`,
  `performance_pass`, `production_kept` name the active contract and evidence
  completeness. `release_eligible` is never a synonym for `opt056_pass`.
- `claims_throughput: true` for complete measured throughput evidence, even
  when the performance target fails; no improvement claim without its CI and
  quality. Quality-blocked preflight emits false.

## Tests and commands

```sh
uv run pytest -q tests/test_opt088_batch_gate.py tests/test_opt091_quality_tradeoff.py tests/test_opt098_batch_gate.py
uv run python tools/run_optimization_task.py --task OPT-098 --mode feedback --phase freeze
uv run python tools/run_optimization_task.py --task OPT-098 --mode feedback --phase preflight
uv run python tools/run_optimization_task.py --task OPT-098 --mode release --phase quality
uv run python tools/run_optimization_task.py --task OPT-098 --mode release --phase state-memory
uv run python tools/run_optimization_task.py --task OPT-098 --mode release --phase performance
uv run python tools/run_optimization_task.py --task OPT-098 --mode release --phase two-k
uv run python tools/run_optimization_task.py --task OPT-098 --mode acceptance --phase report
```

Freeze is host-only; preflight is bounded parity plus 32-target alarm with a
300 s aggregate deadline. Quality and state-memory use explicit 7200 s long
budgets; performance uses a separately predeclared 21600 s budget, two-k 3600 s.
No long phase is an automatic fallback from a timed-out feedback command.
`report` only validates/assembles completed evidence. Preserve partial/failed
runs; do not lower sample counts or keep sampling for significance.

## Non-goals

No new optimization, automatic next batch, remote quality scorer, historical
evidence rewrite, absolute task-accuracy claim or relaxation of OPT-056/016.
