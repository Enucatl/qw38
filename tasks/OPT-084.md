# OPT-084 — Establish baseline quality under current shipping Quartz

Status: pending. Dependencies: OPT-083. Coupled IDs: none.
Priority: P0. Target: freeze shipping quality before reconsidering candidates.
Read [the post-080 protocol](PERFORMANCE-RECOVERY-POST-080.md).
Quality risk: measurement of the current engine; no candidate install.
Instrumentation: effective selectors/dispatch recorded on every run.

## Outcome

The complete local quality suite from OPT-083 is run on pinned llama.cpp and
on the shipping Quartz configuration frozen at the start of this batch. The
resulting numbers and acceptance criteria are frozen. Future candidates must
not materially regress this Quartz baseline. No new candidates are installed.

Shipping configuration to score (must match OPT-080 freeze):

- Q4 `packed` / `paired_staged`
- Q8 `r2_w2`
- MMQ `fma_async_x` `i128_j128`
- prompt attention `kv_once`
- decode GDN sequential
- decode attention `warp_query`
- `--quality` enabled as defined by OPT-083

## Implementation

1. Run the OPT-083 local suite, speed shortcuts disabled, on:
   - pinned llama.cpp scorer/control;
   - current shipping Quartz.
   Same tokenizer, GGUF SHA, prompts, continuations, targets, and scoring
   convention. Authenticate model identity.
2. Produce inspectable per-test llama results, per-test Quartz results,
   aggregate NLL, Quartz-vs-llama differences, existing Quartz baseline
   defects, recurrence/state results, and task-accuracy results. Distinguish
   absolute quality from Quartz regression (regression vs shipping is
   tautological here and recorded as the zero-delta baseline).
3. Freeze acceptance criteria **before** OPT-085/086/087:
   - primary candidate gate: no material regression vs this Quartz baseline
     on teacher-forced NLL/PPL, recurrence incremental NLL, continuation
     consistency, and OPT-073 engine non-regression;
   - PPL ratio ≤1.01 and recurrence drift ≤0.02 remain;
   - absolute task accuracy stays the visible OPT-073/v2 fail on
     `task_arithmetic` (A vs expected B) unless this sitting records a
     different parsed outcome — do not make that historical failure
     disappear;
   - Quartz-vs-llama deltas are inspectable controls, not a projection-error
     substitute;
   - a known baseline defect does not by itself reject a later kernel that
     does not worsen it.
4. Reclassify OPT-056/073 findings under the new framework without changing
   their historical reports. OPT-056/016 stay blocked.
5. Record effective selectors, `--quality` delta, graph/eager identity, and
   llama revision/GGUF SHA in
   `pins/opt084_quality_baseline_contract.json`,
   `fixtures/opt084_quality_baseline.json`, and
   `evidence/optimization/opt084-quality-baseline/REPORT.md`.

## Acceptance

- Fixture contains per-example and aggregate llama and Quartz scores, token
  counts, nonfinites, identities, and explicit
  `absolute_quality_status` vs `quartz_baseline_regression_status`.
- Shipping selectors match the freeze list; mismatch fails closed.
- No candidate kernel installed. `claims_throughput: false`.
- Criteria freeze is complete enough that OPT-085 can evaluate regression
  without inventing a new threshold.

## Tests and commands

Host tests reject incomplete suites, selector mismatch, remote-scorer
invocation, and relabeling of historical OPT-056/073 failures.

```sh
uv run pytest -q tests/test_opt084_quality_baseline.py
uv run python tools/run_optimization_task.py --task OPT-084 --mode feedback --phase llama
uv run python tools/run_optimization_task.py --task OPT-084 --mode feedback --phase quartz
uv run python tools/run_optimization_task.py --task OPT-084 --mode acceptance --phase baseline
```

Feedback llama/quartz may be split to honor 300 s; identity-cache the model
and tokenizer. Acceptance assembles the freeze once. Full-suite GPU work is
required here; it is the baseline sitting, not a keep. Do not run P/D
oracles. Do not call OpenRouter.
