# OPT-063 — Fuse cooperative integer gate/up and SwiGLU

Status: pending. Dependencies: OPT-062. Coupled IDs: none.
Primary target: D2048. Read [the batch protocol](PERFORMANCE-RECOVERY-2026-09-11.md).

## Preconditions and implementation

Proceed only if OPT-062 produced a numerically admitted cooperative Q4 variant.
If it rejected every integer variant for quality, close this task as a documented
no-change with that evidence; do not build a fusion around invalid arithmetic.
If only performance was rejected, the admitted arithmetic can still be tested
against current production as a combined fused candidate.

Read `cuda/q4k_decode_dots.cuh::vec_dot_q4k_group`/`q4k_coop_mmv`,
`cuda/quant_mmv.cu::quant_mmv_q4k_gate_up_swiglu`,
`cuda/full_scheduler.cu::execute_ffn`, and pinned
`mmvq.cu::mul_mat_vec_q`'s `has_fusion` handling.

1. Add a focused paired kernel in `cuda/q4k_decode_dots.cu` or a new small TU.
   Keep two original GGUF weight pointers; no concatenation or repack. Each CTA
   owns the same output row in gate and up, K split across4 warps initially.
   Load an activation pack once per K/group and feed two packed Q4 dot paths.
   Keep gate and up FP32 accumulators separate through K.
2. Start with the exact OPT-062 accepted dot/staging semantics, including scale
   and min corrections. Refactor only the shared pack decoding needed to reuse
   activation loads. The existing kernel performs group shuffles inside K;
   do not simultaneously invent a different reduction tree here. Reduce both
   accumulators with the same row-completion mapping as the unfused control.
3. After the complete row reduction, compute existing SwiGLU arithmetic
   `silu(gate)*up` and round once to BF16. Write `ffn_activated_` directly;
   gate/up FP32 output arrays are unnecessary in normal execution. Do not fuse
   the following32-value Q8 activation quantization across independently scheduled
   row CTAs; keep its existing separate stage before down.
4. Candidate list: admitted separate integer FFN control and paired 4-warps.
   Add paired 2-warps only if compiler/resource evidence shows a concrete4-warp
   problem; do not sweep1/2/4/8 again. Report registers, spills, shared memory
   and active blocks. Keep current production as an extra performance control
   if OPT-062 did not install the separate integer path.
5. Add an explicit paired-integer selector and its staging format to
   `ffn_decode_path.cuh`, wire `execute_ffn`, invalidate reused activation caches
   and recapture FFN graphs. Trace mode may use the unfused equivalent when
   separate gate/up taps are requested; label the fallback and test numerical
   equivalence instead of inventing fused intermediate buffers in production.
