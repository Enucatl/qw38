# OPT-060 — Measure matched full-engine family gaps

Status: pending. Dependencies: OPT-057. Coupled IDs: none.
Primary target: trustworthy Quartz versus llama attribution.
Read [the batch protocol](PERFORMANCE-RECOVERY-2026-09-11.md).

## Scope and reference points

Extend Quartz `GpuPhaseRecorder`, `LeafTimings`, OPT-043 diagnostics, and a
private diagnostic build of pinned llama. Pinned entry points are
`ggml/src/ggml-cuda/ggml-cuda.cu::ggml_cuda_graph_evaluate_and_capture`,
`ggml_cuda_try_fuse`, `ggml_cuda_compute_forward`, and `mmvq.cu`/`mmq.cuh`
dispatch. Existing `component_gap.cpp` creates isolated ggml ops and cannot
provide this full-engine comparison.

## Implementation

1. Add a checked-in minimal patch under `tools/llama_authority/patches/` and an
   idempotent build helper that verifies `cc83d7b...`, applies it to an isolated
   worktree/cache copy, and records patch SHA, CMake flags and image identity.
   Leave sibling source, production authority image and historical evidence
   intact. This is a private instrumentation build, no upstream submission.
2. Define a shared record: engine, phase, sequence/token position, layer, role,
   tensor name/type/M/N/K/strides, stream, launch family, fused member IDs,
   start/end events, graph mode and complete-work attribution. Group gate/up/GLU
   as one family if actually fused; record member operation counts but charge
   time once. Include activation quantization, final epilogues, copies, graph
   and CPU/unknown gaps. Never force a fused operation into artificial sub-times.
3. Place events around actual execution on `cuda_ctx->stream()` in llama.
   Record one enclosing pair for a fused operation before advancing skipped
   nodes. Normal graph replay bypasses that host loop: implement an explicitly
   labeled diagnostic eager mode with fusion retained, and a graph-enabled
   timeline capture when tools permit. Do not describe eager events as normal
   graph timings. Register compile-time-only NVTX ranges with operation IDs.
   Prefer preallocated event pools, resolve once after the run; avoid an event
   synchronize or printf after every kernel. Quartz's current per-phase event
   create/destroy can be pooled in the diagnostic path for the same purpose.
4. Inspect llama concurrent streams. Preserve their schedule and event stream
   identity; summed GPU durations are work, not wall time when operations overlap.
   Report interval union/critical-path information separately. A fallback
   single-stream diagnostic must be labeled and cannot prove production deltas.
5. For each engine use exactly the same model, token IDs, prompt/prefix, output
   count, cache dtypes, logits policy and physical batch where supported. Record
   both historical authority defaults and a matched-batch diagnostic; do not
   silently change the oracle to favor Quartz. Read actual selected FFN/Q8/Q6
   dispatch and graph/fusion behavior rather than relying on source availability.
6. Produce P4096 and D2048 tables of full-engine enclosing family ms, call counts,
   Quartz minus llama differences and unattributed/overlapped time. Display
   uninstrumented wall measurements beside instrumented measurements and report
   overhead. Use this for ranking only. A matched-token diagnostic has a distinct
   identity from `llama-bench` if that tool uses a different input policy.
7. Try installed host/container `nsys` and `ncu` discovery once. Use timeline
   tracing for one 16-token decode range and one prefill range. Do not install
   host packages or run a full Nsight Compute sweep just to finish this task.
   Record unavailable tools/errors; events plus actual dispatch are the required
   fallback. OPT-061 owns targeted hardware counters.

## Fast tests

Native Quartz target: `build/qw38-cuda-opt060-engine-attribution-test`.
Authority target: `qw38-llama-engine-attribution`. Add
`tests/test_opt060_engine_attribution.py` for stream-aware aggregation,
fused-member double-count prevention, missing/unmatched roles, event-pool
overflow, and patch/revision identity. Synthetic intervals must include an
overlap where summed time is greater than wall time.

Smoke: 3 tiny synthetic operations (one fused pair), no model. Correctness:
same case in two graph modes, one warmup/one sample, exact output comparison.
Screen `decode`: 2 engines × 2 modes (unperturbed/diagnostic) × 1 prefix 2048
with 16 output tokens. Screen `prefill`: 2 engines × 2 modes × 1 P4096. Build
instrumented llama once as explicit setup, not within each feedback phase.
No candidate sweep, no 30-run decode sitting, no host scalar full engine.

```sh
uv run pytest -q tests/test_opt060_engine_attribution.py
uv run python tools/run_optimization_task.py --task OPT-060 --mode feedback --phase decode
uv run python tools/run_optimization_task.py --task OPT-060 --mode feedback --phase prefill
uv run python tools/run_optimization_task.py --task OPT-060 --mode acceptance
```

Each phase inherits the 300-second deadline. On acceptance collect three
repetitions per listed workload/mode to report stability, not throughput claims.
Keep engine order alternated and GPU ownership exclusive.

## Acceptance

Deliver contract/fixture, patch/build provenance, raw operation records and
`evidence/optimization/opt060-engine-attribution/REPORT.md`. Explain every
family's inclusion/overlap, show real selected kernels and quantify profiling
overhead. If graph-enabled attribution is unavailable, label eager results and
retain the uninstrumented graph wall total; never invent paired production
kernel deltas. This instrumentation task can complete without a speedup or
Nsight counters. It cannot complete with only old isolated-op timings.
