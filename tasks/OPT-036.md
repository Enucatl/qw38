### Kernel behavior (frozen)

Retain:

- `stage_chunk_rows` candidate K/V staging (RMSNorm + partial RoPE + BF16 candidate) exactly as today
- GQA grouping (`query_heads / kv_heads == 6`), `kAttentionKvTileRows = 32`, `kThreads = 256`, physical committed KV addressing, candidate-versus-committed isolation
- FP32 online per-partition max / denominator / numerator (same inner scalar Q·K reduction and V accumulation as the current grouped tiled path; this increment does **not** introduce MMA — that is OPT-035)
- Gate sigmoid applied **once after merge** (not per partition)
- `token_count == 1` diagnostic `normalized_query` write from **part 0 only** (avoid multi-part races)

Contiguous partitions for legal length `L = position + 1`:

```text
part_begin(p) = (p * L) / n_parts
part_end(p)   = ((p + 1) * L) / n_parts
```

Part `p` owns rows `[part_begin, part_end)`. The current token's candidate row is index `position`. Empty parts (`part_begin == part_end`) write `max = -INFINITY`, `den = 0`, `numerator[:] = 0` and skip the KV loop.

Grid: `(kv_heads, n_parts)` one GQA group × one partition per block. Layout:

- `partial_vkq[query_head * n_parts * 256 + part * 256 + lane]`
- `meta[query_head * n_parts + part]` as adjacent FP32 `{max, den}`

Merge kernel (deterministic ascending-part combine, llama.cpp `flash_attn_combine_results` technique):

1. `global_max = max_p meta[p].max` over `p = 0 .. n_parts-1`
2. For `p = 0 .. n_parts-1` in increasing `p`: `scale = expf(meta[p].max - global_max)`; accumulate `scale * numerator[p]` and `scale * den[p]`
3. `ungated = numerator / denominator`; apply the existing gate sigmoid; write `output`

No atomics. No reordering. `n_parts == 1` does not launch merge.
