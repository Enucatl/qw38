# OPT-083 — Port/adapt ds4 full-model quality framework

Status: pending. Dependencies: OPT-058, OPT-073, OPT-080. Coupled IDs: none.
Priority: P0. Target: model-quality suite as the primary behavior gate.
Read [the post-080 protocol](PERFORMANCE-RECOVERY-POST-080.md).
Quality risk: infrastructure only; no production kernel change.
Instrumentation: per-example/per-token inspectable artifacts.

## Outcome

Quartz gains a ds4-style quality runner adapted to pinned Qwen3.8. Production
projection-error admission is no longer the quality gate. Kernel parity is not
inferred from model output, and model quality is not inferred from kernel
parity. No production kernel change. Remote OpenRouter scoring is exposed and
disabled.

## Implementation

1. Inspect `../ds4/gguf-tools/quality-testing/` (`README.md`,
   `score_official.c`, `score_llama.cpp`, `compare_scores.py`,
   `collect_official.py`, `prompts.jsonl`). Port architecture: teacher-forced
   continuation NLL, official/known continuations, llama control scorer,
   inspectable per-case TSV/JSON, comparator with per-example deltas. Do not
   copy DeepSeek/GLM fixtures as if they were Qwen continuations. Document
   those datasets as **not applicable**. This is not a same-model comparison
   with ds4.
2. Adapt to Qwen3.8: pinned GGUF, Quartz tokenizer/template
   (`enable_thinking=false`), existing OPT-058/073 cases, and new
   deterministic Qwen continuation fixtures owned by this task. Reuse
   `tools/run_llama_quality_reference.py` and
   `build/qw38-cuda-opt058-quality-baseline-test` rather than a second llama
   adapter. Prove Quartz and llama use identical tokenization, context
   construction, target tokens, and scoring definitions on a frozen fixture.
3. Suite classes (all inspectable, not aggregate-only):
   - teacher-forced continuation scoring (NLL per example and aggregate);
   - official/known continuations (deterministic Qwen fixtures; not remote);
   - NLL/PPL comparisons on the existing 1024-target spans;
   - recurrence short/long incremental NLL;
   - OPT-073 functional dual verdict (absolute vs engine non-regression);
   - 32 held-out teacher-forced targets as alarm, not kernel admission;
   - finite vocabulary and structural state/continuation consistency.
   Retain OPT-073/PPL/recurrence evidence by reorganizing it under this
   framework. Do not make historical OPT-056/073 failures disappear.
4. Explicit `--quality` mode. Document the exact flag/selector/precision
   delta in `pins/opt083_quality_framework_contract.json`. Quality mode must
   disable any shortcut that would make the run fail to represent the
   production arithmetic configuration under test (including diagnostic
   fallbacks and any speed-oriented numeric bypass). Record effective
   selectors and dispatch. Graph vs eager, if both run, is
   `same_math_equivalence` evidence, not a license to use a different kernel.
5. Optional remote OpenRouter scorer interface for `qwen/qwen3.8-27b`:
   default off; no network from ordinary tests; API key only via
   `OPENROUTER_API_KEY` / config, never committed; missing credentials must
   not fail local tests; outputs labeled `external_scorer` and
   non-authoritative; do not call it automatically in this batch. Authoritative
   local comparison remains pinned llama.cpp plus Quartz.
6. Proposed quality-acceptance fields (frozen numerically by OPT-084, not
   here): Quartz-vs-shipping-baseline regression as the primary candidate
   gate; PPL ratio ≤1.01 on both 1024-target spans; recurrence incremental
   NLL ≤0.02; engine non-regression vs OPT-073 v3; absolute task accuracy
   visible and separate; Quartz-vs-llama NLL/continuation deltas inspectable
   with no single projection-error substitute for OPT-074.
7. Layout: `tools/opt083_quality_framework.py`,
   `tools/quality/` runner modules, `pins/opt083_quality_framework_contract.json`,
   `fixtures/opt083_quality_framework.json`,
   `evidence/optimization/opt083-quality-framework/REPORT.md`. Host tests
   cover scoring identity, `--quality` delta documentation, remote-scorer
   default-off, missing-key non-failure, and refusal to reduce results to one
   boolean.

## Acceptance

- Runner produces per-example and aggregate records for Quartz and llama on
  the same fixture definitions.
- `--quality` changes are enumerated and tested (unknown shortcut fails closed).
- Remote scorer cannot run in pytest; absence of credentials is success.
- No production pin or kernel change. `claims_throughput: false`.
- OPT-056/016 remain blocked and unrelabeled.

## Tests and commands

```sh
uv run pytest -q tests/test_opt083_quality_framework.py tests/test_opt073_quality_policy.py
uv run python tools/run_optimization_task.py --task OPT-083 --mode feedback --phase identity
uv run python tools/run_optimization_task.py --task OPT-083 --mode feedback --phase quality-flag
uv run python tools/run_optimization_task.py --task OPT-083 --mode acceptance --phase framework
```

Identity and quality-flag phases are host_only. Acceptance may compile the
existing quality diagnostic once but must not run the full shipping baseline
(that is OPT-084) and must not call OpenRouter. Product stays inside 300 s by
using tiny synthetic continuations for framework proof.

## Non-goals

new logit/projection threshold. No claim of ds4 same-model quality.
