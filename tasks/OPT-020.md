## Goal and boundaries

Split the live 2048-token prefill attribution so mixer-projection MMQ is no
longer buried inside the composite `gdn` and `attention` buckets. One cold
exact-2048 production `sync_tokens` must emit exclusive CUDA-event categories
`mixer_mmq`, `gdn_core`, and `attention_core` together with the existing
`embedding`, `ffn_mmq`, `logits`, `commit_sync`, `graph`, and `other_idle`
values, reconstruct that same run's host wall within the frozen OPT-014
tolerance, and retain the live JSON as OPT-020 evidence. This is
instrumentation for mixer-versus-core steering after OPT-017–OPT-019. It is
not a throughput gate and does not own OPT-016.

## Implementation decisions

Keep production kernels, `matrix_prompt`, decode `RuntimeTimings`, public
Engine/`qw38-bench` schemas, `Makefile`, and `plan.md` unchanged. Keep the
optional trailing `PrefillAttribution*` default `nullptr`. Do not add a

### Exclusive summing categories

Replace composite `PrefillAttribution::gdn` and `::attention` with three
exclusive TimingValues. JSON/fixture keys for the nine summing categories:

`embedding`, `mixer_mmq`, `gdn_core`, `attention_core`, `ffn_mmq`, `logits`,
`commit_sync`, `graph`, `other_idle`

Do not keep composite `gdn` / `attention` on the struct or in `categories_ms`.
Derived composites would invite double-counting in the wall reconstruction.

| Category | Owns (prompt compute stream unless noted) |
|---|---|
| `embedding` | Unchanged: H2D token copy plus batched embedding decode/widen |
| `mixer_mmq` | Every mixer-block `matrix_prompt`: GDN packed_qkv, value_gate, alpha, beta, output; attention query_gate, key, value, output. FFN gate/up/down stay in `ffn_mmq`. |
| `gdn_core` | GDN-layer mixer RMSNorm when it runs in the mixer block, `prepare_gdn_gate_rows`, convolution/scan/recurrence (`launch_gdn_prepare_chunk_tiled` / production fused quality), and `gdn_gated_output_rows` |
| `attention_core` | Attention-layer mixer RMSNorm when it runs in the mixer block, `split_attention_rows`, `launch_attention_prepare_chunk`, and the FP32-to-BF16 convert of attention output rows |
| `ffn_mmq` | Unchanged: fused residual-add-norm, SwiGLU, three FFN MMQ projections, last-layer residual add, or prompt-graph executable |
| `logits` | Unchanged |
| `commit_sync` | Unchanged |
| `graph` | Unchanged host monotonic time around `cudaGraphLaunch`; at 2048 tokens measured 0 with `prompt_graph_launches == 0` |
| `other_idle` | `max(0, wall - exclusive_sum)` where exclusive_sum is embedding + mixer_mmq + gdn_core + attention_core + ffn_mmq + logits + commit_sync + graph |

`wall` remains `std::chrono::steady_clock` around attributed `sync_tokens`
evaluated work. Copy-stream D2H is still not a tenth GPU interval.

Unavailable (`measured == false`) is forbidden for those ten TimingValues
(`nine` summing categories plus `wall`) on a successful attributed run.
`0 ms` with `measured == true` remains legal for empty work (`graph` at 2048).
On a successful cold exact-2048 production run, `mixer_mmq`, `gdn_core`, and
`attention_core` must be strictly greater than 0.

### Non-contiguous mixer MMQ bracketing

CUDA events measure contiguous stream intervals. Per GDN or attention layer,
record three sequential phases that accumulate into the existing destinations:

1. `mixer_mmq` — input projections only (`matrix_prompt` of packed_qkv /
   value_gate / alpha / beta, or query_gate / key / value).
2. `gdn_core` or `attention_core` — RMSNorm when it actually launches in this
   block, then non-projection core work listed above.
3. `mixer_mmq` again — output `matrix_prompt` only.

Skip a phase when that layer has no launches (fused layers after 0 skip
mixer RMSNorm; do not emit an empty event pair). `GpuPhaseRecorder::begin`
already accumulates elapsed time into `destination->milliseconds` on
`collect()`, so two `mixer_mmq` phases per layer sum correctly.

Do not move fused-FFN `next_input_norm` RMSNorm out of `ffn_mmq`.

### Phase recorder size

One attributed 2048-token chunk worst case:

`1 embedding + 64 × (mixer_mmq_in + core + mixer_mmq_out + ffn) + logits +
commit = 259` phases.

Enlarge `GpuPhaseRecorder::phases_` from 132 to **264**. Do not collect/reset
mid-chunk: extra `cudaEventSynchronize` inside the timed run would perturb
more than the extra opt-in events. Decode `execute_token` keeps using the same
class on the default stream; extra unused slots are stack-only (~8 KiB) and
are not extra events when attribution is null.

Null `PrefillAttribution*` still creates no extra CUDA events. Prompt NVTX
ranges always emit, including when attribution is null: keep
`qw38.prefill_chunk`, `qw38.embedding`, outer `qw38.gdn` / `qw38.attention`,
`qw38.ffn`, nested `qw38.graph_launch` only on actual prompt-graph replay,
`qw38.logits`, and `qw38.state_commit`. Add nested labels `qw38.mixer_mmq`
and `qw38.gdn_core` / `qw38.attention_core` around the corresponding
brackets. NVTX remains a label, not a stopwatch.

- Keeping composite `gdn`/`attention` in the summing set plus extra split

- Emitting derived `gdn`/`attention` beside the split — invites consumers to
  sum the wrong set; OPT-017–OPT-019 already retain their composite snapshots.
