## Implementation

1. Extend existing `tools/llama_authority/projection_export.cpp` and its pinned
   private build. It already accepts GGUF/tensor/input; the previous sitting
   exported only synthetic Q4. Bind real tensor names and exact captured BF16
   values converted losslessly to FP32 for the authority, retaining originals.
   Model/authentication, producer revision and reference flags are recorded.
2. Calibrate gate and up K5120, down K17408 first; then Q8 mixer K5120/K6144
   and Q6 vocab K5120 in separate family phases. Preserve actual full M and
   N=1 dispatch, even though output/host-reference checks sample 16 rows.
   Current --row-limit changes M and may choose another CUDA kernel: do not
   use it as evidence of production reduction. Instrument actual dispatch and
   separately export fused gate/up/SwiGLU where the production authority fuses.
3. Use OPT-059's frozen layers 0/3/31/32 at tokens 128/512 for calibration and
   62/63 at 2048/4095 for held-out. Validate family presence against inventory;
   absent layer-kind combinations are explicit, never substituted silently.
   Each named layer/family phase checks at most 16 rows x 4 available captured
   vectors, full K. Decode host rows once and reuse them. Export only the
   relevant full GPU projection(s), not a fresh full model per sampled row.
4. Synchronize the CUDA backend before reading outputs. Independently verify
   original-input error, exact-staged-input error, signedness and scales.
   If needed, export Q8_1 bytes from the actual quantization launcher through
   the private adapter; do not repeat unsupported ggml_cpy F32-to-Q8_1.
   Name sum_q/sum_x/exact-integer-sum variants and identify consumers.
5. Freeze OPT-059 v2 ceilings from authority data before reading candidate
   errors. Preserve v1 and historical missing evidence. Update per-family
   admission records only for measured exact shape/staging/variant coverage;
   wildcard columns=0 is not production coverage. Held-out data validates,
   never enlarges the calibration ceiling. Q4 admission is not contingent on
   finishing unrelated Q6 calibration, but its required Q4 phases must finish.
6. Produce reference cache keys, row/token lists, actual launcher records,
   finite checks and a concise admission table consumable by OPT-075 onward.
   Missing production GPU outputs must yield a blocked deliverable, not
   another successful policy-only freeze with Q4 still unrepresented.

## Tests and commands

Host tests mutate model/tensor/K/M, producer/consumer tags, row lists and
authority revision; test wrong dispatch, missing rows and nonfinite references.
Reuse `build/qw38-cuda-opt059-numerics-test` and the existing pinned
`qw38-llama-projection-export` target. No new general backend.

Feedback selects one listed layer/family case, at most 64 FP64 dots per
projection. Full GPU M is affordable for a projection and preserves dispatch;
full host M references and repeated token-generation captures are forbidden.
Acceptance is one execution of each frozen reference case, not a timing sweep.
Split explicit layer/family phases at the 300-second boundary and cache outputs.

```sh
uv run pytest -q tests/test_opt074_production_gpu_admission.py
uv run python tools/run_optimization_task.py --task OPT-074 --mode feedback --phase q4-gate-up
uv run python tools/run_optimization_task.py --task OPT-074 --mode feedback --phase q4-down
uv run python tools/run_optimization_task.py --task OPT-074 --mode acceptance --phase q4
uv run python tools/run_optimization_task.py --task OPT-074 --mode acceptance --phase q8-q6
```

The grouped acceptance commands expand an explicitly listed finite case plan;
they resume identity-matched reference work, never recalculate a finished
reference because a candidate changed. Stop on unsupported dispatch, absent
captures or nonfinite authority; do not infer a budget from another shape.
