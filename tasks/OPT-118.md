## Outcome and evidence

Reduce measured data transfers and synchronization across token and prompt
boundaries while preserving atomic session behavior. Read [OPT-115](OPT-115.md)
and [OPT-116](OPT-116.md). Use the kept OPT-117 graph path as parent, otherwise
post113; record both parent and post113 comparisons.

[cuda/full_scheduler.cu](../cuda/full_scheduler.cu) copies all 248320 FP32
logits and final hidden values to host, then scatters candidate KV and commits
GDN through pointer swaps. Its prompt path copies GDN carry state between
chunks. [src/engine.cpp](../src/engine.cpp) implements host sampling and public
logits retrieval. These are inspection leads, not evidence of GB-scale PCIe
traffic: the logits vector alone is 993280 B/token, and GDN decode already
uses swaps. Diagnostic trace copies must not be counted as production traffic.

## Implementation

1. Resolve OPT-115's copy/ownership inventory into required public outputs,
   speculative candidates, reusable device state and unnecessary copies.
   Measure H2D/D2H/D2D bytes plus fence/host-sampling latency for ordinary
   generation, explicit logits calls, prefix reuse, and multi-chunk prefill.
2. Select at most two changes by whole-request potential. Candidate A is lazy
   host logits/hidden materialization with device-side greedy selection; a
   sampled mode may retain its host fallback unless moving it is measured and
   fully compatible. Candidate B is eliminating demonstrated redundant
   carry/state copies or fences using existing ownership and event ordering.
   Implement only opportunities the inventory actually shows.
3. Preserve `Session::logits`, `sample`, `eval`, stop behavior and checkpoint
   semantics. Lazy output must refer to the committed frontier, stay valid
   across later operations and materialize on demand. Maintain full-vocabulary
   logits and exact greedy tie/NaN policy. Do not introduce top-k vocabulary
   pruning, approximate sampling or silently change RNG consumption.
4. Any device state lifetime change must preserve rollback on cancellation,
   rejected input and CUDA failure, plus graph address/generation validity.
   No in-place overwrite of the only committed GDN state or live KV prefix.
   Compare repeated sample/logits calls before and after eval, save/restore,
   prefix branching and a failed call. Memory savings must include both
   committed and candidate state and any replacement scratch.
5. Run complete-request screens and acceptance with the parent graph on/off
   as a bounded interaction check. Include one path explicitly requesting
   full logits every token and the ordinary token-only caller. Report GPU
   benchmark timing separately so a host-output improvement is not claimed
   as faster MMV. Include total request wall time and TTFT, not only a CUDA
   interval ending before D2H/commit.
