### `fuse_conv` (required behavior)

Keep the current warp-column grid `(48, 1, 32)` / block `(32, 4)` / `__launch_bounds__(128, 2)`. Extend the token loop so each warp, before the existing Q/K L2 + S update:

1. Holds 4-tap causal history for that lane’s four Q channels (`row*32+lane`), four K channels, and the V channel `col` (`blockIdx.z*4 + threadIdx.y`). Load token 0 from `committed.convolution`; then shift in `convolution_input[token * channels + channel]`.
2. Computes the same `__fadd_rn` / `__fmul_rn` / SiLU as `prepare_convolution_chunk_parallel`.
3. Feeds those Q/K/V registers into the existing warp-column recurrence (do not change S algebra).
4. Writes `candidate.convolution` at the last token: V channel of this `(value_head, col)` from every z-block; Q/K of this `key_head` only from `replica == 0 && blockIdx.z == 0` (all z-blocks recompute the same Q/K; one writer avoids races).
5. Production passes `convolution_output = nullptr` and does **not** materialize `prompt_gdn_convolved_` on this path. Component envelope tests may pass a non-null buffer; if non-null, write the per-token convolved Q/K/V this warp owns (tests compare recurrent + candidate state, which always exist).

Do not change warp-sum L2 / decay / beta / S update. Occupancy of this kernel must be ≥ 1 or the candidate is ineligible.

### `fuse_gate` and `fuse_both` (required behavior)

Gated output RMS needs all 128 columns of a head, which the split warp-column grid cannot see (32 z-blocks). Collapse gated-output **into the token loop** by launching **one block per value head**:

- Grid: `(value_heads)` = 48
- Block: `(32, 32)` = 1024 threads (32 warps)
- `__launch_bounds__(1024, 1)`
- Four column-groups: warp `w` owns column `g*32 + w` for `g ∈ {0,1,2,3}`
- Per thread: `float s_shard[4][4]` (4 groups × 4 key-rows) matching llama.cpp `rows_per_lane=4`
- `__shared__ float attn[128]` plus `__shared__ float inverse`

Per token, after all four groups update S and write `attn[col]`:

1. `__syncthreads()`
2. Lane 0 of warp 0 performs the **same serial RMS fold** as `gdn_gated_output_rows` (`for index in 0..127: sum = __fadd_rn(sum, __fmul_rn(attn[index], attn[index]))`; `inverse = 1/sqrtf(sum/128 + 1e-6)`)
3. Each warp writes gated BF16 for its four columns using grouped→tiled head mapping, SiLU(`gate_tiled`), and `norm[lane]` exactly as `gdn_gated_output_rows`
4. Still write FP32 `recurrent_output[token, head, col] = attn[col]` so GDN-002 envelope tests remain on recurrent values

`fuse_gate` still launches `prepare_convolution_chunk_parallel` first and reads `convolution_output`. `fuse_both` inlines the `fuse_conv` history/SiLU into this one-block-per-head kernel (Q/K history in the 32 lanes; V history per owned column) and skips the parallel conv kernel and the full conv tensor.

If occupancy of the 1024-thread kernel is 0, that candidate is ineligible. Do not invent a third layout.

When `gdn_fuses_gated_output()` is true, `execute_prompt_chunk` **skips** `gdn_gated_output_rows` and passes `prompt_projection_b_`, `layer.gdn.norm`, and `prompt_projected_bf16_` into `launch_gdn_quality_fused`. When false, gated-output stays the existing kernel.
