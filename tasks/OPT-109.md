# OPT-109 — Keep transposed GDN state for the session lifetime

Status: pending. Dependencies: OPT-101, OPT-106, OPT-114. Coupled IDs: none.
Primary target: D128/D2048 GDN core and state traffic.

## Outcome

Evaluate the topology llama actually uses: persistent col-major FP32 device
state from one token to the next, with canonical row-major conversion only at
external checkpoint boundaries. Retain the selected sequential row-major path
as control.

## Why this differs from OPT-101

OPT-101 implemented the warp-column recurrence but its launcher performs a
source-to-candidate transpose, inverse preparation, recurrence, and
candidate-to-source transpose on every layer invocation. It therefore paid two
full 786,432-float state traversals per layer in addition to the recurrence,
then rejected the complete path (13.339 vs 12.418 ms over 48 layers). Pinned
llama keeps `M[col][row]` as the live device representation; it does not pay
those per-token relayouts. Persistent layout lifetime, not the recurrence
kernel alone, is the new mechanism. The OPT-101 timings include enclosing
work, so use recurrence-only and complete timings separately.

## Implementation

1. First run a resident-layout pilot: feed the OPT-101 recurrence a
   pre-existing col-major state and compare it with the current recurrence on
   identical state/query buffers. Stop the task if the recurrence itself loses;
   do not redesign session ownership to rescue a losing kernel.
2. Make both committed and tentative GDN state buffers col-major for the entire
   live session only if the pilot wins. The decode recurrence consumes and
   produces col-major state directly. No row-to-column or column-to-row kernel
   may appear inside a timed layer or token.
3. Preserve atomicity with col-major ping-pong buffers or an equivalent
   recoverable journal. Commit by swapping/advancing ownership only after all
   layers succeed; cancellation and errors leave committed state unchanged.
4. Have prompt GDN emit the persistent layout directly when practical. If a
   prompt-boundary conversion is required, execute it once per synchronized
   prompt, outside per-layer decode timing, and include it in P4096 wall time.
5. Convert to canonical row-major only when serializing a checkpoint or serving
   an explicit diagnostic view; convert back only on restore. Record conversion
   count and bytes for prefill, decode, save, and restore.
6. Reuse the OPT-101 warp-column recurrence, but prepare q/k inverses once per
   key head and keep them out of the 48 value-head inner work. Screen exactly
   `persistent_transposed` against `sequential_row_major`; no tile sweep.
7. Verify that state addresses/layout identities remain stable under CUDA graph
   capture. If pointer swapping invalidates a graph, use graph node parameter
   update or two pre-captured address variants rather than copying state back.

## Verification and evidence

- Add contracts, fixture, native state-layout/lifetime test, component replay,
  host validator, runner entry, and
  `evidence/optimization/opt109-persistent-gdn-state/REPORT.md`.
- Test token counts 0, 1, 2, 32, prompt-to-decode transition, reset, divergent
  prefix replay, checkpoint save/restore, failure after a middle layer, and
  cancellation before publication. Canonical checkpoint bytes must round-trip.
- Run independent FP64 recurrence samples, current full-model quality, and the
  128K memory ledger. Report recurrence-only, conversion-only, and complete
  48-layer GDN time without summing overlapping intervals.
- Performance acceptance uses 3+10 resident-recurrence pairs for the pilot,
  then 3+10 complete GDN pairs and five uninstrumented D128/D2048 engine pairs
  for a surviving session design, plus P4096 and checkpoint-time guards.

## Acceptance and stop rule

- The pilot must beat the current recurrence on identical buffers. A surviving
  session design must contain zero relayout launches in timed decode and save
  at least 0.10 ms/token over complete 48-layer GDN with a positive 95% paired
  interval.
- D128 and D2048 point throughput must improve with existing p95/non-regression
  bounds. P4096, quality, state, checkpoint, cancellation, graph, and memory
  gates must pass.
- If persistent lifetime still loses, retain sequential row-major and do not
  retry OPT-077/094/101 layouts.

## Non-goals

No reduced-precision GDN state, changed recurrence equation, per-token
checkpoint conversion, new scan algorithm, or reinterpretation of OPT-101's
measured rejection.
