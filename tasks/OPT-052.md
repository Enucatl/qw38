# OPT-052 — Remove redundant GDN arithmetic and state traffic

Status: done. Dependencies: OPT-044, OPT-045. Coupled IDs: none. Primary target: P;
secondary D2048. Read [the shared protocol](PERFORMANCE-RECOVERY-2026-09-10.md).

## Change

Start from the selected shared-inverse loop in `cuda/gdn_fused_quality.cuh`.
OPT-040 only hoists inverse norms: every state column still multiplies Q/K by
those inverses and evaluates decay per token. Implement a preprocessing sibling
that produces scaled Q/K per token/key-head and decay per token/value-head,
once, feeding the existing register-state recurrence. Preserve source equations
and epsilon; initially use the identical `expf` and multiplication order.
Read original convolved values for V and preserve tiled-to-grouped mapping.
Use a proven-dead scratch overlay or explicit budgeted workspace; do not
overwrite convolution values before all normalization/V consumers finish.

Next replace eligible update operations with FMA under OPT-044. State remains
FP32: `delta = beta * (v - decay * dot(S,k))`,
`S = decay*S + k*delta`, `out = dot(S,q)` with existing output scale placement.
Keep Q normalization's scale convention exactly as encoded in the reference;
do not add or remove 1/sqrt(width) based on a different model's notation.
Measure precise exp against approximate exp as a separate variant. References:
pinned llama `qwen35.cpp` pre-loop L2 norms and
`gated_delta_net.cu::gated_delta_net_cuda`. Decay hoisting is a Quartz proposal;
llama itself evaluates decay inside its loop.

If OPT-043/updated counters show material state-load/store cost, add a separately
measured variant using a temporary transposed state tile: contiguous lanes load
the logical row-major input cooperatively, transpose in padded shared memory,
then each warp owns a column's registers; reverse at the output. Alternatively
test a transposed private scratch state only when conversion-inclusive time wins.
Keep canonical session/checkpoint layout unchanged in this task. A persistent
layout migration would require a new explicit task with checkpoint compatibility
handling. The transpose is most plausibly useful for decode; prompt amortizes
state entry/exit over thousands of tokens. Do not assume it saves prompt time.

Do not repeat OPT-029 conv/output fusion or OPT-013 affine-operator scan. Both
engines' fused token loops are sequential in time; a new WY/tensor-core GDN
algorithm is outside this bounded task.
