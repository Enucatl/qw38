### Implementation repair (2026-09-12T06:17:46Z)

Python-side OPT-090 call-count mapping. No commit. Production Q4/FFN pins unchanged. `claims_throughput=false`.

Root cause: paired_integer decode records emit one enclosing `ffn_mmv` (`tensor_name=blk.N.ffn_mmv`, empty `fused_member_ids`) plus leaf `ffn_gate_up_glu`/`ffn_down`. OPT-071 `canonical_family` mapped empty-member `ffn_mmv` only to `ffn_gate_up_glu`, so `ffn_down` observed=0 vs 2048. Enclosing+leaf GDN/attention/logits events were also double-counted (and layer-0 emitted two `gdn_core` begins). `unexplained_measured_window` was injected when ranking had no valid windows (`unexplained_share` dummy 1.0); measured unexplained share was already 0.

Fix (option 2): `tools/opt090_decode_attribution.py` treats enclosing `ffn_mmv`/`ffn_mmq` with empty members as one paired FFN crediting both `ffn_gate_up_glu` and `ffn_down`. Graph-fused enclosing records that list both members still credit both. Counts are unique per `(engine, phase, token_position, layer)` so nested leaves and the extra layer-0 `gdn_core` do not inflate expected 64/64/48/16/1 plus 48/16 extras. Ranking uses the window's real accounting when attribution is invalid instead of forcing unexplained=1.0. Added `test_enclosing_ffn_mmv_empty_members_is_one_paired_ffn`.
