# OPT-090 — Measure the remaining decode gap
Status: pending. Dependencies: OPT-089. Coupled IDs: none.
Priority: P0. Target: a valid matched family attribution after the first Q4 decision.
Read [the post-088 protocol](PERFORMANCE-RECOVERY-POST-088.md).
Quality risk: instrumentation can change dispatch or include setup work; no production arithmetic changes are authorized.
Instrumentation: OPT-071 event conservation, host wall, graph/eager dispatch, per-family bytes/counters and matched pinned-llama timings.

## Outcome

Measure matched post-Q4 decode sinks and secondary P4096 attribution, with
an auditable ranking and explicit triggers for conditional GDN/graph tasks.
No optimization keep or throughput improvement is claimed.

## Implementation

1. Create `pins/opt090_decode_attribution_contract.json`, the iteration contract,
   `tools/opt090_decode_attribution.py`, `tests/test_opt090_decode_attribution.py`,
   `fixtures/opt090_decode_attribution.json` and
   `evidence/optimization/opt090-decode-attribution/REPORT.md`. Add
   `cuda-opt090-diagnostics` reusing
   `build/qw38-cuda-opt060-engine-attribution-test`,
   `build/qw38-cuda-component-replay` and
   `build/qw38-cuda-optimization-engine-probe`. Reuse
   `tools/opt071_attribution_repair.py`, `cuda/full_scheduler.cu` diagnostic
   ranges, `tools/llama_authority/engine_attribution.cpp` and its pinned patch.
2. Freeze two Quartz diagnostic idents: `opt088_control` and
   `opt089_selected`; if selector/source arithmetic is identical, measure once
   and reference the same record. Pinned llama is a separate matched control.
   Authenticate full revision/model/token/flags/graph identities. Do not read
   current `../llama.cpp` HEAD as the pinned engine. Instrumentation changes
   belong to diagnostics and must not change the production path.
3. Named phases `d128`, `d2048`: one 32-token measured window after a 128 or
   2048 prefix, one warmup window then three independently restored windows
   per engine/config, no Cartesian prefix sweep in one feedback command.
   Match `(42 + index*997) % 248320`, full logits and committed-state work.
   Measure graph-on uninstrumented ITL/p95 separately from eager event traces;
   take three matched uninstrumented windows per ident, with fixed AB/BA order.
   P4096 is one warmup plus three complete cold prompts per engine/config in
   its own phase, after decode attribution. Prefix/load/capture/warmup/reset
   stay outside measured windows, with their durations reported separately.
4. Attribute FFN gate/up/GLU/down, activation quantization, Q8 input projections,
   Q8 GDN output, Q6 attention output, GDN recurrence/conv/gate, attention
   preparation/core/merge, final Q6 logits, pointwise, state copies/commit and
   unhidden idle. Per token expect 64 FFNs (64 paired calls, not 128), 48 GDN
   and 16 attention groups, 48 Q8 GDN outputs and 16 Q6 attention outputs.
   Resolve tensor names/shapes from the model manifest, not byte offsets.
5. Apply OPT-071 one-epoch event union and parent/leaf exclusion. Reject dropped
   events, wrong call counts or >5% unexplained raw wall. Report GPU work sum,
   union, unhidden host time and instrumented-versus-uninstrumented overhead;
   never stretch wall to match a sum. Do not subtract replay milliseconds from
   full-engine milliseconds. Audit OPT-077/078 replay units, repetitions,
   restoration and copies; their component sums exceed a token's elapsed time.
6. Targeted counter phase: one steady-state launch each for selected Q4 paired
   gate/up and down, Q8 GDN qkv, sequential GDN and D2048 attention. Query
   available Nsight metric names, then collect DRAM bytes/bandwidth, L2 hit rate,
   instruction mix, occupancy, registers/local bytes and stall samples; no
   `--set full`. If counters are unavailable, record that fact and use event
   evidence; no invented bandwidth diagnosis. Build a weight-byte roofline
   from actual tensor formats, excluding unrelated file content.
7. Emit `gdn_reopen_eligible=true` only when a specific timing/capture defect in
   OPT-077 is demonstrated and repaired with before/after count/identity evidence;
   record the exact repair. A newer GPU sitting or broad CI alone is insufficient.
   Emit `graph_reopen_eligible=true` only if uninstrumented timeline evidence
   finds ≥0.50 ms/token removable unhidden launch/idle overhead at both prefixes.
   Report measured family gaps and non-additive ceilings with confidence; no
   forced explanation when attribution is invalid. Pin all raw sources.

## Acceptance

- Call counts and conservation pass; unexplained wall ≤5%; eager timing is
  labeled diagnostic and separate from shipping graph timing.
- D128/D2048 include observed p95; P4096 attribution follows decode. Reports
  identify matched versus unmatched costs and the mechanism supporting each rank.
- Counter absence is explicit; missing valid attribution cannot enable a
  conditional optimization. No production selector changes.
- `claims_throughput: false`.

```sh
uv run pytest -q tests/test_opt071_attribution_repair.py tests/test_opt090_decode_attribution.py
uv run python tools/run_optimization_task.py --task OPT-090 --mode feedback --phase conservation
uv run python tools/run_optimization_task.py --task OPT-090 --mode feedback --phase d128
uv run python tools/run_optimization_task.py --task OPT-090 --mode feedback --phase d2048
uv run python tools/run_optimization_task.py --task OPT-090 --mode feedback --phase counters
uv run python tools/run_optimization_task.py --task OPT-090 --mode feedback --phase p4096
uv run python tools/run_optimization_task.py --task OPT-090 --mode acceptance --phase report
```

Each feedback phase includes compilation/children within 300 s. Conservation
is model-free OPT-071 negative/positive coverage; `report` is a host-only
validation of collected evidence. It cannot convert three diagnostic samples
into performance admission. Stop attribution on invalid counts/identity.
