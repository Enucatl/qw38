# OPT-126 — Make decode graph inputs stable across token commits

Status: pending. Dependencies: OPT-125. Coupled IDs: none.
Priority: P1.

## Outcome

Provide the smallest correct prerequisite for replay without per-token
recapture. OPT-117 repaired capture but lost because frontier and GDN pointer
changes rebuild all eight graphs. This is a new causal design, not another
segmentation sweep. Read OPT-125's shared protocol and OPT-117's rejection.

## Implementation

1. Inventory every changing input captured by
   `cuda/full_scheduler.cu::capture_decode_segment_graph` and
   `SchedulerGraphs::update_launch_params`: frontier/RoPE position, visible
   KV length, split count/crossover, GDN committed/candidate pointers, token,
   session identity and grouped-Q8 descriptor lifetime. Name every consumer
   and whether it takes a value, pointer or changes topology.
2. Implement a session-owned device launch-state record for dynamic values
   where the actual consumer can read it without changing arithmetic. Keep
   pointer ownership and lifetime explicit. Update it in stream order once
   per token; prohibit captured pointers to temporary host storage. Do not
   patch opaque captured argument bytes (OPT-117 did not establish safety).
3. Resolve GDN parity using stable physical ping-pong storage with an explicit
   committed slot, or two bounded parity graph variants. Select one design
   from the inventory before implementation; allow a second only on evidenced
   infeasibility. Do not copy the entire recurrent state every token to retain
   addresses. Preserve candidate isolation and commit only on success.
4. Separate true topology boundaries from ordinary frontier updates. Include
   the actual attention dispatch transition(s) and session replacement.
   Keep topology-dependent graph variants bounded; no graph per position.
   Account for parameter upload and extra device indirection in component cost.
5. Keep the shipping graph selector unchanged in this foundation task.
   Exercise dynamic-input consumers through eager and diagnostic graph paths,
   without switching kernels to historical graph-compatible alternatives.

## Verification and acceptance

Prove identical same-path logits/state over consecutive odd/even commits,
positions 0/127/1023/1024/2047 and near capacity; test every actual split
transition, cancel before commit, retry, failure, divergent prefix,
checkpoint restore and session destruction/replacement. State hashes and
frontiers must distinguish candidate and committed buffers. Check that a
restored/new session cannot replay stale descriptors. Validate both existing
`ffn_only` and experimental segment paths.

Deliver the argument/ownership inventory and
`evidence/optimization/opt126-stable-graph-inputs/REPORT.md`, with measured
upload/indirection/memory costs. Completion is a verified prerequisite, not
a production speed keep; OPT-127 owns full replay admission. If infeasible,
retain production and document the exact consumer or semantics blocker.
