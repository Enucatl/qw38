# OPT-122 — Evaluate lower-precision persistent GDN state

Status: pending. Dependencies: OPT-115, OPT-116, OPT-118. Coupled IDs: none.
Priority: P2. Conditional on a material state-traffic opportunity.

## Outcome and evidence

Test whether smaller persistent recurrent state reduces complete-request time
without accumulating unacceptable text-quality errors. This is a numerical
storage experiment, not a rerun of OPT-101/109's rejected FP32 transposition.
Read [OPT-115](OPT-115.md) and [OPT-116](OPT-116.md). Use the admitted graph/
residency parent, otherwise its retained control.

[gdn_step.cu](../cuda/gdn_step.cu), [full_scheduler.cu](../cuda/full_scheduler.cu)
and [checkpoint.cu](../cuda/checkpoint.cu) own recurrence, candidate/committed
buffers, prompt carry and persistence. The current 158859264-byte session GDN
state/rings are not GBs per token by capacity alone, and decode already swaps
candidate/committed pointers. [OPT-109](OPT-109.md)'s recurrence-only win lost
at complete GDN scope. Measure the actual reads/writes before implementation.

## Implementation

1. Bound net latency savings from state traffic on the complete pipeline after
   OPT-118. Include read/write amplification, candidate buffers and prompt
   carries. If a defensible upper bound is below A/A resolution, deliver
   `no_material_opportunity` with the calculation; do not claim no opportunity
   merely because a counter or category is missing.
2. Admit at most two storage candidates: BF16 recurrent matrices with FP32
   update/accumulation; and one block-scaled 8-bit representation only if
   calibrated error and net byte savings justify the more aggressive stage.
   Keep convolution rings, gates/decay, reductions and update arithmetic at
   their baseline precision initially. Avoid an unrelated transposed-layout
   sweep or global fast math.
3. Load packed state directly into the recurrence and write the next packed
   candidate once. Do not expand every full state matrix into a persistent
   FP32 shadow. Version scale/rounding rules and make prompt scans, carry
   boundaries and one-token updates share a documented representation policy.
   Count any chunk-boundary conversion and ensure chunking does not silently
   choose a different precision policy.
4. Test independent update/quantizer correctness, near-unit decay, very small
   updates, outliers, long repeated inputs and finite behavior. Follow OPT-116's
   >=2048 consecutive decode updates, long prefixes through 128K and generated
   text suite. Report drift by layer and elapsed steps, not only a short mean
   NLL. A recurrence-only speedup never admits the candidate.
5. Preserve atomic candidate/committed ownership, cancellation, graph buffer
   generations, divergent-prefix replay and exact same-format checkpoints.
   Save enough packed state and scale metadata for identical restored
   continuation; decoding/requantizing on restore must not introduce an extra
   rounding step. Reject incompatible old checkpoints before mutation or
   provide an explicit separately tested conversion.
6. Measure complete P4096/D128/D2048 and long-context requests plus live 128K
   peak memory. Compare with parent and post113. Explain if reduced traffic is
   offset by scaling, conversion or scheduling; retain FP32 on failed quality,
   negligible benefit or an E2E loss.

## Acceptance and artifacts

Use shared quality/E2E/state/memory gates. Lower storage precision changes a
stated v1 architectural assumption, so any admitted implementation records a
dated, narrowly scoped plan exception authorized by this investigation request;
historical FP32 reference/quality evidence remains intact. Deliver state-format
tests, raw long-recurrence evidence and
`evidence/optimization/opt122-gdn-state-precision/REPORT.md`.
