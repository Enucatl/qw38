# OPT-116 — Freeze generated-text quality admission for precision experiments

Status: pending. Dependencies: OPT-113. Coupled IDs: none.
Priority: P0. Quality foundation; no candidate promotion in this task.

## Outcome

Permit documented arithmetic/representation changes when generated text and
model quality pass a frozen, meaningful regression suite. Different tokens or
floating-point values alone must not reject an otherwise acceptable precision
experiment. Preserve deterministic same-path execution, exact structural
behavior, the historical strict verdict, and visibility of inherited defects.

## Evidence and scope

[OPT-084](../pins/opt084_quality_baseline_contract.json) requires no new greedy
mismatch, PPL ratio <=1.01 and recurrence incremental NLL <=0.02.
[OPT-091](../pins/opt091_quality_tradeoff_contract.json)'s 1.015 exception is
specific to late_w4 and cannot automatically cover new formats. The existing
[quality framework](../tools/quality/) and
[OPT-113 scores](../evidence/optimization/opt113-coupled-stack-gate/) are the
starting point, but short teacher-forced cases alone cannot assess long-cache
or accumulating recurrent-state quantization.

The user explicitly accepts reduced numerical accuracy when generated-text
quality checks pass. Implement a named successor contract for this batch;
report original strict checks alongside it, without relabeling OPT-016/056.
No remote judge, credential use or external transmission is required.

## Implementation

1. Authenticate post113 and pinned llama on the full existing quality suite.
   Freeze a successor contract before any OPT-117–122 candidate results:
   prompt/token/answer-boundary identity, decoding configuration, seeds,
   scoring rules, datasets, split hashes, bounds and missing-evidence behavior.
   Preserve existing anchors and add post113; do not loosen bounds after a
   candidate fails. Record this request as authority for the scoped policy.
2. Keep PPL ratio <=1.01 against both authenticated post113 and the applicable
   frozen OPT-084 anchor on every existing scored span and aggregate;
   recurrence incremental NLL <=0.02; zero non-finites; zero new objectively
   scored functional failures. These budgets do not compound across keeps.
   The successor changes cross-arithmetic token-identity admission, not those
   bounds. Historical strict verdicts and inherited arithmetic failures stay
   visible; a baseline failure is never recorded as a successful task answer.
3. Add at least 32 held-out free-running cases covering extraction/long-context
   recall, instruction constraints, arithmetic/reasoning, code with executable
   checks, tool-call JSON/schema/arguments, and coherent multi-turn prose.
   Include at least four cases per class. Freeze expected outputs or objective
   validators where appropriate; text generation consumes its own sampled
   tokens, never teacher-forced answers. Store complete outputs and termination
   reasons. Use deterministic greedy runs and a frozen three-seed sample set
   on a representative subset of at least 12 cases. Pin current sampler
   settings rather than silently changing temperature/top-p for a candidate.
4. For prose/non-unique answers define a baseline-blinded rubric before scoring:
   instruction compliance, factual consistency with supplied context,
   coherence/completion and repetition. Use a fixed 0–2 scale per dimension;
   require no newly zero-scored dimension and no lower aggregate than post113.
   Keep raw paired answers and per-case reasons for independent review; an
   implementation agent's unsupported `quality=true` is not a grader. Require
   completed review before promotion; do not replace unavailable review with
   an unapproved remote service. Different wording is allowed when the rubric
   and objective checks pass. Same-path seeded repeatability remains exact.
5. Add cache-reading teacher-forced and free-running tests with populated
   prefixes at 8192 and 32768 tokens, and a bounded prefix of 131040 followed
   by 32 scored/generated tokens at capacity 131072. Include dispersed
   retrieval positions, not only the most recent window. NLL must run the
   actual compressed-cache decode path; an uncached all-prefill score cannot
   validate cache quantization. Apply the same 1.01 ratio cap to added spans
   against post113; publish pinned-llama results separately.
6. Stress GDN over repeated prefill chunks and at least 2048 consecutive decode
   updates, alongside the long-prefix probes. Check matched token histories,
   recurrence NLL, finite state, and free-running stability. Exercise chunk
   splits, prompt-to-decode, graph/eager, cancellation, divergent prefix,
   repeated save/restore and seeded sampler continuation using the actual
   candidate representation. Record both numerical drift and output quality.
7. Define correctness for approximate formats in two layers: the kernel must
   implement its declared quantizer/dequantizer/arithmetic against an
   independent reference (scales, clipping, ties, tails, zeros, extreme values);
   the complete changed operation is admitted by model quality. Do not apply
   an old same-math bitwise gate to a deliberately different representation,
   or misclassify corruption as an acceptable approximation. Same-path
   graph/eager and checkpoint restore still require exact equivalence.
8. Separate calibration/development inputs from admission inputs. Candidate
   role/format choices cannot be tuned using held-out answers. Reuse framework
   machinery and extend identity records to include weight/KV/state encodings,
   quantizer parameters and graph path so `--quality` cannot silently revert
   to the old high-precision kernel. Negative tests must reject a wrong-path
   score, missing case, missing long-cache execution and fabricated aggregate.

## Acceptance and artifacts

Deliver a versioned contract, baseline raw generations and scores, focused
validators and `evidence/optimization/opt116-generated-quality/REPORT.md`.
Report `strict_quality_pass`, `successor_quality_pass`,
`absolute_task_quality`, `baseline_regression`, `cache_path_exercised`, and
`state_consistency` separately. Complete baseline evidence and frozen scoring
rules are required before precision candidates can be admitted. An inherited
baseline defect need not block defining the regression suite, but cannot be
hidden. No model/kernel change or performance claim in this task.
