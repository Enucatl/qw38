## Source basis

`cuda/q8_decode_dots.cuh::q8_coop_mmv` launches one CTA per output row and
reduces through shared memory, including when only one warp is used.
`full_scheduler.cu::matrix_vector` already reuses Q8 staging for identical
activation pointers/column counts. Preserve that behavior. ds4's
`ds4_cuda.cu::matmul_q8_0_preq_warp8_kernel` demonstrates eight independent
warp rows per CTA. Pinned llama supports row grouping, but its generic
single-token non-small-K path normally returns one row/block; do not claim it
uses the proposed layout on this workload without OPT-060 evidence.

## Implementation

1. Keep Q8_0 bytes and admitted Q8_1 scale/quant semantics unchanged. Add a
   `RowsPerCta,WarpsPerRow` template to the focused Q8 TU, not the scheduler.
   Candidate tuples are `(1,4)` current control, `(2,2)`, `(4,1)`, `(8,1)`.
   If current selected warps changed, include that exact control and remove
   one alternative to keep four configurations total.
2. Map `row = blockIdx.x*RowsPerCta + warp/WarpsPerRow`; cooperative K index
   uses `warp % WarpsPerRow`. Preserve current `kVdr`/packed-dot mapping and
   FP32 accumulation. For one warp/row reduce with shuffles and write directly,
   with no shared array or block-wide barrier. Multiwarp rows have disjoint
   shared reduction slots. Inactive tail rows contribute zero through barriers.
3. Retain legal2-byte-aligned loads for34-byte Q8_0 blocks. Do not cast every
   payload to an aligned int pointer: block+2 alternates alignment. Inspect
   generated vector loads and DP4A. Do not introduce a persistent SoA copy or
   repeat OPT-024's rejected repack in this task.
4. Benchmark actual mixer shape groups from tensor inventory: GDN qkv10240× 5120,
   value gate6144× 5120, output 5120× 6144; include attention projection sizes and
   skinny48-row alpha/beta as correctness/fallback cases. Select a maximum of
   two production row-group rules (large versus skinny) only if measurements
   justify them; otherwise one winning rule. Existing skinny paths may remain.
5. Integrate selected layout through `launch_q8_coop_mmv_prequant`, leave stage
   reuse and cache invalidation intact, and report actual layout per role.
   In repeated calls overwrite input at the same address and verify the
   scheduler invalidates staging; pointer identity is not data identity.
