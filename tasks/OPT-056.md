## Test execution contract (mandatory)

The test author must define `smoke`, `correctness`, and `acceptance` commands
in this dossier and make the new GPU test require `QW38_CUDA_TEST_TIER`, failing
closed when it is missing. Smoke is limited to compile/small probes, correctness
uses reduced samples without model-scale P/D oracles, and acceptance alone may
record performance evidence; each tier must list its phases, sample counts,
model loads, and skipped work. Reuse cached builds/binaries and emit phase
timestamps so implementation loops cannot launch the expensive default.

## Required outcome

On the same GGUF, pinned CUDA toolchain, exclusive RTX 5090 and same sitting,
the final selected production engine exceeds pinned llama.cpp P/D128/D2048
throughput by **at least 5%**, and both decode p95 measures are no worse than
llama's. Use unchanged OPT-021 and OPT-032 protocols and retain raw samples,
latencies and controls. Require confidence-supported improvement, not a rounded
tok/s headline. The 5% margin makes “faster” meaningful; it is a goal, not a
forecast. Current llama implies approximately 3347 P and 70.45 D2048 tok/s,
but actual same-sitting llama measurements determine thresholds.

Also run the existing frozen 2K OPT-016 parity gate. This task supplies evidence
to that owner and may update its run record/status when the original acceptance
passes; it does not redefine or replace it. Keep longer-context performance
and release gates separate. Do not mark done on partial parity or because the
candidate list is exhausted.
