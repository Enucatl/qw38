# OPT-112 — Fuse decode normalization into typed Q8 staging

Status: pending. Deferred until the component trigger below. Dependencies:
OPT-106, OPT-114. Coupled IDs: none.
Primary target: unmatched decode normalization and activation traffic.

## Outcome

Remove the decode-only FP32 residual/RMSNorm → BF16 materialization → typed Q8
restaging chain when the normalized value exists only to feed quantized
projections. Produce the exact staged encoding required by each selected
same-input projection group at the normalization boundary and reuse it only
among consumers of that encoding. Current Q8/Q6 consumers require Q8_1, while
the selected late-Q4 FFN path requires FP32-scale `Q8Block`; those encodings are
not interchangeable. This is deferred until a fresh component screen shows
enough removable cost to justify its state and arithmetic risk.

## Evidence and rationale

OPT-099 records 26.29 ms of Quartz `ffn_norm` work across the D2048 diagnostic
window with no matched llama family. That unmatched diagnostic total is an
upper-bound clue, not a measured removable budget. OPT-045 parallelized
RMSNorm, OPT-047/049 shared staging inside mixer/FFN groups, and OPT-092
grouped same-input Q8 projections, but no task fused the normalization producer
with the selected typed Q8 consumers or removed the intervening BF16 round
trip. This is a data-lifetime change, not a new row/warp layout.

## Implementation

1. Inventory every decode normalized activation consumer by layer kind. Mark
   whether BF16 normalized values are externally observed or reused by a
   non-quantized operation; retain the existing path for those cases.
2. Implement exactly two bounded producer-fusion candidates only if the screen
   justifies it: `norm_to_typed_q8_rounded`, which performs the existing BF16
   conversion and re-expansion in registers before quantization, and
   `residual_norm_to_typed_q8_rounded`, which also folds the preceding residual
   add when legal. Instantiate only the encoding required by an inventoried
   production consumer: exact half-scale/sum `Q8_1Block` semantics for selected
   Q8/Q6 paths, or exact FP32-scale `Q8Block` semantics for selected late-Q4
   paths. Do not silently replace BF16→FP32→Q8 with direct FP32→Q8 conversion;
   that changes arithmetic and requires a separate quality-approved task.
3. Reuse one staged activation only within a group whose consumers have both
   identical logical input and identical staged encoding. Reuse Q8_1 among
   eligible Q/K/V or QKV/gate/alpha/beta groups and Q8Block among eligible
   gate/up Q4 groups. If one logical input needs both encodings, generate and
   account for both independently; never reinterpret or cross-reuse their
   storage. Invalidate each typed value on every residual, pointer, token,
   layer, normalization-scale, or representation change.
4. Do not force one CTA to serially quantize all 5120 elements. Use a bounded
   reduction/quantization design and count every partial/finalize launch. No
   device-wide cooperative launch or new persistent allocation without an
   explicit 128K ledger entry.
5. Keep current residual/norm/BF16 and standalone Q8 staging callable as the
   control. Record bytes avoided, launch count, graph nodes, registers, spills,
   and selected consumer identities.

## Verification and evidence

- Add contracts, fixture, native typed-staging/lifetime test, complete 64-layer
  decode replay, host validator, runner entry, and
  `evidence/optimization/opt112-norm-q8-staging/REPORT.md`.
- Prove exact Q8_1 and Q8Block field semantics independently, typed staging
  invalidation, mixed layer kinds, graph/eager equivalence, reset/replay,
  checkpoint/restore, cancellation, and no stale or cross-encoding reuse.
  Compare reconstructed normalized values and final projection outputs to the
  current path plus independent CPU/dequant samples.
- Run full-model candidate NLL/quality and 128K memory validation.
- Screen both candidates once only after the fresh component trigger; run 3+10
  complete decode rounds only for the survivor, followed by five uninstrumented
  D128/D2048 pairs and one P4096 guard.

## Acceptance and stop rule

- Require at least 0.25 ms/token saving over the complete 64-layer decode body
  with a positive paired 95% interval, improved D128 and D2048 point throughput,
  and existing p95, quality, state, graph, and memory gates. If the fresh
  component screen cannot show at least 0.50 ms/token of potentially removable
  norm/staging cost, mark this task deferred without implementing either
  candidate.
- Do not keep a reduction/quantization microbenchmark win if the complete body
  loses. If both bounded candidates fail, retain the current materialization and
  do not add a third fusion variant.

## Non-goals

No new weight layout, changed GGUF, Q8 semantic reinterpretation, global
precision/fast-math change, cross-token activation cache, or broad pointwise
fusion framework.
