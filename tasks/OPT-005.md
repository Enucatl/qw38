## Goal and boundaries

Replace the prompt-attention loop that launches normalization, QK/softmax, and
value work separately for every prompt token with a fixed-memory tiled CUDA path.
One chunk-wide staging launch prepares every candidate K/V row, and one
chunk-wide attention launch maps every `(query row, query head)` to a block,
streams only that row's legal causal context through shared-memory KV tiles, and
updates its stable softmax and value accumulator online. The production prompt
scheduler obtains the new path through its existing
`launch_attention_prepare_chunk` call.

- Constraints: preserve the C++17/CUDA 13.0.2 `sm_120` target; token-major
  projected Q/K/V/gate input; 24 query heads, four KV heads, width 256, partial
  first-64-lane RoPE, BF16 K/V storage, FP32 normalization/score/softmax/value
  accumulation, exact causal visibility across committed and candidate rows,
  whole-chunk prepare/commit isolation, invalid-input rejection, and the existing
  frozen ATN-001/ORA-004 numerical limits. Use a compile-time 32-context KV tile
  and 256 threads per block; use no prompt-sized global score matrix. Retain the
  pre-optimization implementation as an explicit test-only reference entry point.
  Adapt no external implementation; therefore no new provenance license entry is
  required. Keep exclusive RTX 5090 work serialized.
- Non-goals: sharing one KV tile among the six query heads in a GQA group
  (`OPT-006`); processing multiple query rows in one CUDA block (`OPT-007`);
  changing the 64-row scheduler chunk (`OPT-008`); changing KV physical layout
  (`OPT-010`); fusing projections/output/commit, adding prompt graphs, sparse or
  compressed attention, changing decode graph ownership, or claiming the final
  2K/8K/32K end-to-end recovery or comparative speed gate.
- Plan impact: `none`
- Affected interfaces: add a CUDA-internal
  `launch_attention_prepare_chunk_reference` test boundary; retain the signatures
  and validation behavior of the production single-row/chunk attention and commit
  APIs. No public engine, CLI, server, checkpoint, fixture-format, or model-format
  interface changes.

## Implementation decisions

Modify `launch_attention_prepare_chunk` for every positive token count, including
one, so chunked prompt execution and repeated `launch_attention_prepare` calls use
the same arithmetic and the existing SCH-002 exact token-wise differential remains
meaningful. Launch a two-dimensional `(kv_head, token)` 256-thread staging grid
that performs key RMSNorm/RoPE and converts all candidate K/V rows to BF16. Then
launch a `(query_head, token)` 256-thread attention grid. Each attention block owns
exactly one query row/head, computes that query's RMSNorm/RoPE, traverses contexts
in increasing 32-row tiles, selects committed rows below `start_position` and
candidate rows at or above it, masks everything beyond its absolute query
position, and accumulates stable online-softmax state `(running_max, running_sum,
weighted_value[lane])` in FP32. Rescale the old denominator and value accumulator
whenever the running maximum increases, divide once after the final legal tile,
apply the existing stable sigmoid gate, and write token-major FP32 output.

The 32-row tile stages one KV head's BF16 keys and values plus FP32 scores in
shared memory. Each block still reloads that tile independently for each query
head, and each block owns only one query row: those are explicit OPT-006 and
OPT-007 seams. The multi-row property in OPT-005 is grid-wide execution of all
chunk rows, not multiple row ownership within one block.

Keep the former normalization plus score-materialization implementation callable
only through `launch_attention_prepare_chunk_reference`. It accepts the same
buffers, runs the original `3 * token_count` launch sequence, and is never called
by the scheduler. Keep legacy normalization/score helpers solely for this
differential. Production input validation continues to require the existing
non-null workspace arguments for ABI/caller compatibility, but the tiled path
does not read or write the global score buffer for multi-token work. For a
single-token call, write the supplied normalized Q/K buffers so ATN-001's
diagnostic boundary remains observable; concurrent multi-row calls do not expose
per-row normalization through those one-row buffers.

Add a dedicated native OPT-005 diagnostic rather than relabeling historical
ATN-001/002 evidence. It will compare tiled and retained-reference outputs under
the BF16-aware `0.00005` maximum absolute/`0.000005` RMS limits and the frozen
ORA-004 `0.051` maximum absolute, `0.0016` RMS, and `0.999424` cosine limits;
require exact BF16 candidate K/V, exact chunk-versus-repeated-tiled output/cache,
future-row sentinel exclusion, finite outputs, prepare isolation, commit/frontier
equality, and overflow rejection; poison and verify the global score buffer is
unchanged; and capture each launcher into a CUDA graph to prove two tiled kernel
nodes versus `3 * token_count` reference nodes.

Freeze the component scaling gate at the production `24/4/256/64` shape with 64
query rows and committed-prefix lengths 2,048, 8,192, and 32,768. On the pinned
RTX 5090, use three warmups and 30 synchronized tiled samples plus one warmup and
three reference samples at each prefix. Every tiled mean must be positive and
strictly lower than the corresponding retained-reference mean; record raw means,
speedups, node counts, device/toolkit identity, all numerical metrics, and proof
limits in the OPT-005 fixture. This is a component gate only and does not replace
the later end-to-end recovery matrix.
