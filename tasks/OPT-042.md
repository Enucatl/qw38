### Candidate integer-dot association (frozen)

Keep Quartz `Q8Block` staging. Each Q4_K 256-value block has eight 32-value subgroups; each subgroup maps to one `Q8Block`.

For subgroup `s = 0..7` in **ascending** order:

1. Pack the 32 Q4 nibbles and 32 Q8 bytes.
2. Integer dot `dot_s = Σ quant[i]*q8[i]` via `__dp4a`.
3. Integer sum `sum_q8_s = Σ q8[i]` via `__dp4a(0x01010101, q8_packed)`.
4. FP32 apply, matching llama.cpp's scale/min split against Quartz's FP32 Q8 scale:

   `c_s = q8.scale * (d * float(scale_s * dot_s) - dmin * float(min_s * sum_q8_s))`

   Use `__fmul_rn` / `__fadd_rn` / `__fsub_rn`. Do not rewrite as three-float `d * scale * quant`.

5. Fold `acc = c_0 + c_1 + … + c_7` with `__fadd_rn` left to right, then the next 256-block in ascending index.
6. Five-step `__shfl_down_sync` warp tree (`offset = 16,8,4,2,1`); lane 0 writes `output[row]`.

Thread mapping (locked): one warp per row; `blockDim = Warps * 32`; `grid.x = ceil(rows / Warps)`; `Warps = selected_mmv_warps(rows)`. Inside a 256-block, lane `lid` owns subgroup `s = lid / 4` and 4-pack `pack = lid % 4` (elements `s*32 + pack*4 .. +3`). The four lanes of each subgroup warp-sum their integer dots/sums (exact), then lane 0 folds the eight FP32 `c_s` in ascending `s`. Occupancy of this kernel must be ≥ 1.

Host integer reference implements the same association in scalar C++ (int32 dots/sums, then FP32 apply and ascending fold). Candidate versus that host must be **byte-equal**. That is an association check, not the CUD-001 envelope.
