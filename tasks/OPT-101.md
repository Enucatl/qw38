# OPT-101 — Transpose and register-shard decode GDN state

Status: pending. Dependencies: OPT-099. Primary target: D128/D2048 GDN core.
Read [the post-098 protocol](PERFORMANCE-RECOVERY-POST-098.md).

## Outcome

Replace the selected one-token row-major GDN recurrence with a transposed,
warp-column kernel that keeps each lane's state shard in registers. Keep it
only on complete 48-layer GDN and two-prefix end-to-end wins with full recurrent
quality and transactional-state correctness.

## Rationale

The selected Quartz kernel launches one 128-thread CTA per value head. Each
thread serially walks 128 key rows, reads state once for prediction and again
for update, then writes 128 values. Lane 0 also serially computes q/k norms,
repeated for three value heads sharing each key head. Pinned llama.cpp
`gated_delta_net_cuda<128>` uses transposed state, four warps per CTA, one warp
per output column and four register-resident state values per lane. OPT-077's
tile16/tile32 candidates retained row-major state and shared-memory reductions;
this is a new layout and ownership mechanism, not a rerun.

## Implementation

1. Define a transposed production GDN-state layout with the same element count.
   Preserve the canonical checkpoint payload by transposing only at save/restore
   boundaries, or version the payload with backward-compatible restore. The
   allocation ledger and hashes must identify logical versus device order.
2. Hoist q/k normalization to one computation per 16 key heads. Compare a
   fused-in-recurrence form only if it does not repeat work per reused value
   head. Convolution and gate preparation stay visible reference stages.
3. Implement the exact production specialization: key/value width 128, 48
   value heads, four warps per CTA, `grid=(48,32)`, each warp owning one output
   column and each lane owning four key rows. Load state once into registers,
   perform prediction and output reductions with warp shuffles, update the
   register shard, and write state once. Retain the current sequential kernel.
4. Preserve FP32 recurrence, q/k RMS conventions, decay/beta semantics, value
   head permutation and BF16 output boundary. Validate independent FP64 taps,
   long recurrence, chunk/decode equivalence and nonfinite behavior.
5. Prove candidate-versus-committed isolation, cancellation before and after
   recurrence, divergent-prefix restore, graph replay, checkpoint round trip and
   exact frontier ownership. In-place state is allowed only inside an already
   isolated candidate slot.
6. Apply the shared 3+10 complete-GDN and five-pair D128/D2048 protocol. Use
   OPT-099 matched excess as the expectation; do not add OPT-077 replay values
   to wall time.

## Acceptance

- Layout round trips are exact and checkpoint compatibility is explicit.
- Kernel parity, full quality and recurrent NLL pass with zero nonfinites.
- Complete 48-layer GDN saves at least 0.10 ms/token with positive paired CI;
  D128 and D2048 both improve and P4096 does not regress beyond the shared gate.
- State/checkpoint/cancellation and 128K memory gates pass. Rejection restores
  `sequential` without altering historical OPT-077/094 evidence.
- Add contract/fixture, diagnostic, runner and
  `evidence/optimization/opt101-gdn-transposed-state/`.

## Non-goals

No reduced-precision state, recurrence approximation, changed convolution,
tile32 reopening, speculative rollback policy or extra persistent state copy.
