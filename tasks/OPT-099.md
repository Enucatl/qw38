# OPT-099 — Close matched engine attribution blind spots

Status: pending. Dependencies: OPT-098. Primary target: D2048 diagnostics.
Read [the post-098 protocol](PERFORMANCE-RECOVERY-POST-098.md).

## Outcome

Produce one current, matched Quartz-versus-pinned-llama attribution for D128,
D2048 and P4096 that can explain at least 95% of each measured GPU window and
assign nonzero llama time to every family the authority actually executes. This
task changes diagnostic tooling only and makes no throughput claim.

## Implementation

1. Freeze `post098_selected` from actual compiled selectors: Q4
   `integer_q8_late`/four warps, FFN `paired_integer`, Q8
   `grouped_r1_w4`, Q6 `integer_q8_1`/two warps, GDN `sequential`, attention
   `warp_query`, prompt MMQ `i128_j128_fma_async_x` with joined waits, and
   `ffn_only` graphs. Fail if requested and observed selectors differ.
2. Repair the pinned-llama diagnostic patch so CUDA operator/kernel ranges map
   to the same semantic families as Quartz. At minimum distinguish FFN
   gate/up/GLU from FFN down, Q8 input projections from mixer outputs, GDN
   convolution/norm/recurrence/gate, attention query prep/core/merge, Q6
   attention output, final Q6 logits, pointwise/state work, copies and unhidden
   idle. Record actual llama dispatch identities; never fill missing values with
   zero and call the comparison complete.
3. Run 3 warmup plus 3 measured 32-token windows after fixed D128 and D2048
   prefixes for each engine. Run 3 warmup plus 3 P4096 samples in a separate
   process/sitting. Uninstrumented wall/ITL/p95 and eager CUDA-event traces are
   separate records; prefix/load/graph construction/restoration stay outside
   measured windows.
4. Use event unions and explicit parent/leaf exclusion. Validate per-token call
   counts from graph/operator structure, not hard-coded tensor offsets. Report
   family sum, union, overlap, wall, idle and instrumentation overhead. Families
   remain non-additive.
5. Collect one targeted Nsight Compute record for the hottest Quartz and llama
   kernel in Q4 gate/up, FFN down, Q8 input, GDN and attention when the metrics
   are available. Record DRAM bytes/rate, L2 hit rate, issue/active cycles,
   registers, spills, occupancy and dominant warp stalls. Explicitly record
   unavailable metrics; event timing is not a substitute for counters.
6. Publish matched excess and an upper bound on removable Quartz time per
   family. Emit go/no-go trigger fields consumed by OPT-100 through OPT-105.

## Acceptance

- D128, D2048 and P4096 each have valid call counts, no dropped events, at most
  5% unexplained wall and measured instrumentation overhead.
- Pinned llama coverage is nonzero for executed families; unsupported mappings
  are `unknown` and make `gap_attribution_complete=false`.
- FFN down is a first-class family rather than `unmapped_mul_mat`.
- Raw timelines and machine-readable samples reproduce the ranking. No replay
  time is added to engine time and no speedup/keep is claimed.
- Add the task contract/fixture, runner, native diagnostic, host tests and
  `evidence/optimization/opt099-matched-attribution/`.

## Non-goals

No production selector, kernel, quality policy, historical fixture or outcome
gate changes. Do not benchmark current `../llama.cpp` HEAD as the authority.
