# OPT-011 — Pipeline and fuse prompt execution and chunk commit

## Control

- Primary ID: `OPT-011`
- Coupled IDs: `none`
- Dependencies: `OPT-008`, `OPT-009`, `OPT-010`; all done at planning admission
- Status: `done`
- Ledger acceptance: Justified fusion/overlap removes avoidable copies, launches, and barriers while preserving cancellation and atomic publication

## Goal and boundaries

Remove avoidable prompt-chunk orchestration cost that remains after OPT-008
(4,096-row transactions), OPT-009 (weight-reusing MMQ), and OPT-010 (physical
KV scatter). Production `execute_prompt_chunk` must (1) decode all embedding
rows in one kernel that preserves the existing BF16 round-trip, (2) fuse
mixer-residual-plus-FFN-norm and FFN-residual-plus-next-input-norm the way
OPT-002 already fuses decode, (3) scatter all 16 attention layers in one
multi-block kernel, and (4) overlap that scatter with asynchronous last-row
logits/hidden D2H so publication waits on one join rather than a blocking D2H
followed by sixteen copy launches and a second device barrier. Keep whole-chunk
atomic publication, layer-boundary cancellation, and byte-exact equality with
the retained unfused serial prompt path.

- Constraints: keep C++17, CUDA 13.0.2, `sm_120`, `--fmad=false`, 256 threads,
  BF16 activation/KV storage, FP32 residual and GDN recurrence, the production
  `24 / 4 = 6` GQA mapping, OPT-010 physical committed KV, OPT-009 MMQ
  dispatch, OPT-008 `kPromptChunkRows = 4096` and
  `prompt_chunk_rows_ = min(4096, capacity)`, SES-002 candidate-versus-committed
  isolation, and all frozen SCH-002/OPT-008/OPT-009/OPT-010 numeric and
  exact-state gates. Do not add a persistent session, workspace, or prompt-sized
  `cudaMalloc`. Do not edit `Makefile`; build the new diagnostic with an
  explicit pinned `nvcc` command. Exclusive RTX 5090 work stays serialized.
  Nsight Systems remains absent from the pinned image, so justification is
  executed launch/barrier counts plus paired CUDA-event A/B, not a Systems
  timeline.
- Non-goals: prompt CUDA graphs (`OPT-012`); associative/block-parallel GDN
  scan (`OPT-013`); changing MMQ tiles or Q8_0-by-BF16 arithmetic (`OPT-009`);
  changing committed KV layout (`OPT-010`); changing the 4,096-row outer chunk
  or 64-row internal GDN scan (`OPT-008`/`GDN-002`); overlapping independent
  MMQ launches on extra streams; committing KV or swapping GDN pointers before
  the chunk succeeds; dropping per-layer poll synchronization; loosening frozen
  envelopes; claiming end-to-end prefill/decode speedup, comparative 5% gates,
  or 128K quality recovery; editing `plan.md` or `QLT-001`.
- Plan impact: `none`
- Affected interfaces: no public Engine, CLI, server, model, or JSON API
  changes. CUDA-internal `execute_prompt_chunk` gains an optional retained
  unfused path, optional launch/barrier counters, workspace-owned prompt
  compute/copy streams and one compute-done event, one batched embedding
  launcher, one row-wise residual-add-norm kernel, and one all-layer KV scatter
  launcher. Decode `execute_token` may call the all-layer scatter launcher but
  keeps blocking D2H and `cudaDeviceSynchronize` publication. New schema-1
  contract and fixture files are task evidence, not a public protocol.
- Implementation classification: not mechanical. This changes CUDA stream
  ownership, kernel fusion, launch geometry, commit overlap, cancellation
  synchronization, and exact BF16/FP32 publication invariants. Use the
  CUDA/numeric implementation agent, not a mechanical path.
- Documentation stage: required. Update the existing full-prefill, profiler-led
  fusion, and atomic-eval handbook chapters plus `docs/sources.md` and one
  non-final then final OPT-011 audit row. Do not add an EDU task; EDU-038 and
  EDU-047 already cover fusion and prefill chapters.

## Implementation decisions

Keep decode `execute_token` pointwise fusion, MMQ kernels, GDN scan windows,
attention prepare kernels, `kPromptChunkRows`, workspace byte formula, and
checkpoint pack/unpack unchanged. Change only prompt orchestration plus the
shared scatter kernel's grid and an all-layer launcher that decode may also
call.

Add CUDA-internal types in `cuda/full_scheduler.h` next to `PointwisePath`:

```text
enum class PromptPipelinePath : std::uint8_t {
  kFusedOverlapped = 0,
  kUnfusedSerial = 1,
};

struct PromptPipelineCounters final {
  std::uint32_t embedding_kernel_launches = 0;
  std::uint32_t widen_kernel_launches = 0;
  std::uint32_t residual_add_kernel_launches = 0;
  std::uint32_t rms_norm_kernel_launches = 0;
  std::uint32_t fused_residual_norm_kernel_launches = 0;
  std::uint32_t scatter_kernel_launches = 0;
  std::uint32_t blocking_d2h_copies = 0;
  std::uint32_t async_d2h_copies = 0;
  std::uint32_t device_synchronizes = 0;
  std::uint32_t stream_synchronizes = 0;
  std::uint32_t layer_polls = 0;
};
```

Extend `execute_prompt_chunk` with two optional trailing arguments defaulting
to fused production:

```text
PromptPipelinePath path = PromptPipelinePath::kFusedOverlapped,
PromptPipelineCounters* counters = nullptr
```

`sync_tokens` keeps calling the fused default. Update the three friend
declarations to the new signature. Increment counters only when `counters !=
nullptr`; production `sync_tokens` passes null.

### Workspace streams (no extra cudaMalloc)

On `SchedulerWorkspace::create`, after successful buffer allocation, create:

- `prompt_compute_stream_` with `cudaStreamNonBlocking`
- `prompt_copy_stream_` with `cudaStreamNonBlocking`
- `prompt_compute_done_` with `cudaEventDisableTiming`

Destroy them in `release` and transfer them in move operations with the other
ownership fields. Reset them to null/zero in the moved-from workspace. They are
driver handles, not `cudaMalloc` bytes, so `allocated_bytes_` and the OPT-008
formula `160,380,416 + 96*C + 404,992*R` stay unchanged. Do not add a token-ID
device buffer.

### Batched embedding (launch fusion)

Add `launch_quant_rows_decode_widen` in `cuda/quant_mmv.h` / `cuda/quant_mmv.cu`.
Keep `launch_quant_row_decode` for decode and the unfused prompt path.

Fused embedding:

1. `cudaMemcpyAsync` the host token IDs into
   `reinterpret_cast<std::size_t*>(workspace->prompt_q8_)` on the compute
   stream. `cudaMalloc` alignment is enough for `std::size_t`. The overlay is
   live only until the first Q4_K/Q6_K `launch_quant_mmq` of the chunk (layer-0
   FFN). Q8_0 MMQ does not use `prompt_q8_`.
2. Launch one kernel with grid
   `[(columns + 255) / 256, token_count, 1]`, block `[256, 1, 1]`. Thread
   `(column, row)` decodes token `token_ids[row]` with the existing
   `decode_weight<Kind>` path, applies `__float2bfloat16_rn`, then stores
   `__bfloat162float` of that BF16 into
   `prompt_residual_a_[row * columns + column]`. That is the current
   decode-then-widen round-trip without a global BF16 embedding store.
3. Do not write `prompt_normalized_` during embedding; layer 0's input RMSNorm
   overwrites it.

Reject null pointers, zero `token_count`, `token_count` above `rows` (vocab),
non-multiples of 256 columns, and illegal kinds with `cudaErrorInvalidValue`.
Production embedding is Q6_K; the launcher still switches on `kind` like
`launch_quant_row_decode`.

Unfused path keeps the per-token `launch_quant_row_decode` loop plus
`bf16_to_fp32`.

### Prompt residual-add-norm fusion

Add `__global__ void residual_add_norm_rows_fp32_to_bf16` in
`cuda/full_scheduler.cu` beside the existing one-row fused kernel. Grid is
`token_count` blocks of 256 threads. Each block:

1. parallel `__fadd_rn` of residual and correction into the output row (same
   ownership as `residual_add_fp32`);
2. `__syncthreads`;
3. thread 0 runs the same ordered FP32 sum-of-squares plus
   `1 / sqrtf(sum / width + 1e-6f)` as `rms_norm_rows_fp32_to_bf16`;
4. `__syncthreads`;
5. parallel scaled BF16 stores into `normalized`.

Fused layer schedule (mirrors decode OPT-002):

- Layer 0: standalone `rms_norm_rows_fp32_to_bf16` of `residual` with
  `input_norm`.
- After mixer: fused mixer residual add into `after_mixer` plus FFN-norm into
  `prompt_normalized_` (64 fused launches per full stack).
- After FFN of layers 0–62: fused FFN residual add into `residual` plus next
  layer `input_norm` into `prompt_normalized_` (63 fused launches). Layers 1–63
  skip the standalone input RMSNorm.
- After FFN of layer 63: standalone `residual_add_fp32` into `residual` (no
  next decoder layer). Then last-row `rms_norm_fp32_to_bf16` and
  `matrix_vector` logits, unchanged.

Unfused path keeps today's three pointwise launches per layer (input RMSNorm,
mixer residual, FFN RMSNorm, FFN residual) so 64 input norms + 64 mixer adds +
64 FFN norms + 64 FFN adds remain the reference.

Do not fuse SwiGLU, GDN gate prep, attention split, or `launch_fp32_to_bf16`
after attention; those sit on MMQ/attention outputs and would change OPT-009/
OPT-007 kernels.

### All-layer multi-block scatter (launch fusion + copy occupancy)

Rewrite `scatter_committed_rows` to a grid-stride loop
`index = blockIdx.x * blockDim.x + threadIdx.x` with
`stride = blockDim.x * gridDim.x`. Launch
`min(2048, ceil(values / 256))` blocks, never a single block for large chunks.
Keep the physical-index scatter math. When `committed_frontier != nullptr`,
only `blockIdx.x == 0 && threadIdx.x == 0` writes it after a device-wide
assumption that the kernel completed; prefer keeping frontier publication on
the host for scheduler commits (existing `launch_attention_scatter_chunk`
already passes `nullptr`).

Add `launch_attention_scatter_layers` in `cuda/attention_decode.h` /
`cuda/attention_decode.cu`:

```text
candidate_key_base + layer * candidate_layer_stride
committed_key_base + layer * committed_layer_stride
```

Grid is `dim3(blocks, layer_count)` with `layer_count == 16`. Prompt strides
are `prompt_chunk_rows_ * kAttentionKvWidth` (candidate) and
`capacity * kAttentionKvWidth` (committed). Reject `layer_count == 0`, null
bases, aliasing candidate/committed, or overflow of `start + token_count`
versus capacity.

Production prompt commit calls this once. Decode `execute_token` commit also
calls it once with `token_count == 1` and decode candidate stride
`kAttentionKvWidth`; decode still uses blocking D2H and
`cudaDeviceSynchronize` (no stream overlap on the one-token path). Keep
`launch_attention_scatter_chunk` as a one-layer wrapper so OPT-010 diagnostics
stay valid.

### Commit overlap (barrier fusion)

Fused commit, only after all 64 layers and logits MMV enqueue on the compute
stream:

1. `cudaEventRecord(prompt_compute_done_, prompt_compute_stream_)`.
2. `cudaStreamWaitEvent(prompt_copy_stream_, prompt_compute_done_, 0)`.
3. `cudaMemcpyAsync` logits D2H and last-row hidden D2H on the copy stream
   (two async copies, zero blocking `cudaMemcpy`).
4. `launch_attention_scatter_layers` on the compute stream (already ordered
   after logits MMV on that stream; the event is for the copy stream).
5. `cudaStreamSynchronize(prompt_copy_stream_)` and
   `cudaStreamSynchronize(prompt_compute_stream_)`. Count these as stream
   synchronizes, not `cudaDeviceSynchronize`.
6. Only then host-publish: GDN pointer swaps, token memcpy, last logits/hidden
   memcpy into session and caller buffers, `frontier_ += token_count`.

Unfused commit keeps blocking default-stream `cudaMemcpy` ×2, 16 one-layer
scatters, and one `cudaDeviceSynchronize`.

If logits MMV, async copies, scatter, or either stream sync fails, return the
CUDA status **without** swaps, token writes, caller-buffer writes, or frontier
advance. Caller logits/hidden therefore remain unchanged because they are
written only at step 6 from host staging. Staging buffers may hold candidate
bytes; that is not publication.

### Cancellation

When `control != nullptr && control->poll != nullptr`, fused path
`cudaStreamSynchronize(prompt_compute_stream_)` after each layer, then polls.
Count that as a stream synchronize plus a layer poll. Do not enqueue later
layers, logits, D2H, or scatter after a non-OK poll. Return the poll status
with frontier, committed GDN/KV, tokens, and caller outputs unchanged. Unfused
path keeps `cudaDeviceSynchronize` at the same boundary.

Do not overlap a later layer with an earlier layer. Do not scatter KV at layer
boundaries. Poll synchronization stays a visibility barrier for cancellation
and for surfacing async CUDA errors while state is still candidate-only.

### All other prompt launches

On the fused path, pass `workspace->prompt_compute_stream_` into
`matrix_prompt`, `launch_gdn_prepare_chunk_tiled`, `launch_attention_prepare_chunk`,
`launch_fp32_to_bf16`, `launch_swiglu_bf16`, and every direct `<<<..., stream>>>`
pointwise launch in `execute_prompt_chunk`. Unfused keeps `nullptr`. After a
successful fused return, both prompt streams have been synchronized, so a later
decode on the legacy default stream cannot race leftover prompt work.
