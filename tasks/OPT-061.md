# OPT-061 — Build real-input streaming replay and identify hardware limits

Status: pending. Dependencies: OPT-060. Coupled IDs: none.
Primary target: reusable component evidence with realistic cache behavior.
Read [the batch protocol](PERFORMANCE-RECOVERY-2026-09-11.md).

## Problem

OPT-046/047 microbenchmarks repeatedly reuse one shape/weight allocation.
That can reward cache-resident loads very differently from the 64-layer model.
FFN useful weight bytes total 9.626 GB/token. Per-family elapsed time alone
does not tell us whether DRAM, issue throughput, shared-memory barriers, or
CPU launches dominate. This task makes subsequent A/B tests representative.

## Implementation

1. Extend the OPT-043 capture structure or add a small capture bundle. Store
   exact BF16 projection inputs, FP32 residuals and intermediate outputs needed
   by FFN/mixer replay. Include FFN down input, output norm input for Q6 and
   actual prompt-row indices. Calibration layers 0,3,31,32; held-out62,63.
   Capture each once with role/layer/token/shape, GGUF tensor identity, selector
   set and hashes. Capture state separately for any stateful family; never time
   the capture copies. Do not copy hard-coded byte offsets from old harnesses;
   resolve tensor names through the validated inventory/model binding.
2. Add `cuda/optimization_component_replay.cu` and
   `build/qw38-cuda-component-replay`. Expose exactly these families initially:
   complete decode FFN, complete decode mixer projections, complete prompt FFN.
   The task-specific launchers select variants; the replay provides inputs,
   reset, timing and sampled reference utilities. Avoid a generic backend.
3. Support `cache_mode=hot|rotating`. Hot repeats one matrix and is diagnostic.
   Rotating visits distinct admitted layer weights in execution order. Use the
   resident model when available or a bounded set whose working set exceeds
   twice the queried L2 size. A timed round covers that full set. If a larger
   set cannot fit with current session/reserve, use an explicit cache-eviction
   pass outside the event interval and label it as an approximation. Do not
   charge flushing to one candidate only or count it as model work.
4. Match complete scope: norm, one shared activation stage, gate/up, SwiGLU,
   down stage/projection and residual for FFN; correct shared inputs plus all
   real mixer projections for mixer. Report kernel-only and enclosing time
   separately. Use OPT-060 frequencies, giving all gate/up/down exactly64 calls
   per token; a combined gate/up pair is 64 calls, not128 pairs.
5. Compare the same primitive inputs and complete family boundaries against
   the pinned authority adapter, using its actual selected dispatch. Do not
   call a standalone ggml MUL_MAT time the cost of fused llama FFN. Keep
   isolated-op output for numerical/reference use, labeled as such.
6. Record queried SM/L2/shared-memory limits, current400 W cap (or actual new
   readback), clocks, temperatures and throttling. For the dominant FFN decode,
   Q8 decode and Q4 prompt kernel only, request a bounded Nsight Compute capture
   if available: DRAM bytes/throughput, L2 hit rate, occupancy/register/local
   traffic, tensor activity and scheduler/barrier stalls. Query available metric
   names (`ncu --query-metrics`) rather than guessing architecture-specific names.
   Use `--launch-count 1` and a selected steady-state launch; no `--set full`.
7. If counters are unavailable, measure a streaming read calibration using a
   buffer larger than 2×L2 and a reduction/checksum preventing dead-code removal.
   Useful-byte rate is an estimate, never a DRAM-counter claim. Record compiled
   registers/shared/local bytes and the hot/rotating difference. Bound potential
   gain using measured family time; report uncertainty rather than declare
   bandwidth-bound from low arithmetic intensity alone.

## Tests and loop cost

Add `tests/test_opt061_component_replay.py`. Host tests cover capture hashes,
wrong role/shape, double-counted paired FFN, independent timing rounds, and
hot results refused as sole production acceptance. Native smoke: one tiny
Q4 case and one tiny Q8 case, no model; altered guard bytes must fail.
Correctness: at most 16 sampled output rows × 4 activation vectors ×one selected
K/family, independently decoded FP64. Reuse immutable OPT-059 references when
available; otherwise validate replay against independently decoded control dots
and record reference identity. Instrumentation can proceed while OPT-059 is
pending, but that does not admit changed arithmetic.

Screen one selected family: control only, 2 cache modes ×(1 warmup+3 samples)
on one bounded rotating set. Projection family outputs have full finite checks;
host reference is sampled. Prefill screen uses one 4096-row family, only 4 sampled
activation rows. A new capture is a separately labeled setup phase and cached
by the complete source/input identity. No repeated full-model captures per candidate.

```sh
uv run pytest -q tests/test_opt061_component_replay.py
uv run python tools/run_optimization_task.py --task OPT-061 --mode feedback --phase decode-ffn
uv run python tools/run_optimization_task.py --task OPT-061 --mode feedback --phase decode-mixer
uv run python tools/run_optimization_task.py --task OPT-061 --mode feedback --phase prompt-ffn
uv run python tools/run_optimization_task.py --task OPT-061 --mode acceptance
```

Each phase has a 300-second limit. Acceptance is 3 warmups+10 independent rounds
per cache mode/family. Hardware counters are a separate optional diagnostic
phase with one kernel launch per family; timeout/unavailability must not block
usable event replay. No end-to-end throughput sitting in this task.
