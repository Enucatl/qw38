# OPT-081 — Production numerics v3 contract

Status: pending. Dependencies: OPT-059, OPT-074, OPT-080. Coupled IDs: none.
Priority: P0, first execution task. Target: versioned candidate-vs-llama policy.
Read [the post-080 protocol](PERFORMANCE-RECOVERY-POST-080.md).
Quality risk: none (policy only). No production pin or kernel change.

## Outcome

Ship `pins/production_numerics_v3_contract.json` and a **new** Python module
`tools/production_numerics_v3.py`. Do not mutate v2 semantics in
`tools/production_numerics_v2.py` or `pins/production_numerics_v2_contract.json`.
Reuse pinned llama revision, GGUF SHA, calibration/held-out IDs, and family
shapes from OPT-059/074. No throughput or production keep claim.

Pinned llama GPU is the direct numerical authority. Candidate eligibility is
Quartz-vs-llama on identical production cases. llama-vs-FP64 is
`reference_error` only. The v2 rule
`held_out_llama_vs_fp64 <= calibration_derived_ceiling` is **not** active in
v3.

## Implementation

1. Freeze candidate-vs-llama limits in the v3 contract **before** any candidate
   output is read. Constants from the protocol: `abs_floor=1e-4`,
   `rel_abs=2e-3`, `rms_floor=1e-5`, `rel_rms=2e-3`, `cosine_ceiling=1e-5`.
   `scale(llama)=max(1e-6, max_i |llama_i|)`. Do not derive constants from
   candidates. Do not reuse `1.25 * llama_gpu_vs_fp64`.
2. Define fields `authority_coverage`, `authority_complete`,
   `reference_fp64_consistency`, `reference_drift`, `candidate_testable`,
   `candidate_v3_admitted`. Preserve `v2_admitted` / `v2_reason` /
   `held_out_validates` as diagnostics copied from historical fixtures, never
   as the v3 gate.
3. `reference_drift` is `high` when held-out llama-vs-FP64 max abs exceeds
   twice calibration max abs (or the historical v2 ceiling); else `low`.
   Drift does not set `candidate_testable=false` when authority coverage is
   complete.
4. Enforce hard staging tags: `quartz_q8_1_sum_q`, `llama_q8_1_sum_x`,
   `q8_fp32`, exact/recomputed integer sums. Interchange fails closed.
   Nonfinite fails closed without filtering finite lanes.
5. Authority identity fails closed: llama revision, GGUF SHA, tensor name,
   activation hash, K/M/N, layer, token position, production dispatch
   (`mmvq`, full M, N=1, no `--row-limit`).
6. Stateful operations are out of this task's kernel work but the contract
   must require GDN/attention candidates to add commit/reset/replay/causal
   tests in their owning tasks; projection-only admission is insufficient
   for those families.
7. Host tests prove the ten required v2-vs-v3 cases in the protocol,
   including exact llama match admitted under high FP64 drift, excess
   Quartz-vs-llama rejected under the same drift, held-out cannot enlarge
   limits, policy identity frozen before candidate read, and historical
   OPT-059/074 fixtures still produce the same v2 admission table.
