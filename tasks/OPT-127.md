# OPT-127 — Replay decode segments without per-token recapture

Status: pending. Dependencies: OPT-126. Coupled IDs: none.
Priority: P1.

## Outcome

Use OPT-126's stable inputs to remove the actual cost that defeated OPT-117.
Read OPT-125's shared protocol. Retain `ffn_only` unless full-request gates
pass. If OPT-126 found rooted infeasibility, record that blocked mechanism
as a no-candidate outcome rather than retiming the old recapturing path.

## Implementation

1. Reuse the eight-layer segment graph structure and all current selected
   kernels, including OPT-118/119. Capture/instantiate/upload at preparation
   or a genuine topology/session transition. Instrument each operation
   separately from parameter updates and graph launches.
2. Demonstrate zero capture/instantiate/destroy calls in steady-state tokens
   within one topology region, including alternating GDN commits. Predeclare
   a bounded policy for crossover/split changes and invalidation. Include its
   transition cost in full requests that cross 1024 and other actual boundaries.
3. Preserve the existing cancellation callback cadence and atomic commit.
   Measure cancellation response latency, including callbacks that request
   cancellation mid-segment. Do not defer user-visible output until a token
   batch completes or hide launch preparation outside the measured request.
4. Screen the existing segmentation first. Permit only one coarser candidate
   if correlated activity proves remaining graph submission gaps material
   and cancellation semantics permit it. No persistent full-model kernel.
5. Compare with fresh parent using both real sample/eval/output requests and
   historical engine probes. Attribute changes in true device inactivity,
   CPU submission, parameter upload, graph transitions and busy work.
   Do not claim any weight-byte reduction from replay.

## Acceptance

Run OPT-125's full quality/state/memory/performance gates. Include graph
startup amortization across short and 256-output requests, prompt-to-decode
handoff, long-cache checks and live 128K reserve. Publish counters proving
recapture elimination, raw correlated traces and
`evidence/optimization/opt127-recapture-free-replay/REPORT.md`.
Keep only with a measured request gain and passing guards; otherwise retain
`ffn_only` with a measured rejection.
