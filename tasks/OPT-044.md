## Concrete protocol

1. Inventory CUD-001, CUD-003, GDN, attention, graph, chunk-equivalence, trace,
   scalar-oracle, and `pins/quality_contract.json` gates. Make a table assigning
   each check to structural exactness, retained-reference arithmetic,
   production primitive quality, or end-to-end quality. Correct tests that
   assume the production selector must permanently equal a historical value;
   still test that the historical reference is callable and passes its checks.
2. Reproduce OPT-042's failed large shapes with existing packed, diagnostic
   integer, pinned llama, FP32 scalar, and FP64 accumulation of independently
   decoded weights × the same input. Compare separately to original BF16 input
   and each kernel's staged activation. This separates quantization error from
   reduction error. Keep the original numeric_reject evidence unchanged.
3. Freeze a calibration manifest BEFORE tuning production candidates. Use
   OPT-043 real captures, all historical primitive probes, zero inputs,
   alternating signs/cancellation, block extremes and large/small magnitudes.
   Include every quant family, each production K, early/middle/late layers,
   attention tails/nonzero prefixes, and GDN nonzero incoming state. Retain
   held-out captures at different tokens/layers; do not fit to only 0/3/63.
4. For each family/shape define reference error against independent FP64
   dequantized arithmetic. Measure pinned llama's error on identical inputs.
   Default production abs and RMS ceilings are
   `max(strict_reference_ceiling, 1.05 * measured_llama_error + 1e-6)`.
   For unit-norm cosine use `1-cosine` with the same construction and a `1e-7`
   floor; zero-vector pairs use explicit norm/abs checks. The 5% error headroom
   and floor are new documented design choices, not claimed llama thresholds.
   Report relative distributions, first failure and zero nonfinites. Freeze
   values before candidates and require held-out cases to pass the frozen
   family/shape ceilings. Unrepresented shapes use the strict path until covered.
   If llama fails a stress case, document the case and retain the strict path;
   do not automatically inflate ceilings from nonfinite/pathological output.
5. Use existing quality infrastructure (`tools/qw38_quality.py`,
   `tools/freeze_quality_inputs.py`, `tools/run_llama_quality_reference.py`,
   `tools/llama_authority/quality_oracle.cpp`). Keep dataset/revision/tokenizer
   pins. Add a versioned **production-optimization** suite using the existing
   1024-target Wikitext case, all eight functional cases, continuations at
   2048/4096, and recurrence short/long cases. Add a held-out 1024-target span
   disjoint from calibration, with exact token offsets/hashes in the manifest.
   Obtain pinned llama and current Quartz scores before candidate selection.
6. End-to-end default: perplexity ratio versus pinned llama <= **1.01** on
   both calibration and held-out spans (stricter than existing 1.05), and
   incremental recurrence NLL drift <= existing **0.02**. Require the existing
   functional answers, exact token/template handling, and zero nonfinites.
   Report teacher-forced full-logit max/RMS/cosine/KL and top-1 agreement on
   the captured positions. For continuation differences, freeze the allowable
   llama top-two margin from existing stored near-tie evidence before tuning;
   absent such evidence the margin is zero. A candidate may choose the runner-up
   only within that margin. A different free-running continuation is reported
   separately and must still meet the functional checks; token identity is not
   assumed to measure perplexity. Keep legacy quality verdicts alongside the
   new suite, not overwritten. Long-context quality remains distinct from speed.
7. Add internal strict/optimized path selection for diagnostics without
   installing an unvalidated fast kernel. Document supported precision at each
   boundary. Keep FP32 residual/GDN state/logits and BF16 persistent storage.
   Permit local explicit `fmaf`, `rsqrtf`, `__expf` or separate optimized objects;
   individually validate them. Do not globally fast-math host code, JSON,
   finite-value validation, or strict reference objects.

## Acceptance and scope limits

Deliver `pins/production_numerics_contract.json`, a calibration/held-out fixture,
`tests/test_production_numerics.py`, an independently computed metrics report in
`evidence/optimization/opt044-production-numerics/`, and a concise precision/
quality tradeoff section in the existing handbook. Test malformed/mutated
budgets, rejected nonfinites, held-out coverage, and preserved strict references.
Run the new suite, `tests/test_quality.py`, `tests/test_scalar_authority_alignment.py`,
`tests/test_cuda_quant_mmv.py`, `tests/test_cuda_scheduler_primitives.py`, and
affected native reference tests. Report baseline failures as existing failures;
do not quietly tune away a model-level discrepancy.

Every later arithmetic task uses these frozen criteria and validates the
combined production configuration. If its candidate fails, reject it or retain
strict dispatch for that shape. Do not adjust budgets after seeing a failure.
No sparse attention, weight requantization, reduced vocabulary, or speculative
decoding is admitted. Structural/session exactness is not an accuracy compromise.
