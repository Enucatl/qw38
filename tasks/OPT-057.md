# OPT-057 — Make optimization feedback bounded and builds reliable

Status: pending. Dependencies: OPT-055. Coupled IDs: none.
Primary target: iteration time and trustworthy validation; no model speedup claim.
Read [the batch protocol](PERFORMANCE-RECOVERY-2026-09-11.md) and
[testing strategy](TASK-TESTING-STRATEGY.md).

## Problem and scope

`tests/cuda_test_support.py` caches only two shared suites and omits an explicit
container working directory. Many newer pytest files embed their own nvcc and
long oracle commands. CUDA object rules have manually enumerated headers and no
depfiles; a pin or inline-kernel edit can leave stale objects. The existing
decode oracle allocates sessions/workspaces/graphs 33 times. Setting a tier on
its caller does not reduce those hard-coded loops.

Deliver a narrow runner for this batch, reliable CUDA dependencies, and a short
engine probe. Do not migrate every historical test or redesign the build system.

## Implementation

1. Add CUDA compile depfiles (`-MMD -MP`, explicit target/path as needed) and
   include them for release and trace objects. Add a content-compared build flag
   stamp per CUDA configuration so flag changes rebuild affected objects, while
   identical invocations are no-ops. Keep strict and experimental objects in
   distinct directories. Add explicit Make targets for this batch's diagnostics;
   take object/link lists from current scheduler targets, not old copied commands.
2. Add `tools/run_optimization_task.py` with `--task OPT-NNN`,
   `--mode feedback|acceptance|release`, `--phase <named-phase>` when a dossier
   splits setup, `--output-dir`, and `--dry-run`. Read explicit workloads from
   the task contract; do not invent a generic benchmark DSL. Dry run prints the
   resolved target, tier, cases/candidates, all loop products and deadline.
3. Use the already-built `qw38-cuda:13.0.2` image with `-w /workspace`, the
   repository bind mount and caller UID/GID. Missing image/model is a setup
   result with a concrete command, not an automatic Docker rebuild inside
   feedback. Use an exclusive advisory GPU lock and verify no foreign compute
   process; serialize CUDA work. Do not change power/clocks or kill foreign work.
4. Implement `screen` in `cuda/test_tier.h` and Python tier validation; audit
   every consumer of the shared native enum before adding the enum value.
   Legacy binaries must explicitly reject screen if their sizing logic would
   treat it as acceptance. In feedback, build once, run smoke/correctness, then
   screen only if those pass. Enforce a 300-second aggregate monotonic deadline;
   terminate the owned container and child process group on expiration.
5. Add `cuda/optimization_engine_probe.cu` and
   `build/qw38-cuda-optimization-engine-probe`. Reuse model binding and execution
   from `decode_oracle_test.cu`/`prefill_4k_oracle_test.cu`. Accept explicit
   prompt/prefix, output count, run count and named admitted selector combination.
   Defaults must be small; reject requests exceeding the selected tier's bounds.
   Load model once. Reuse allocated session/workspace and reset to exact initial
   state each round. Capture graphs separately for each selector; a host override
   changed after capture does not change captured kernels. Baseline and candidate
   share weights, not mutable recurrence/KV state. Skip logits host copies only
   if the corresponding control does too and the workload is explicitly different
   from the historical oracle; retain all logits for the standard short probe.
6. Feedback screen is at most one control/candidate pair: P4096 once each or
   prefix 2048 + 32 predetermined output tokens each. Use the historical token
   formula when comparing speed. Stateful setup/reset is outside timing but
   inside telemetry. Full P/D oracles remain unchanged and may only be invoked
   by explicit release mode. Mark short p95 results diagnostic.
7. Emit JSONL phases with start/end epoch, elapsed monotonic time, success,
   cache hits/misses, compile/link/load/reference counts, tokens, selected paths,
   and result class. Write to a fresh run directory; normal pytest only reads
   evidence. A later explicit task promotion copies its own successful evidence.
   Preserve stdout/stderr on timeout and numerical failure.

## Fast tests and commands

Add `tests/test_optimization_loop.py` for the runner. Use fake subprocesses,
fake clocks and a tiny temporary Make fixture for host behavior. Verify the
300-second aggregate budget, teardown of owned children, screen/release
separation, malformed tier, compile-once behavior, flag/header invalidation,
and immutable historical evidence. Do not use wall-clock sleeps in host tests.

Native smoke: one deterministic tiny projection, one warmup maximum, one
measurement, no model. Engine correctness for the new runner: once prepared,
two predetermined tokens and reset/replay, one selector, one graph/eager pair;
compare full logits and state/frontier, with no 64-layer scalar rerun.
Native integration is `screen`, since it loads the real model.

```sh
uv run pytest -q tests/test_optimization_loop.py tests/test_documentation.py
uv run python tools/run_optimization_task.py --task OPT-057 --mode feedback --dry-run
uv run python tools/run_optimization_task.py --task OPT-057 --mode feedback
uv run python tools/run_optimization_task.py --task OPT-057 --mode acceptance
```

The runner commands above are deliverables of this task. Acceptance validates
the runner itself with the bounded workload below, not a model speedup. Run one cold setup and
two warm repetitions; report all three durations. The second warm repetition
must avoid recompilation when inputs/flags are unchanged. Native counts are
one tiny case plus two tokens × two execution modes, not a P/D sweep.

## Acceptance and stop rule

Deliver `pins/opt057_iteration_contract.json`, a measured fixture and
`evidence/optimization/opt057-iteration-loop/REPORT.md`. Show one intentional
header change invalidates the appropriate temporary build, missing tiers fail
before GPU work, and an over-budget subprocess leaves no owned GPU work behind.
Demonstrate a useful warm feedback result within 300 seconds. If cold setup or
compilation exceeds it, identify that cost honestly; do not change the budget
or run acceptance as a substitute. No tok/s acceptance and no production pin
change. Do not run the complete historical test suite.
