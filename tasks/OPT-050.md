# OPT-050 — Prepare prompt queries once outside attention

Status: done (keep). Dependencies: OPT-044, OPT-045. Coupled IDs: none. Primary target: P.
Read [the shared protocol](PERFORMANCE-RECOVERY-2026-09-10.md).

## Change

In `cuda/fattn_mma_f16.cuh`, current CTAs loop over members/query rows, perform
RMS, RoPE and dual-F16 splitting using repeated CTA barriers. The two KV
partitions repeat the same query preparation. Add an upstream preparation
kernel in `cuda/attention_decode.cu`, one warp or CTA per token/query-head,
producing normalized/rotated Q once. Pinned llama `src/models/qwen35.cpp` and
`fattn-mma-f16.cuh` provide the upstream-norm/RoPE/prepared-Q boundary.

First preserve existing dual-F16 arithmetic and the virtual-warp RMS reduction
order to isolate the movement change. Then test OPT-044's cooperative/FMA norm
as its own variant. Write prepared Q hi/lo to a bounded reusable workspace;
reuse existing normalized-query storage only if size/alignment/lifetime are
proven. Feed all KV partitions from it, remove per-CTA normalization and trig,
and keep the strict old launcher available. Precompute inverse RoPE frequencies
once per model; compute position sin/cos once per needed position/frequency,
only if their additional workspace/cost beats in-kernel evaluation. Preserve
partial rotary dimensions and both rotated halves.

Candidate K/V preparation, physical cache indexing, causal span clipping,
grouped head mapping and atomic publication remain intact. No second committed
KV copy or persistent per-session allocation without allocation-ledger updates.
Prompt query preparation must handle nonzero prefix, tail rows, and prefix
reuse. Keep the already fast one-token decode path unless a measured win exists.
