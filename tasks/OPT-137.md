## Outcome

the pinned llama MMA execution organization with Quartz's dense BF16 cache.
Convert operands within a reused tile, not the entire cache every token. Admit
only a measured complete-engine win on D8192 and D32768 under `target_guard_v2`.
Retain the current parent on measured rejection or inconclusive performance.
Do not promise parity or a keep before evidence exists.

Ledger acceptance: One dense BF16 long-context MMA experiment has a verified
keep or bounded measured no-keep; any keep requires complete 8K/32K
branch/engine evidence, frozen target/guard admission, measured quality and
graph/state/128K checks.

## Frozen candidate design

Candidate ID: `dense_bf16_tile_f16_mma_decode_v1`. Exactly one candidate and one
dispatch rule; do not reopen OPT-130 as a second tuning sweep.

1. Retain BF16 authoritative committed/candidate K/V. Adapt pinned
   `fattn-mma-f16.cuh` for DKQ=DV=256, decode ncols1=1/ncols2=8 where the actual
   pinned shape dispatch verifies it. The model has GQA ratio six; the padded
   eight-column tile must mask unused heads exactly as the pinned code does.
   Verify actual launch, not just the selector's string. If this specialization
   does not match the authenticated model, block with the mismatch; do not
   silently substitute an unrelated vector benchmark.
2. Load BF16 K/V into a bounded transient tile, convert via FP32 to F16 using
   the same rounding convention as existing OPT-111 prompt attention, and
   reuse that tile across the applicable query heads. Keep FP32 accumulation
   and online softmax. This is a changed arithmetic path, not byte-exact
   equivalence to the old BF16 vector core. Charge conversion, query preparation,
   tail masking, partial reduction, merge and output gating to the complete
   candidate branch. Preserve raw query norm, partial RoPE, causal frontier and
   output-gate semantics outside the changed core.
3. Start from pinned load/tile/stage organization and partition formula, without
   tile/swizzle/register sweeps. For graph compatibility, compute partition
   counts once at graph creation using representative visible lengths 8448,
   33024 and 131072. Freeze the resulting integer counts and grids in the
   candidate contract before screen timing. Do not retune after results.
4. Dispatch: old production path at positions <8192; new consumer for
   [8192,32768), [32768,65536), [65536,131072), with a frozen graph topology for
   each bucket. Use OPT-126 device launch state for live frontier and GDN slot.
   Construct all needed eight-layer segment graphs up front; replay without
   per-token capture/update. Boundary changes select a prebuilt topology.
   Keep parent eager fallback and eight-layer cancellation checkpoints.
5. No persistent cache migration is required. Checkpoints retain canonical
   BF16 and FP32 state; temporary tile/merge workspace has explicit byte counts,
   lifetimes and graph-key coverage. Do not consume the 1.5 GiB reserve to add
   a second cache. P4096 prefill uses the current production prompt path.
6. Record file-level MIT provenance and the exact changes from pinned source:
   BF16 load/conversion, Quartz physical strides, head masks, frontier access,
   output gating, partition buckets and graph integration. Never label a
   modified adapter as the actual native llama result.

## Validation and fixed phases

All modes inherit explicit test tiers and GPU exclusivity from OPT-136. The
runner emits all loop counts before execution, reuses compiled artifacts, and
never changes measured roles or thresholds. Limit ordinary child operations to
300 s; explicitly budget 1200 s per full 131K cold-prefix quality/fit operation
(the historical prefill alone took about 243 s), with phase telemetry. Aggregate
acceptance is capped at 7200 s; missing hardware or timeout is incomplete. The
131K ceiling is a declared acceptance workload, not a smoke/screen exception.

1. **Identity/correctness.** Actual production-shaped Q/K/V captures from layers
   3/7/63; positions 8191,8192,8193,32767,32768,32769,65535,65536,131071.
   One sample per case, deterministic sampled FP64 reference with existing
   attention tolerances and zero nonfinites. Add zero/tail/masked-head tests.
   Check unchanged dispatch at 128,1023,1024,4096,4097. Compare old vs candidate
   under existing numerical tolerance; candidate graph vs candidate eager must
   be exact. Verify at final capacity position without accessing row 131072.
2. **Screen.** Exactly D8192/D32768, one warmup + three alternating paired
   complete 16-layer attention rounds on rotating real inputs, including
   conversion/prep/merge/gate, not a repeatedly cached single layer. One
   32-eval complete-engine pair at D32768 is the only optional engine screen.
   Advance if candidate branch point time is lower at both targets and the
   optional engine screen, if run, is not >2% slower. Otherwise measured
   `screened_out`; no expensive acceptance, no throughput admission claim.
3. **Quality (survivor required).** Invoke actual OPT-058 harness for both
   parent and candidate, using `--quality --quality-config` and the explicit
   new attention selector. Reuse active OPT-116 held-out/wikitext and recurrence
   budgets, not newly chosen tolerances. Add the candidate selector to that
   harness only as needed. Short teacher-forced prompts alone do not exercise
   this candidate: reuse OPT-116/120 long-cache free-running cases at populated
   8192,32768,131040+32 and compare parent/candidate using the existing scoring
   and thresholds. Emit positive new-kernel launch counts in long quality
   cases; zero launches makes candidate quality incomplete. Retain measured
   failures. Same-math reuse of parent NLL is forbidden for this arithmetic.
4. **State/memory.** Prompt->decode handoff, repeated sample/logits ownership,
   graph/eager equality, cancellation before/during/after a segment, restoration
   across 8192/32768/65536 boundaries and final-capacity correctness. Populate
   a 131072-capacity session and measure live memory after all candidate graphs
   exist; require the existing reserve and checkpoint round-trip gates. Do not
   substitute an allocation formula or the parent's old fit for candidate fit.
5. **Acceptance performance.** OPT-135 three warmups + ten AB/BA pairs per
   workload. Targets: D8192 and D32768 decode-only (256 evals). Guards: their
   complete-request rates, D128 and D2048 decode-only and complete-request,
   and P4096 prefill. Use OPT-136's common capacity/input/output boundaries on
   both Quartz arms, identical restoration outside timing, all work charged.
   All targets L>1; all throughput guards L>=0.98; every decode p95 ratio<=1.05.
   No aggregate can conceal a target failure. Report 2% materiality separately.
6. **Long ceiling probe.** Parent/candidate D131040+32 at capacity131072,
   three warmups + ten paired runs using reusable validated prefix checkpoints
   restored outside decode timing. Decode-only is a guard with L>=0.98 and
   p95<=1.05; request throughput is N/A when prefix is restored. Run once per
   arm from cold prefix to report full prefill cost separately. Do not silently
   count restore as prefill. If fit or long guard is missing, no keep.
7. **Mechanism and llama check.** For the survivor use OPT-136 bounded node
   captures to verify the new kernel executes at 8K/32K, short graphs remain
   unchanged, and steady-state recapture count is zero across bucket boundaries.
   Compare against fresh unmodified pinned llama 8K/32K using the matched
   harness. Reconcile the branch saving with the engine delta; unexplained
   disagreement >max(0.2 ms/eval, 20% of predicted saving) triggers one
   integration diagnosis, not a fabricated additive explanation.
