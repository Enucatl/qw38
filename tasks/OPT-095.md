# OPT-095 — Share decode KV across query heads
Status: pending. Dependencies: OPT-094. Coupled IDs: none.
Priority: P1. Target: remove repeated KV loads within each six-query-head group without adding query preparation launches.
Read [the post-088 protocol](PERFORMANCE-RECOVERY-POST-088.md).
Quality risk: incorrect grouped-head mapping, synchronization or candidate-KV visibility can break causality.
Instrumentation: actual KV loads/bytes, CTA occupancy, prep/core/merge/gate complete cost and D128/D2048 ITL/p95.

## Outcome

Share decode KV loads across six query heads without a prep launch, with one
production keep or retention of warp_query. This is not a repeat of OPT-078:
its prepared_q acceptance was 9.092 →10.315 ms (CI −1.970 to −0.476 ms),
and the extra launch erased the proposed benefit. Both old prep candidates
remain rejected.

## Implementation

1. Create `pins/opt095_attention_gqa_contract.json`, the iteration contract,
   `tools/opt095_attention_gqa.py`, `tests/test_opt095_attention_gqa.py`,
   `fixtures/opt095_attention_gqa.json` and
   `evidence/optimization/opt095-attention-gqa/REPORT.md`. Add
   `cuda/opt095_attention_gqa_test.cu`, native
   `build/qw38-cuda-opt095-attention-gqa-test`, Makefile
   `cuda-opt095-diagnostics` with existing replay/probe targets.
2. Exactly two configurations in `cuda/attention_decode_path.cuh`:
   `warp_query` control and new `warp_query_gqa6` candidate. Implement
   `warp_query_gqa6_decode_attention` in `cuda/attention_decode.cu` and wire
   its existing scheduler call in `cuda/full_scheduler.cu`. Candidate
   `prep_launches=0`; retain K/V preparation and commit boundaries, all 16
   partitions, output gate, BF16 casts and deterministic ascending-part merge.
3. Production configuration: 24 query heads, four KV heads, width256,
   rotary64, one token. Launch block=(32,6), grid=(4,16): one warp per query
   head within a KV group, query_head=6*kv_head+warp. Prepare each Q inside
   its warp with the exact existing lane0 ordered norm/RoPE arithmetic.
   At each existing key position, cooperate to load K and V once into two
   shared BF16[256] slabs, synchronize before consumption and before overwrite;
   every warp retains its original lane*8+i order and softmax operations.
   Use legal 16-byte loads only on aligned segments; otherwise use safe scalar
   loads with identical values. Do not change KV layout or materialize head copies.
4. Parity positions {0,1,31,32,127,128,2047,2048}; fixed 24/4/256/64 shape,
   random seed89 plus zero and cancellation at positions1/32. Compare all
   outputs bitwise to warp_query for small cases; at production positions also
   compare full outputs bitwise and independently sample four query heads×eight
   output dimensions against the existing attention FP64 checker. Preserve
   existing ATN-001/OPT-078 tolerances; graph/eager and aligned/scalar load
   variants must be identical. Check last committed KV, current candidate KV,
   new input/position at the same address, empty partitions and output guards.
5. Entry trigger: valid OPT-090 attention evidence must show repeated KV load
   work, with ≥0.10 ms/token measured attention cost available. If not, finish
   `no_go_no_measured_sink`. Screen all 16 attention layers at position128 and
   2048 in separate 1+3 AB/BA phases; at most one D2048+32 engine screen.
   The reduced grid can lose occupancy or synchronization time; reject if
   neither prefix saves ≥0.10 ms/token or either complete component regresses
   >2%. No partition or warp-count sweep is allowed.
6. Run/reuse full Q with exact-output evidence and frozen-anchor guards. Then
   3+10 complete-attention pairs at each prefix and five engine pairs each at
   D128/D2048+32 with p95. Require positive component CI and ≥0.10 ms/token
   at D2048, and ≤2% complete-component regression at D128, plus common E2E
   guards and one P4096 guard. Select one global candidate only; no per-context
   exception table. Otherwise keep warp_query. Include shared-memory size,
   registers, occupancy and actual bytes to explain keep/reject.

## Acceptance

- Bitwise per-head outputs, same-path graph replay and causal KV boundaries
  pass; no new prep kernel or altered quantization/softmax.
- Complete 16-layer component saving transfers through D128/D2048+p95 guards;
  isolated DRAM-byte reduction is insufficient.
- Independent verdicts: `kernel_parity_pass`, `model_quality_pass`,
  `performance_pass`, `production_kept`.
- `claims_throughput: true`; screened or rejected candidates claim no gain.
