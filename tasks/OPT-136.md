## Frozen measurement protocol

All new task runners implement `--phase`, `--mode` and `--run-dir`. Commands
below name the interface to create, not an interface already present.
Use `tasks/TASK-TESTING-STRATEGY.md`: explicit tiers, build once, recorded loop
counts, shared GPU lock `build/optimization-runs/qw38-gpu.lock`. No concurrent
large GPU processes. Record residents before each process; do not stop unrelated
services automatically. Each child capture/sample has a 300-second timeout;
the enumerated overall acceptance run has a 7200-second ceiling. Report timeout
as incomplete, retaining partial evidence. No optional sweeps or automatic
retries beyond one diagnosed capture retry per failed case.

1. **Identity.** Freeze current Quartz selectors/binary hash at preflight and
   pinned llama revision `cc83d7b4824f73cfdda4dfbb47ee39804f71b328`. Same GGUF
   SHA from `pins/artifacts.lock.json`; record actual compiled kernel names,
   grids, dtypes, strides, padded/visible lengths, graph mode and capacity.
   Authenticate current pins, not an obsolete `ffn_only` prerequisite helper.
2. **Inputs.** Prefixes 128, 2048, 8192 and 32768, each followed by exactly 256
   planned eval tokens `(42 + index*997) % 248320`, no sampling. Both engines
   allocate context 131072, populate the same prefix, and execute the same
   eval sequence. Report eval count separately from emitted token count (zero
   in this fixed-token probe). One eval includes final logits computation;
   host full-logit materialization and sampler are excluded on both sides.
   Synchronize completion consistently. Quartz's intrinsic argmax/commit work
   remains charged and identified if the production path performs it.
3. **Metrics.** Setup/load/graph creation/warmup/restore are separately timed.
   `prefill_ms`: prefix evaluation only. `decode_only_ms`: first planned eval
   start through completion of eval 256. `complete_request_ms`: prefix start
   through final eval completion, with no restore inserted inside it.
   Rates use explicit prompt/eval numerators; label these fixed-token engine
   metrics, not public chat output rates. Never subtract TTFT containing a
   decode eval as though it were prefix-only time.
4. **Unprofiled baseline.** Three warmups plus ten alternating Quartz/llama
   pairs per prefix, never both loaded together. Preserve each run and per-token
   latencies. Both arms use the same input/capacity/output boundary; a same-arm
   A/A check at D128 and D2048 uses three warmups + five pairs. A/A is usable
   if its two-sided 95% paired log-ratio CI (Student-t, df=4, critical
   2.7764451051977987) contains 1 and point ratio lies in
   [0.98,1.02]; otherwise diagnose environment/identity once and stop ranking
   if unresolved. The baseline comparison reports uncertainty, not a keep.
5. **Capture bounds.** On each prefix and engine capture steps [0,12),
   [122,134), [244,256) of a 256-eval trajectory. Use NVTX ranges containing
   engine, prefix, step and logical layer/operation IDs plus explicit CPU and
   GPU window boundaries. Capture three windows in one process where supported
   (12 complete evals per window, 36 profiled evals total; count all graph nodes
   for those evals, not just twelve kernel nodes).
   Keep marker boundaries and drain/warmup outside the measured work consistent
   across twins. Fall back to three separate identical-trajectory processes
   only if repeated capture is unsupported; record this fixed alternative.
6. **Three capture arms.** For each engine/prefix run three independent twins
   of unprofiled, graph-level, and node-level capture (8 engine/prefix cases x
   3 repetitions x 3 arms). Baseline twins disable CUDA-event attribution,
   per-operation synchronization and profiler API gating waits. Profile the
   current production graphs; do not disable them for component attribution.
   Use `--trace=cuda,nvtx,osrt --cuda-graph-trace=graph` or `=node`,
   `--sample=none --cpuctxsw=none`, and CUDA-profiler capture ranges, saving the
   exact nsys commands. If pre-created graph NVTX projection is unavailable,
   map nodes using recorded graph/node identities and kernel/operation order;
   do not infer GPU durations from CPU NVTX spans.
7. **Overhead.** Report each window's baseline, graph and node wall durations,
   absolute/relative perturbation and all three repetitions. Node profiling
   with >5% median absolute relative perturbation cannot establish absolute
   production component savings; label it perturbed and allow only hypotheses.
   One bounded lower-overhead attempt is allowed after identifying a cause.
   Do not subtract profiler overhead uniformly from every kernel.

## Accounting assertions and evidence schema

Store native nsys timestamps as integer nanoseconds. Read units from the export
schema, never infer them from numeric magnitude. Scope by device/context/process
and explicit capture window; include kernels, memcpy/memset, GPU graph envelopes
and CPU APIs as distinct tables. Clip all intervals to the same window, merge
overlaps, and keep cross-stream overlap explicit. Window length comes from its
markers, not first/last observed leaf (which would discard leading/trailing gaps).

Each `coverage.json` row includes identity, window start/end, table names/counts,
expected/observed graph launches, parent/node correspondence, drops/errors,
kernel/copy union, graph envelope union, graph-exclusive intervals without leaf
coverage, time outside all activity, unmapped kernel time and profiler overhead.
On graph-only captures `internal_idle_ms` is null. Node coverage is required
before labeling intervals inside a graph as no-kernel intervals. Even complete
trace gaps are process-scoped no-kernel activity, not proof of hardware-wide
idle, host causation or removable time. Those require their own evidence.

Assertions (all must be independently tested):

- Duration conservation after clipping: window = disjoint covered + uncovered
  intervals within max(0.01 ms, 0.1% of window). Parent+child overlap is never
  charged twice. Nested NVTX cannot add GPU work.
- Graph-level capture of Quartz has eight GPU graph executions per eval;
  graph/node captures cross-check corresponding launches and expanded node
  identities. Count changes require a source-verified topology explanation.
- Drop/truncation, absent required tables, duplicate/missing correlated nodes,
  wrong units, missing bounds and missing expected activity invalidate coverage.
- At least 95% of observed kernel/copy duration is assigned to a named family;
  publish unmapped remainder explicitly. Coverage validation is not forced to
  call an observed scheduling gap a kernel. Large gaps are a separate family.
- A component matched to llama requires equal logical work, input, cache length
  and output boundary. Fused llama operations remain one enclosing group;
  regroup Quartz to the same boundary or report unmatched, never llama=0.
- Do not explain OPT-125's historical four-token `ffn_only` gaps using a scalar
  fraction of a different twelve-token `decode_segments8` capture. Historical
  aggregate comparisons are labeled non-causal; only same-run aligned intervals
  can establish overlap. Remove that false causal reconciliation.

Families: Q4 gate/up/SwiGLU/down, Q8 mixer projections, Q6 attention output,
Q6 logits, GDN convolution/recurrence/gated output, attention
prepare/cache-write/core/merge/gate, residual/norm/quant staging, other copies,
and unclassified. Also publish larger non-overlapping FFN/mixer/attention/logits
groups for fused matches. Report per-window ms/eval, counts and differences;
no cross-family sum unless the grouping is disjoint. Reconcile the total gap
to measured family excess plus scheduling/unmatched remainder, not assumed zero.

For matched family excess use paired per-run differences
`Quartz_ms - llama_ms` from the three capture repetitions, per window; positive
excess requires the one-sided 95% Student-t lower bound >0 (df=2, critical
2.919985580355516). Do not treat tokens, layers or the three windows of one run
as independent samples. Also report the two-sided 95% interval (df=2, critical
4.302652729696142). Whole-rate comparisons use ten paired log ratios with df=9:
one-sided critical 1.8331129326536335, two-sided critical 2.2621571628540993.
These diagnostic intervals rank evidence; they do not admit a production keep.
When uncertainty cannot resolve a family ordering, keep the tie/unknown visible.
