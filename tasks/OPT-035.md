Scalar path (`MmaPv=false`, production until A/B): today's unrolled `scores[qcol * 32 + krow] * bfloat16(V)` into dim-strided `acc[]`. Must remain byte-identical to current `main` when the pin is `scalar`.

MMA path (`MmaPv=true`):

- After the existing FP32 softmax writes **weights** into `scores` (causal/OOB already zero), do **not** change max/denominator arithmetic.
- Convert each weight to two F16 components on the fly when packing MMA A fragments, matching Q dual-F16: `hi = __float2half_rn(w)`, `lo = __float2half_rn(w - __half2float(hi))`. Do not add shared arrays for packed P. Do not quantize scores before the FP32 exp/max/den loop.
- Convert BF16 V to **single** F16 on the fly when packing MMA B fragments (`__float2half_rn(__bfloat162float(V))`), matching K in Q×K. Do not add dual-F16 V (that would be four MMA products and is out of scope).
- Use existing `mma::mma_m16n8k16_f16_f32` only:
  - M = 16 query columns (`m0` steps over `kNcols=32`)
  - N = 8 head-dim lanes
  - K = 16 KV rows (`k0` steps over the 32-row tile)
  - A = dual-F16 probability; B = F16 V; C = FP32
  - Two MMA per K-step: `C_hi += P_hi × V`, `C_lo += P_lo × V`, then `C += C_lo` in FP32
- Warp ownership of N tiles: `n0 = warp * 8 + n_local * (kNwarps * 8)` so each of 4 warps holds 8 n8 tiles of the 256-wide head (64 FP32 C elements per thread: `2 M-tiles × 8 N-tiles × 4`). Do not use the scalar dim-strided `tid + slot * 128` mapping for MMA C.
- Before adding the tile, rescale each live C element by that query column's FP32 `rescale[qcol]` (same factor as today's register path). First-tile `factor == 0` zeros C.
- Pad K-steps and dead query rows with zero P and zero V. Do not write dead rows (`row >= active_rows`) to global `vkq`.
- After the KV loop, scatter MMA C fragments once to global `vkq` (`output` for `kv_z==0`, `partial` for `kv_z==1`) using `mma::tile16x8_i` / `tile16x8_j`. Then existing meta write (`tid==0`) and existing combine launch.
- No extra `__syncthreads__` beyond the current tile barriers except those required so softmax `scores`/`rescale` are visible before packing A. Do not introduce a second score workspace.

`KvParts==1` templates used by occ2/baseline are not retargeted. Persistent is not retargeted.
