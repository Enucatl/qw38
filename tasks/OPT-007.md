# OPT-007 — Execute multiple prompt query rows per CUDA block

## Control

- Primary ID: `OPT-007`
- Coupled IDs: `none`
- Dependencies: `OPT-006`; done at planning admission
- Status: `done`
- Ledger acceptance: Prompt attention maps query-row tiles to occupied blocks with bounded scratch and passes short/chunk boundary equivalence

## Goal and boundaries

Change the production grouped tiled prompt-attention kernel from one query row
per `(KV head, row)` block to a fixed two-query-row tile per
`(KV head, row tile)` block. A block stages each causal 32-context K/V tile once
and applies it to both owned query rows, masking contexts beyond each row's
absolute position. Preserve the admitted grouped-query mapping, online-softmax
operation order, candidate/committed transaction boundary, fixed scratch bound,
and exact observable results of the retained one-row grouped path.

- Constraints: keep C++17, CUDA 13.0.2, `sm_120`, 256 threads, 32-context K/V
  tiles, the production `24 / 4 = 6` GQA mapping, token-major inputs/outputs,
  BF16 K/V storage, FP32 normalization/score/softmax/value accumulation,
  partial 64-lane RoPE, strict causality, prepare/commit isolation, and the
  frozen ATN-001/ATN-002/OPT-005 numeric limits. Keep exactly two production
  kernel nodes for every positive chunk. Dynamic shared memory must remain the
  existing fixed 33,792 bytes, independent of prompt length; compiler-reported
  per-thread local storage must be no more than 512 bytes and the production
  attention kernel must admit at least one active block per SM under the
  captured launch parameters. Do not add persistent or prompt-sized global
  scratch. Do not edit `Makefile`, whose complete bytes are covered by existing
  provenance contracts; build the diagnostic with an explicit pinned `nvcc`
  command.
- Non-goals: changing the scheduler's 64-row prompt chunk or making 4,096 rows
  the default (`OPT-008`); changing physical KV layout (`OPT-010`); changing
  prompt projection/MMQ, GDN scans, output fusion, pipeline overlap, or prompt
  graphs; changing cache/checkpoint formats or public APIs; tuning a family of
  row-tile sizes; or claiming component or end-to-end speedup.
- Plan impact: `none`
- Affected interfaces: no public engine, CLI, server, model, checkpoint, or
  fixture-format interface changes. The existing CUDA-internal production and
  diagnostic launcher signatures remain unchanged. A new task-specific
  contract and fixture form a schema-1 evidence interface.
- Implementation classification: not mechanical. This changes CUDA block
  ownership, synchronization, register/local state, causality masking, and
  numerical invariants, and introduces hardware-inspected launch evidence.

## Implementation decisions

Rename the current `grouped_tiled_chunk_attention` implementation to identify
it as the retained one-row grouped diagnostic and leave its arithmetic and
instrumented-load behavior unchanged. Keep
`launch_attention_prepare_chunk_grouped_instrumented` wired to that retained
kernel so the delivered OPT-006 evidence remains reproducible.

Add a non-instrumented production specialization with compile-time
`kQueryRowsPerBlock = 2`. Launch it on
`(config.kv_heads, ceil(token_count / 2), 1)`. Block `blockIdx.y` owns relative
rows `2 * blockIdx.y` and `2 * blockIdx.y + 1`; the last block processes only
the first when the chunk length is odd. There are no empty logical row blocks.
The staging launch remains `(config.kv_heads, token_count, 1)`.

For each active row and each of its six mapped query heads, normalize and apply
RoPE in the same increasing-lane order as the retained kernel, then keep that
thread's query lane, running maximum, denominator, and value accumulator in
fixed compile-time arrays. Stream contexts only through the later owned row's
absolute position. Load each BF16 K/V context lane once into the existing
32-row shared tile. For each context, update the earlier row only when the
context is no greater than its absolute query position, and always update rows
in increasing row order and heads in increasing group-member order. Thus each
individual query row consumes exactly the same contexts, in the same order,
with the same lane-order dot reduction, online-softmax rescaling, stable sigmoid
gate, and token-major write as the retained one-row grouped path. The extra
context needed by an odd/even partner is staged but never included in the
earlier row's state.

Keep the existing dynamic shared layout: 256 FP32 scratch values followed by
32-by-256 BF16 keys and 32-by-256 BF16 values, exactly 33,792 dynamic bytes.
Do not use global score scratch. The two-row and six-head state is compile-time
bounded and independent of token count. Acceptance additionally inspects the
compiled kernel through the captured graph: `cudaGraphKernelNodeGetParams`
must report the expected grid, 256-thread block, and 33,792 dynamic bytes;
`cudaFuncGetAttributes` must report no more than 512 local bytes per thread;
and `cudaOccupancyMaxActiveBlocksPerMultiprocessor` must report at least one
resident block for the captured parameters. Record the actual register count,
static shared bytes, local bytes, maximum dynamic shared bytes, active blocks
per SM, SM count, and launch block count rather than embedding unverified source
claims in the fixture.

Add `cuda/query_row_attention_test.cu`. With production configuration
`{24, 4, 256, 64, 131072}`, allocate independent production-row-tiled and
retained-one-row buffers. Test row counts 1, 2, 3, 63, 64, and 65 at committed
prefix 31. Require byte-exact production/reference FP32 outputs and candidate
BF16 K/V, finite output, unchanged committed K/V and frontier during prepare,
untouched score scratch, and unchanged invalid-input rejection. The existing
OPT-006, OPT-005, and ATN regression suites retain commit, future/later-row,
capacity, and untiled-oracle gates.

In the same native diagnostic, prove the current chunk boundary by comparing a
single 65-row prepare/commit sequence at prefix 31 with a 64-row prepare/commit
followed by a one-row prepare/commit using the corresponding input offset.
Require all 65 token-major output bytes, committed K/V bytes through the new
frontier, and final frontier to be exact. Capture production launches for every
row case, require two kernel nodes, identify the attention node by its nonzero
dynamic shared bytes, and require grid Y to equal `ceil(rows / 2)` while the
staging node grid Y equals `rows`. Record the compiler attributes and occupancy
from the 64-row attention node and fail before emitting JSON if any semantic,
topology, scratch, or occupancy predicate is false.

Add a schema-1 contract, measured fixture, and Python validator in
`tests/test_cuda_query_row_attention.py`. The validator requires exact
keys/types, pinned environment metadata, tile size two, all six row cases,
byte-exact true predicates, exact per-case staging and attention grids, two
kernel nodes, exact dynamic shared bytes, local bytes at or below 512, positive
register/SM/launch counts, and at least one active block per SM. Negative tests
must reject a missing equivalence predicate, a row-grid count off by one, a
dynamic-shared value off by one, zero occupancy, local bytes above the cap, and
placeholder metadata. The exclusive test builds with the same pinned flags as
OPT-006, executes exactly one native record, and validates it through the same
function used for the checked-in fixture. `--regenerate-fixture` performs one
successful pinned run and atomically replaces the fixture.

Update the existing attention-prefill chapter with the two-row mapping, causal
mask, tail behavior, fixed shared/local bound, captured launch/occupancy values,
65-versus-64+1 equivalence, and component-only proof limit. Add a local
derivation/evidence entry to `docs/sources.md` and one non-final OPT-007 audit
row during implementation; delivery changes that row to the final measured
