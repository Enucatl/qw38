# OPT-103 — Port the one-query vector attention specialization

Status: pending. Dependencies: OPT-099. Primary target: D2048 attention core.
Read [the post-098 protocol](PERFORMANCE-RECOVERY-POST-098.md).

## Outcome

Add a Quartz-owned 128-thread, one-query online-softmax attention kernel based
on the pinned llama vector FlashAttention organization. Compare it with the
selected `warp_query` path and keep only a complete 16-layer D128/D2048 win.

## Rationale

At D2048 Quartz attributes about 4.4 ms/token to attention core. OPT-095's
`warp_query_gqa6` combined six query heads in one CTA and was slower. Pinned
llama selects `flash_attn_ext_vec<256,1>` for one BF16/F16 query at the measured
prefixes: 128 threads cooperatively traverse K/V, maintain online softmax and
accumulate V in registers. That mechanism does not require the rejected GQA6
CTA or a separate query-preparation launch.

## Implementation

1. Confirm the pinned llama dispatch for the exact head width 256, 24 query
   heads, 4 KV heads, BF16 KV, D128 and D2048 shapes in OPT-099 evidence. Port
   only the necessary algorithmic organization with file-level MIT provenance;
   do not import ggml tensor/runtime machinery.
2. Implement one candidate `vec128_online`: 128 threads per query head and
   sequence partition, query held in registers, vectorized BF16 K/V loads,
   stable online max/sum, register V accumulation, and a bounded merge only
   when more than one sequence partition is measured faster. Keep head width
   and GQA mapping compile-time fixed for the model.
3. Choose the partition count from `{4,8,16}` in a single production-shape
   screen at D128 and D2048; select one candidate before acceptance. Report
   blocks, K/V bytes, registers, spills, occupancy and merge cost. Do not add a
   second GQA-sharing design.
4. Preserve partial RoPE, q/k RMSNorm, causal masking, stable softmax, KV write
   visibility, output gate, BF16 conversion and transactional KV commit. The
   current `warp_query` path remains the reference.
5. Require independent FP64 attention samples, per-head output parity, full
   logits/quality, long-prefix boundary tests, graph/eager equivalence,
   checkpoint/restore and cancellation.
6. Apply the shared 3+10 complete-attention and five-pair D128/D2048 protocol;
   P4096 is a non-regression guard.

## Acceptance

- Preparation-inclusive complete 16-layer attention saves at least
  0.10 ms/token with a positive paired 95% interval.
- D128 and D2048 point throughput and p95 improve; full quality, state and
  P4096 guards pass.
- Dispatch is limited to admitted one-query shapes with explicit fallback.
  Rejection restores `warp_query` and leaves `warp_query_gqa6` rejected.
- Add contract/fixture, native tests, runner and
  `evidence/optimization/opt103-vector-attention/`.

## Non-goals

No approximate/quantized KV, GQA6 retry, prompt-attention rewrite, changed RoPE,
reduced partitions without measurement, or current llama HEAD as authority.
