# OPT-125 — Reconcile decode timing, GPU activity and traffic evidence

Status: pending. Dependencies: OPT-123, OPT-124. Coupled IDs: none.
Priority: P0.

## Outcome

Establish a trustworthy post124 baseline and a causal budget for the next
batch. This task changes diagnostics and evidence only. Read OPT-115,
OPT-116 and OPT-124; the shared protocol below governs OPT-126–132.

## Evidence that must be reconciled

- In `cuda/opt123_combined_stack_test.cu::run_session_arm`, the clock starts
  before prefill and decode tok/s uses outputs divided by that entire wall.
  Its long-context path uses the same function. OPT-115's request probe
  subtracts prefill. Thus 41.420→8.066 at D8192 and 22.118→1.352 at D32768
  are not evidence of a decode regression without matching boundaries.
- OPT-124 compares those Quartz rates with the pinned llama decode oracle.
  Audit that oracle's actual boundaries before reusing 0.787×/0.620×.
  Even a valid whole-engine ratio cannot identify attention's component ratio.
- `tools/opt115_pipeline_traffic.py::classify_timeline` labels gaps between
  kernel leaves as GPU idle. Missing graph children, copies, another stream,
  event perturbation or unrecorded work can occupy those gaps. Coverage based
  on filling leaf gaps is not independent evidence of hardware inactivity.
- OPT-124's D128 event busy union is 8.2922 ms but its proposed compulsory
  weight-byte minimum is 10.1829 ms. D2048 timeline components total about
  20.9921 ms, while its separate request average is 24.0193 ms. These are
  measurement/model consistency questions, not demonstrated savings.

## Implementation

1. Trace native and Python metric derivations from timestamp to final report,
   including pinned llama. Freeze distinct names and boundaries for setup,
   prefill, time to first emitted token, decode-only, sample/eval/output,
   complete request and fixed-token engine probes. Count actual outputs and
   eval calls explicitly; define whether the first sampled token needs eval.
   Preserve historical fields with a dated correction, never silently rewrite
   a prior experiment. Add small synthetic metric tests with known prefill
   and decode durations, including a missing/failed measurement case.
2. Authenticate current combined OPT-118+119, historical post113 and pinned
   llama. Run fresh A/A and matched baseline P4096/D128/D2048; retain raw
   timestamps, capacities, token sequences/counts, selectors, build/dirty
   identity, clocks, power, GPU occupancy and actual dispatched kernels.
   Separate fixed-token and free-running request comparisons. Recompute old
   numbers only where stored fields support it; otherwise mark not comparable.
3. Capture a bounded CUDA activity/API trace through available Nsight Systems
   or CUPTI tooling on the real unmodified request path. Include all streams,
   graph children, copies/memsets, CPU launch/API spans, waits, callbacks,
   allocation and commit. Align clock domains and compare instrumented with
   uninstrumented samples. Use early/middle/late decode windows over the same
   256-output trajectory, rather than treating a single prefix token as its
   average. Profiler absence is an explicit attribution limitation, not zero
   activity. Keep raw traces and quantify instrumentation overhead.
4. Produce disjoint device-active/device-inactive/unobserved intervals.
   Attribute true inactive spans to CPU submission starvation, host work,
   required dependencies and unresolved causes using API correlation and
   bounded diagnostic ablations. Never count a CPU wait that overlaps GPU
   execution twice, nor equate an event leaf gap with removable launch time.
5. Recompute executed weight reads from tensor roles and actual consumers:
   embedding rows versus the whole embedding, output head, reuse and graph
   coverage. If available, counter-sample DRAM/L2 on representative weight
   kernels and measure a matching access-pattern bandwidth probe. Distinguish
   stored bytes, logical reads and physical DRAM traffic. Reconcile the
   busy-time contradiction or label the bound unsupported. Do not add observed
   idle as an unavoidable lower bound on an implementation that could remove it.
6. Repeat matched populated D8192/D32768 measurements with both request and
   decode-only rates; obtain D131040 and original OPT-016 2K in an exclusive
   sitting if available. Record allocation failures accurately; a generic
   failed process is not necessarily OOM. Do not stop unrelated services.
7. Rank causal removable request milliseconds, confidence and overlaps for
   OPT-126–131. Each receives proceed/no-material-opportunity/insufficient-
   evidence with a reason. Missing profiling does not block independent
   source-grounded graph or attention correctness work.
