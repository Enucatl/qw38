## Change

`cuda/full_scheduler.cu::matrix_vector` currently bypasses quant_mmv for Q8_0
and calls `q8_mmv_bf16`, so optimizing Q4_K does not address the 11.55 ms
historical mixer category. Retain that direct-BF16 kernel as strict reference.
Implement a production Q8_0 × Q8_1 DP4A path using the OPT-046 staging utility,
with no ggml dependency. References: pinned llama `vec_dot_q8_0_q8_1`,
`mmvq.cu`; ds4 `quantize_q8_0_f32_kernel` and `matmul_q8_0_preq_kernel` for
prequantization reuse, not as a drop-in numerical contract.

For each 32-element block compute integer dot(q8_weight,q8_activation), then
apply weight and activation scales in FP32. Distribute K across 1/2/4/8 warps
per row; tune separately for skinny alpha/beta, medium K/V and wide packed
projections. Enumerate actual shapes/types from the model inventory and
OPT-043 captures rather than guessing. Keep direct-BF16 fallback for tiny
projections if staging plus DP4A loses.

Quantize the common normalized input once per mixer layer, then reuse across
GDN packed_qkv/value_gate/alpha/beta or attention query_gate/key/value. Output
projection has a different activation and must stage again. Initially use
separate launches with shared staging; do not couple activation reuse to a
large fused kernel. Enforce workspace lifetime through the last consumer.

This adds activation approximation to a previously direct-BF16 path. Report it
explicitly, using the original BF16 input as the high-precision reference and
the OPT-044 same-input llama quality budget. Do not borrow prompt-only Q8_0
association tolerance as an undocumented decode rule.
