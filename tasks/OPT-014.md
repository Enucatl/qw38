2048-token Quartz prefill writes a retained JSON report whose eight named
categories sum to that same run's host wall time. Record synchronized CUDA
events on the prompt compute stream around exclusive GPU stages, record host

remainder of wall minus the exclusive named work. Do not capture Nsight
Systems or Nsight Compute; the timed `sync_tokens` run is the evidence.

## Implementation decisions

### What "live" means

The attributed 2048-token `sync_tokens` run is the timed run. Categories are
collected from CUDA events and the host wall clock inside that call. Do not
run `nsys` or `ncu`. Do not use a second decode-token probe as a substitute.
Do not change default `qw38-bench` throughput samples: those stay
unattributed wall times per BEN-001. The retained report is the OPT-014
fixture produced by the diagnostic that drives the production scheduler.

### New record (`cuda/full_scheduler.h`)

Add beside `RuntimeTimings`, without modifying decode field ownership:

```text
struct PrefillAttribution final {
  TimingValue embedding;
  TimingValue gdn;
  TimingValue attention;
  TimingValue ffn_mmq;
  TimingValue logits;
  TimingValue commit_sync;
  TimingValue graph;
  TimingValue other_idle;
  TimingValue wall;
  std::size_t prompt_tokens = 0;
  std::size_t evaluated_tokens = 0;
  std::size_t chunk_count = 0;
  std::uint32_t prompt_graph_launches = 0;
};
```

JSON/fixture keys for the eight summing categories are `embedding`, `gdn`,
`attention`, `ffn_mmq`, `logits`, `commit_sync`, `graph`, and `other_idle`.
`wall` is the host monotonic envelope. `0 ms` with `measured == true` means
measured empty work (expected for `graph` at 2048 tokens). Unavailable
(`measured == false`) is forbidden for those nine values on a successful
attributed run.

### API

Extend the existing optional trailing defaults; do not reorder parameters:

```text
Status execute_prompt_chunk(..., GdnScanPath gdn_scan = kParallelAssociative,
                            PrefillAttribution* attribution = nullptr);

Status sync_tokens(..., GdnScanPath gdn_scan = kParallelAssociative,
                   PrefillAttribution* attribution = nullptr);
```

Update every `friend` declaration on `ResidentModel`, `SchedulerSession`,
`SchedulerWorkspace`, and `SchedulerGraphs` to the new signatures. Existing
callers stay source-compatible. `nullptr` preserves today's event-free
prompt path.

When `attribution != nullptr`, `sync_tokens` zeros the record, sets
`prompt_tokens = token_count`, starts the host wall clock after prefix
classification and any reset, passes the pointer into each
`execute_prompt_chunk`, accumulates `evaluated_tokens` and `chunk_count`,
stops the wall clock after the last chunk returns, then sets `other_idle`
as specified below. A successful cold 2048-token sync from an empty session
must take the `chunk >= 2` branch only (one 2048-row chunk at
`prompt_chunk_rows_ == 4096`). Do not add `PrefillAttribution` into
`execute_token`; a one-token tail is out of scope for the 2K case.

### Stream-aware phase recorder (`cuda/full_scheduler.cu`)

Keep `GpuPhaseRecorder` in the translation-unit anonymous namespace.

- Store `cudaStream_t` on each phase. `begin(destination, stream)` and
  `end()` record start/stop on that stream (`cudaEventRecord(event, stream)`).
  Decode `execute_token` keeps passing the default `stream = nullptr`.
- `begin_phase` gains `cudaStream_t stream = nullptr`.
- After `collect()`, add `reset()` that destroys recorded events, zeros
  `count_`, and clears `active_`, so a later chunk can reuse the recorder.
  2048 tokens is one chunk; reset still belongs in `sync_tokens` so an 8K
  caller would not overflow the 132-slot array.
- Do not enlarge the 132-slot array for this task. One attributed chunk
  uses embedding + 64 mixer + 64 FFN + logits + commit = 131 phases.
- Fail closed: any create/record/synchronize/elapsed-time error returns an
  explicit status and must not store fabricated zeros.

### Category ownership (exclusive)

All GPU intervals below are sequential CUDA events on the fused prompt
compute stream (`workspace->prompt_compute_stream_`, or the null/default
stream on the unfused path). Do not add copy-stream elapsed time; overlapped
D2H wait that extends wall time lands in `other_idle`.

| Category | Owns |
|---|---|
| `embedding` | Host-to-device token copy plus batched embedding decode/widen into the FP32 residual |
| `gdn` | Layer-0 or per-layer mixer RMSNorm when this layer is GDN, all GDN MMQ projections, gate prep, parallel/sequential scan, gated output, and GDN output projection. Mixer residual add that lives inside fused FFN is not GDN. |
| `attention` | Mixer RMSNorm when this layer is attention, Q/K/V MMQ, split, tiled chunk attention, and attention output projection |
| `ffn_mmq` | Fused residual-add-norm, SwiGLU, the three FFN MMQ projections, last-layer residual add, or the ordinary fused `execute_prompt_ffn` / prompt-graph executable that replaces them. Mixer MMQ stays in `gdn`/`attention`. |
| `logits` | Final RMSNorm of the last residual row and vocabulary projection onto the compute stream. Device-to-host copies are not logits. |
| `commit_sync` | Compute-done event record, KV scatter, and compute-stream join through `cudaStreamSynchronize(compute stream)` on the fused path (unfused: scatter loop plus `cudaDeviceSynchronize`). |
| `graph` | Host monotonic time around each `cudaGraphLaunch` of a prompt FFN executable, accumulated. At 2048 tokens this is measured `0` with `prompt_graph_launches == 0`. Do not move FFN GPU work into `graph`. |
| `other_idle` | `max(0, wall - exclusive_sum)` where `exclusive_sum` is embedding + gdn + attention + ffn_mmq + logits + commit_sync + graph |

`wall` is `std::chrono::steady_clock` around the attributed `sync_tokens`
evaluated work (not model upload, not `SchedulerGraphs::create`).

Always place decode-style NVTX ranges on the prompt path, including when
attribution is null: `qw38.embedding`, `qw38.gdn` / `qw38.attention`,
`qw38.ffn`, nested `qw38.graph_launch` only when a prompt graph actually
launches, `qw38.logits`, and `qw38.state_commit`. Keep the existing
`qw38.prefill_chunk` outer range. NVTX is a label, not a stopwatch.

### Sum and documented tolerance

Define `other_idle` as the remainder so the eight categories reconstruct
`wall` by construction. Contract and tests use:

- `abs_tol_ms = 0.05`
- `rel_tol = 1e-4`

`math.isclose(sum(categories), wall_ms, rel_tol=1e-4, abs_tol=0.05)` must
hold on the live JSON and the checked-in fixture. If `exclusive_sum > wall`
by more than that tolerance, fail closed rather than clamping a negative
remainder into a fake pass. `other_idle >= 0` on a passing run.

This tolerance covers CUDA-event versus host-clock domains and JSON float
encoding. It is not a throughput gate and not an idle-fraction cap.

### Invariants

- Null `PrefillAttribution*` creates no extra CUDA events on the prompt
  path.
- Attributed events record on the prompt compute stream, not the default
  stream.
- Copy-stream D2H elapsed time is not added as a ninth GPU interval.
- Mixer MMQ belongs to `gdn` or `attention`; FFN MMQ belongs to `ffn_mmq`.
- 2048-token production chunks do not replay 4096-row prompt FFN graphs;
  `graph` is measured zero, not unavailable.
- `other_idle` is a remainder, never a fabricated profiler idle claim.
- Workspace bytes, numeric envelopes, commit isolation, and BEN-001
  throughput JSON stay unchanged.
- Failed event operations return an error; they do not emit a partial
  success report.

### Rejected alternatives

- Reusing `RuntimeTimings.token_total` as 2K wall time — decode
  `token_total` is a CUDA-event span; overloading it would break OPT-001
  and BEN-001 `component_probe`.
- Host clocks around every layer without CUDA events — CUDA work is
  asynchronous; that would measure queueing, not GPU-stream occupancy.
- Extra `cudaDeviceSynchronize` per category — would destroy OPT-011
  overlap and perturb the timed run more than stream events.
- Adding overlapping copy-stream CUDA events into the sum — would
  double-count versus wall time.
- Treating `graph` as FFN GPU time — would double-count `ffn_mmq` when
  graphs replay, and would make the 2K graph category a lie.
- Driving attribution through `qw38-bench --prefill-attribution` in this
  task — would expand the BEN-001 result schema; the production
  `sync_tokens` diagnostic is sufficient and keeps the harness contract
  frozen.
- Using the chat-rendered ~2052-token scaling prompt — BEN-001's pinned
  2K yardstick is 2048 exact tokens.
- Coupling OPT-015 — that report is separable analysis after this
  breakdown exists; it is pending on OPT-013/PIN-002, not inseparable
  documentation of this increment.
- Requiring Nsight Systems to justify categories — the ledger forbids
  making Nsight a capture dependency, and `nsys` is not in the image.
