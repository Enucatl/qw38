1. The selected `warp_query_decode_attention` repeats lane-0 RMS over 256
   elements and RoPE in each of 16 partitions per query head. Each lane then
   loads eight adjacent BF16 dimensions through scalar loop accesses. This
   differs from OPT-050's already-hoisted prompt preparation. Confirm the
   current path and >=0.10 ms/token plausible removable cost with OPT-071.
2. Implement a decode-only preparation launcher with one warp/query head,
   retaining the exact ordered FP32 norm and existing RoPE operations first.
   Write all prepared FP32 Q to the existing normalized-query workspace once;
   all 16 attention partitions consume it. Preserve observable normalized Q
   taps and separate candidate K/V preparation. Count the extra launch in cost.
3. Screen two candidates: prepared-Q only; prepared-Q plus legal 16-byte KV
   loads per lane into eight BF16 values. Keep the existing dim=lane*8+i
   mapping, reduction/softmax order and ascending-part merge. Provide an
   alignment-safe fallback. Do not add a partition-count/GQA-layout sweep or
   prefill change. No speculative overlap or approximate exponential variant.
4. Replay real Q/K/V, gate and committed/candidate caches for 16 layers.
   Include query/key prep, core, merge, gating and FP32-to-BF16 cast in the
   complete attention boundary. Prove the prepared query is refreshed for every
   new input/position and graph capture, never reused merely by pointer identity.
5. Preserve candidate versus committed KV visibility, causal masks, cache
   layout, all query heads, full outputs and cancellation. Same-path eager/graph
   and control/candidate outputs should be exact for the unchanged arithmetic;
   if a compiler association differs, require versioned calibration and full
   model quality instead of silently increasing an old tolerance.
