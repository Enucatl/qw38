# OPT-119 — Reduce activation traffic across pipeline boundaries

Status: pending. Dependencies: OPT-115, OPT-116, OPT-118. Coupled IDs: none.
Priority: P1. Predeclare prefill or decode as the measured primary target.

## Outcome and evidence

Remove repeated intermediate writes/reads across real producer/consumer
boundaries, including prompt batches where activation volumes are larger.
Read [OPT-115](OPT-115.md) and [OPT-116](OPT-116.md); use the admitted graph/
residency parent or its retained control.

Inspect [full_scheduler.cu](../cuda/full_scheduler.cu),
[scheduler_primitives.cu](../cuda/scheduler_primitives.cu),
[quant_mmv.cu](../cuda/quant_mmv.cu), [q4_prompt_mmq.cu](../cuda/q4_prompt_mmq.cu)
and current attention staging. Prior [OPT-112](OPT-112.md) deferred decode
norm→Q8 work from family aggregates; quantization time hidden inside a
projection interval was not directly measured. OPT-025/067 paired FFN and
OPT-054 microbatch work are historical controls, not reasons to repeat an
unchanged candidate.

## Implementation

1. Identify at most two material pipeline slices using actual producer and
   consumer buffer sizes/counts and complete-path timing. Examples are residual
   → norm → typed quantized input shared by compatible projections; prompt
   gate/up → SwiGLU → down input; or projection → query/key preparation →
   packed KV append. Freeze chosen boundaries and removable byte/time bounds.
2. Document exact existing encodings and BF16 rounding boundaries. Q8_1 and
   internal Q8Block are not interchangeable. A single staging buffer can be
   shared only by consumers of the same activation and quantization scheme;
   FFN down and next-layer inputs are new values and cannot reuse old scales.
3. Implement the minimal fused/streamed slice, retaining intermediates in
   registers/shared memory or shortening their lifetime where possible.
   Include synchronization, spills, occupancy loss, repeated weight reads and
   extra quantizer work. Do not assume an entire FFN/inter-layer dependency
   fits on chip or that fusion removes the compulsory dense weight sweep.
4. For prompt work, bound any microbatch/tiling adjustment to the selected
   slice and account for additional weight rereads and reduced GEMM efficiency.
   Test P2048/P4096 plus chunk tails and a long prompt; do not launch another
   broad MMQ tile sweep. No quadratic score buffer, large dequantized weight
   cache or hidden duplicate representation may fund the gain.
5. Retaining BF16 rounding should be the first variant where feasible. If
   bypassing an intermediate rounding/using a lower-bit activation improves
   the pipeline, declare it as changed arithmetic and use OPT-116 admission.
   Validate both quantizer correctness and generated text on the real fused
   production path, including graphs and prefill-to-decode.
6. Run a complete-engine screen even if an isolated fused kernel is slower,
   provided the measured enclosing-byte hypothesis remains plausible. Measure
   request bytes and E2E effect with the actual parent selectors. The old
   OPT-112 0.50 ms heuristic is not this task's admission gate; use the new
   full-path evidence and uncertainty in OPT-115.

## Acceptance and artifacts

Keep only under shared P/D/TTFT, quality, state and memory gates. Record which
materializations disappeared, which traffic moved elsewhere and the net byte
change. If neither bounded slice wins, retain existing execution. Deliver
focused producer/consumer and tail tests, machine-readable evidence and
`evidence/optimization/opt119-activation-traffic/REPORT.md`.
