# OPT-117 — Repair and evaluate complete decode-segment graphs

Status: pending. Dependencies: OPT-115, OPT-116. Coupled IDs: none.
Priority: P1. Primary target: D128/D2048 complete-request latency.

## Outcome and evidence

Test whether capture of the existing eight-layer decode segments removes real
submission/dependency gaps on post113. [OPT-114](OPT-114.md) met its launch
trigger but failed with `cannot capture CUDA scheduler FFN graphs`; that generic
error is not a root cause. [The scheduler](../cuda/full_scheduler.cu) has
`capture_decode_segment_graph`, `enqueue_decode_layer_eager`,
`SchedulerGraphs::capture` and parameter-update machinery. Reuse them, with
the current llama Q4 adapter and attention crossover included.

Read [OPT-115](OPT-115.md)'s shared protocol and [OPT-116](OPT-116.md).
The reported old ~11 ms/token is a hypothesis to validate, not promised savings.

## Implementation

1. Reproduce capture failure on authenticated post113 and locate the first
   failing CUDA call/kernel/stream, preserving both enqueue and end-capture
   errors. Inspect default-stream use, lazy allocations/initialization,
   unsupported synchronization and current adapter launch conventions.
2. Repair the minimal capture/stream/lifetime defect. Capture the real selected
   full layer body with stable storage, initialize outside capture, and prove
   the graph launches the same kernels/arithmetic as eager. Do not replace
   current kernels with a historical graph-compatible implementation.
3. Test the existing eight-layer segmentation first. Permit at most one
   alternative coarser segmentation only if measured update/launch overhead
   limits it and cancellation bounds permit it. No generic graph framework,
   persistent full-model kernel or arithmetic retuning in this task.
4. Cover positions 0/127/1023/1024/2047 and near 131072, token-to-token pointer
   swaps, session replacement, graph invalidation and growth of visible KV.
   Audit captured scalar-by-value arguments: attention crossover, visible
   length, frontier and buffer generation must update correctly. Include all
   update, boundary polling and commit costs in request timing.
5. Retain public cancellation responsiveness. Measure actual poll cadence and
   cancellation latency on eager and graph paths; do not obtain a win by
   disabling a poll callback. Inject cancellation/failure at segment and commit
   boundaries, then verify frontier/state/logits/sampler preservation.
6. Run full-engine graph/eager A/B on the production request path and original
   benchmark path, with same-path quality and state/memory tests. Compare
   measured gaps and launch counts with OPT-115 estimates; explain residuals.
   Record graph creation cost and startup amortization separately, and include
   graph memory in the live 128K fit.

## Acceptance and stop rules

Keep only under OPT-115's E2E/quality/state/memory gates, with a demonstrated
reduction in the targeted gaps. If capture remains unsupported, publish the
minimal reproducer and specific missing capability; do not record it as a
measured graph performance loss. If a working graph loses/inconclusively ties,
retain `ffn_only` and complete with that measured outcome.

Deliver raw timelines, focused graph/state regressions, task-owned summary and
`evidence/optimization/opt117-decode-segment-graphs/REPORT.md`. No claim of
reduced weight/KV DRAM traffic from launch reduction alone.
