## Outcome

Test a lossless Q4_K device layout and source-faithful MMVQ dot organization
that remove repeated scale/min unpack from current late-w4 gate/up and down.
Keep only a complete 64-layer FFN and two-prefix win; otherwise retain
`integer_q8_late`/`paired_integer`.

## Rationale

OPT-089 reduced rotating FFN from 16.38 to 9.78 ms/token, but Q4 gate/up and the
bucket containing down remain the two largest Quartz sinks. OPT-093's
paired-group arithmetic factoring regressed and stays rejected. Pinned llama
MMVQ uses a different VDR/lane mapping and packed 16-bit scale extraction; newer
llama commit `73ab7599b` makes Q4_K scale unpack branchless. This task tests
those exact mechanisms and does not assume the upstream result transfers.

## Implementation

1. Make FFN down a separately timed role before screening. Capture production
   gate/up/down inputs and exact call counts under post-098 selectors.
2. Add a source-faithful diagnostic implementation of pinned llama
   `mul_mat_vec_q<GGML_TYPE_Q4_K,1>`/`vec_dot_q4_K_q8_1` adapted to Quartz
   types. Use it to compare lane mapping, K-loop trips, reduction and generated
   SASS against late-w4; do not vendor ggml headers.
3. Add at most two production candidates: (a) branchless scale/min extraction
   with current late-w4 association, and (b) a lossless aligned metadata/code
   plane layout using the faster of the two verified dot organizations. The
   OPT-093 factored association is not a candidate.
4. If a replacement Q4 layout survives component screening, teach the current
   prompt MMQ and all Q4 fallbacks to consume it and remove the raw device copy.
   If prompt compatibility cannot preserve P4096 and the memory reserve, reject
   the layout candidate. Upload repack is outside steady-state timing but its
   memory and startup cost are reported.
5. Preserve one activation quantization for paired gate/up, exact BF16 SwiGLU
   boundary, FP32 output, Q8Block semantics and visible packed reference. Apply
   kernel_parity_v1, same-math bitwise cases, independent CPU/dequant cases and
   full successor quality.
6. Screen gate/up and down separately, but decide on complete rotating FFN.
   Apply the shared D128/D2048 and P4096 admission gates.

## Acceptance

- Candidate identity, SASS/resource deltas and exact gate/up/down timings are
  retained; a source comparison alone is not a speed claim.
- Complete FFN saves at least 0.10 ms/token with positive paired CI, both decode
  prefixes improve, and P4096/quality/state/memory guards pass.
- Any kept device layout replaces raw Q4 storage and supports decode and prompt;
  no duplicate 9.6 GB FFN copy is allowed.
- Rejection restores late-w4 and does not reinterpret OPT-093.
