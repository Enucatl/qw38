## Outcome

Implement a lossless, aligned structure-of-arrays device representation for the
production Q8_0 matrices and compatible decode and prompt consumers. Keep it
only if complete Q8 mixer work and both decode prefixes improve without a
P4096 or 128K-memory regression; otherwise retain the raw GGUF layout.

## Rationale

Quartz streams about 5.5 GB/token through Q8 input projections and 1.6 GB/token
through GDN output weights. GGUF `block_q8_0` interleaves a half scale and 32
codes in 34-byte blocks. `../ds4`'s `CUDA_DERIVED_Q8_0_ALIGNED_DENSE` separates
the scale and code planes and records 235-245 GB/s versus 150-195 GB/s on its
raw warp8 shapes. Those numbers are a hypothesis only. OPT-024 tested a prompt
D2R kernel and rejected it; it did not test a replacement layout shared by the
current Q8 decode and quality-MMQ implementations.

## Implementation

1. Add one Quartz-owned layout: 64-byte-aligned half scale plane followed by a
   64-byte-aligned int8 code plane, with exact block and tensor geometry in a
   versioned descriptor. Repack during model upload and validate byte-exact
   inverse reconstruction on admitted tensors.
2. Replacement is mandatory for a keep: rebuild device tensor offsets so raw
   Q8 payloads are not also resident. Update allocation accounting before any
   performance run. Temporary upload scratch must be bounded and released.
3. Add aligned variants for `grouped_r1_w4`, standalone Q8 output MMV, skinny
   alpha/beta MMV, current prompt quality MMA and every fallback that consumes
   a converted tensor. Do not resurrect OPT-024 D2R. Non-Q8 tensors and token
   embedding row gather remain unchanged.
4. Preserve the single shared activation quantization and grouped descriptor
   semantics from OPT-092. Compare raw and aligned paths on exact production
   shapes, rotating enough weights to defeat L2 residency. Report useful and
   measured bytes, alignment, transactions, registers, spills and occupancy.
5. Require same decoded weights and kernel parity versus independent CPU
   dequant. Same-association consumers must be bitwise equal. Run graph/eager,
   repeated-address, tails, full quality, checkpoint/cancellation and memory
   gates.
6. Apply the shared component and D128/D2048/P4096 admission protocol. A keep
   must improve both decode prefixes; the P4096 point estimate may not regress
   and its upper regression bound must be at most 2%.

## Acceptance

- The device representation is lossless, fully described and used by every
  Q8 consumer; no raw+SoA duplication remains after upload.
- Complete rotating 48-GDN/16-attention Q8 mixer time saves at least
  0.10 ms/token with a positive paired 95% interval.
- D128 and D2048 improve in the five-pair sitting; P4096, quality, state and
  128K allocation gates pass with at least 1.5 GiB free reserve.
- On rejection, raw Q8 production dispatch and allocation are restored.
- Add contract/fixture, focused CUDA tests, runner and
  `evidence/optimization/opt100-q8-aligned-layout/`.

## Non-goals

No quantization change, extra persistent copy, Q8 D2R revival, public GGUF
rewrite, approximate accumulation, or extrapolation from ds4 performance.
