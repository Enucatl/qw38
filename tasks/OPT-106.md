# OPT-106 — Freeze the post-098 recovery outcome

Status: pending. Dependencies: OPT-100, OPT-101, OPT-102, OPT-103, OPT-104,
OPT-105. Primary target: original comparative outcome gates.
Read [the post-098 protocol](PERFORMANCE-RECOVERY-POST-098.md).

## Outcome

Freeze the exact admitted combination from OPT-100 through OPT-105 and measure
it against a fresh post-098 control and pinned llama.cpp in one exclusive-GPU
sitting. Report internal improvement, llama parity and the unchanged OPT-056
+5% outcome independently; failures remain failures.

## Implementation

1. Authenticate source, build/container, model hash, selected and rejected
   candidates, effective launch identities, graph path, quality contract and
   hardware telemetry. Rejected diagnostic code must not leak into production.
2. Run the complete successor quality suite before long timing. Report
   Quartz-versus-OPT-098 regression and Quartz-versus-llama deltas separately,
   including per-case NLL, PPL, functional scores, recurrence and nonfinites.
3. In one serialized sitting run fresh `post098_control`, the admitted
   `post106_selected`, and pinned llama for P4096, D128 and D2048 using the
   original token/workload definitions. Use the established release sample
   counts, paired ordering, p50/p95 and raw samples; do not reuse old llama
   numbers for the outcome claim.
4. Rerun the original 2K gate, checkpoint/restore, cancellation/frontier,
   graph/eager equivalence and 128K memory ledger. Record cold model/repack and
   graph construction separately from steady-state P/D.
5. Publish current matched family attribution from OPT-099 instrumentation for
   the selected build. It is diagnostic and non-additive.

## Acceptance

- Evidence is complete and independently labels:
  `internal_improvement_with_quality`, `llama_parity`, and `opt056_plus5`.
- Internal improvement requires a positive paired geometric throughput result
  across P4096/D128/D2048 with no p95, quality, state or memory regression.
- Llama parity requires Quartz throughput at least llama on every workload.
- OPT-056 remains unchanged: at least 1.05x llama throughput on every workload,
  decode p95 no worse, quality pass and OPT-016 2K pass.
- Marking OPT-106 done means the sitting and honest verdicts are delivered; it
  does not mean the comparative gates passed.
- Add contract/fixture, batch runner, host validators and
  `evidence/optimization/opt106-batch-gate/`.

## Non-goals

No new optimization, selector tuning, quality concession, benchmark redefinition,
historical fixture rewrite, speculative decoding or release publication.
