## Outcome

A fast small-shape GPU parity suite, patterned after
`../ds4/cuda/mmq/test/test_mmq_parity.cu`, proves whether current shipping and
already-implemented Q4/Q8/Q6 candidates implement the intended quantized
operation. Production-shape performance remains a separate test. No model
inference. No production keep.

After this task it must be possible to answer quickly:

> Does this candidate correctly implement Q4_K/Q8/Q6 matrix arithmetic?

without running a model or collecting production-layer captures.

## Implementation

1. Inspect ds4 `test_mmq_parity.cu` organization (CPU quantize/dequant, host
   GEMM reference, `check_close`, edge/random seeds, fused vs independent
   bit-identity). Port strategy and assertions. Do not vendor ds4 MMQ kernels.
2. Consume `cuda/kernel_parity.cuh` from OPT-081 only. Delete or wrap the
   duplicate `ds4_q4k_association_ok` / `ds4_q8_association_ok` helpers in
   `cuda/quant_mmv_test.cu`, `cuda/prompt_mmq_test.cu`, and
   `cuda/ffn_tile_ab_test.cu` so one canonical implementation remains.
3. Native target `build/qw38-cuda-opt082-kernel-parity-test` (Makefile
   `cuda-opt082-diagnostics`). Deterministic generated quantized blocks and
   activations. No production activation capture. No full-model inference.
4. Required parity classes against CPU dequant at the same quantization:
   - Q4_K MMV / MMVQ decode (`packed`, `integer_q8`, `integer_q8_late`);
   - Q4_K MMQ prompt (`fma_async`, `fma_async_x`);
   - Q8_0 mixer decode (`r1_w4`, `r2_w2`) and Q8_1 staging producer/consumer
     typed checks;
   - Q6_K vocabulary/output MMV;
   - fused gate/up and down projection;
   - staging producer then consumer;
   - paired/fused versus independent paths.
5. Association envelopes (unless OPT-081 recorded a justified equivalent,
   which it must not tighten):
   - Q4_K: `abs_tol = 0.20 * sqrt(K)`, `rel_tol = 0.05`;
   - Q8_0: `abs_tol = 0.05 * sqrt(K)`, `rel_tol = 0.05`;
   - Q6_K: same as Q4_K.
   Record full failure diagnostics. Fail closed on nonfinite.
6. `same_math_equivalence` cases (bit identity unless a named tiny epsilon):
   fused vs unfused reconstruction of the same staged buffer; paired gate/up
   vs executing the same kernels separately; two consumers of one staged Q8
   buffer; packing/unpacking integer identity; eager vs captured selector
   that must not change arithmetic. Do not hide these under the Q4 association
   envelope.
7. Shape/pattern set (explicit product; keep runtime bounded):
   - M ∈ {1, 3, 17};
   - N ∈ {1} for MMV/MMVQ; N ∈ {4, 8} for MMQ;
   - K ∈ {256, 512, 2048} plus one representative near each production
     dimension 5120, 6144, and 4096 if the phase budget allows, **without**
     full production M (no M=17408, no vocab 248320);
   - patterns: zero; +/−; cancellation-heavy; min/max quant values;
     scale/min edges; odd rows (M=17); boundary K; block multiples of 256;
     seeded random; values around integer/half representability; aligned and
     valid unaligned/fallback.
   Smoke uses one family × one tiny shape. Correctness covers the listed
   product with association/same-math as declared per case. Do not time
   production performance here.
8. Prove the requested kernel launched (variant string, not a stale graph or
   packed fallback when a candidate ident is selected). Host tests are
   GPU-free and mutate K/M, dtype, staging tags, and nonfinite payloads.
