# OPT-054 — Tune internal prefill batches without early commit

Status: done. Dependencies: OPT-049, OPT-051, OPT-052, OPT-053. Coupled IDs: none.
Primary target: P. Read [the shared protocol](PERFORMANCE-RECOVERY-2026-09-10.md).

## Why and scope

The user notes Quartz moved from a 2K default to ds4's 4K default. Larger batches
can improve weight reuse and amortize launches, but are not monotonically faster
once kernels are saturated. The retained llama benchmark uses n_ubatch=512.
This task measures physical execution size while preserving the **4096-token
logical transaction** and the existing frozen P benchmark. It does not change
the default just because llama uses 512, or claim a long-context speed win.

## Implementation

1. Add an internal diagnostic microbatch selector for 512/1024/2048/4096 rows.
   In `cuda/full_scheduler.cu::execute_prompt_chunk`, evaluate all 64 layers for
   each chronological microbatch, using optimized kernels from dependencies.
   The final microbatch alone needs full vocabulary logits. Maintain embeddings
   and intermediate residual lifetimes per microbatch; do not rerun old tokens.
2. Carry private GDN convolution/recurrent state from one microbatch to the next.
   Attention reads committed KV plus all earlier **uncommitted** rows in this
   outer transaction, and its current microbatch candidate rows. This requires
   explicit logical position vs scratch-row indexing; `start_position` alone
   must not misclassify earlier candidate rows as committed cache. Keep an
   outer candidate KV staging range and read accessor or equivalent layout.
3. Publish state/frontier/tokens/logits only after all microbatches finish.
   Cancellation or error at any internal boundary discards the whole outer
   transaction. Do not implement by repeatedly calling public sync/eval, which
   would commit early. Preserve prefix reuse, checkpoint behavior and caller
   progress/cancellation semantics. Bound scratch for 128K capacity.
4. For initial A/B disable prompt graphs in **both** batch controls to isolate
   batch-size effects, then measure the candidate's final graph-enabled shipping
   path. Provide corresponding FFN graph shapes for a kept internal batch size
   or show the candidate wins complete wall even without them. Never compare
   an eager candidate to graphs-on baseline and attribute all difference to M.
   Do not remove the existing 4096 path until the complete candidate passes.
5. Run full P and diagnostic 2K from empty context. Also compare a 4K append at
   prefixes 2048/4096 for causal working-set sensitivity, labeled diagnostic
   (not the historical P denominator). Test long-context correctness and memory
   where required, but honor OPT-016's prohibition on longer speed gates.

## Acceptance

Choose the simplest fixed internal size that wins complete cold P under the
shared protocol and does not regress D. Keep 4096 if no smaller candidate wins.
Retain the full sweep and explanation; do not add an adaptive chunk heuristic
based on one run. OPT-044 admits cross-size arithmetic drift; exact atomic
isolation, restore and token/frontier invariants remain mandatory.
Add task contract/fixture, `tests/test_opt054_prefill_microbatch.py`, and

even in cancellation tests after internal batches 1, 2, or the final batch.
