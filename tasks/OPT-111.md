## Outcome

Implement a source-backed prompt-attention adapter only after identifying the
remaining differences from the shipping OPT-079 `kv_once` pipeline. Prove the
base pinned-style kernel on equivalent prompt buffers first, then screen one
current-llama XOR-swizzle variant only if a measured bank-conflict or shared
memory signal justifies it. OPT-051's `f16_async` is historical ancestry, not
the performance control. This task is independent of the decode attention work
in OPT-108.

## Evidence and rationale

Quartz is 6.6% below the fresh llama P4096 throughput (3036.84 versus 3252.58
tok/s), a 7.1% uplift to parity—not the 4.1% historical estimate. OPT-099's
493.87 ms versus 37.89 ms attention-family totals are diagnostic and
non-additive, so they identify an area to investigate but not a recoverable
13x wall-time budget.

OPT-051 admitted F16 operands, register softmax, and asynchronous staging in
`f16_async`; it also recorded slower nbatch64 and GQA6 alternatives. OPT-079
then admitted `kv_once`, which converts each async BF16 K/V stage to F16 once
and reuses it, saving about 11.5 ms over complete P4096 attention. Shipping
production is therefore `kv_once`. This task must document the concrete
algorithmic delta from that path rather than treating OPT-051 techniques or
OPT-079 conversion reuse as untested. The local current-llama commit
`e4b9af007` (XOR swizzle for F16 flash-attention K/V shared tiles) is technique
inspiration only; the pinned llama revision remains the release comparator.

## Implementation

1. Diff the pinned `fattn-mma-f16` launch and kernel against the selected
   OPT-079 `kv_once` path. List the exact remaining differences in query/KV
   tiling, shared-memory layout, MMA fragments, online softmax, causal mask,
   GQA mapping, partition selection, fixup, output combine, and K/V conversion
   lifetime. Do not rewrite a component that is already identical without a
   measured reason, and do not count OPT-079's conversion-reuse saving as a new
   candidate gain.
2. Adapt the pinned-style base path as a Quartz-owned, model-specialized kernel
   and run it first in a same-buffer prompt harness. Include all preparation,
   conversion, fixup, and combine costs in the comparison. If the base path does
   not win on the matched primitive, stop; do not integrate a swizzle.
3. Screen exactly one additional candidate: the base path plus only the
   source-backed K/V shared-memory XOR swizzle from `e4b9af007`, and only when
   counters or generated assembly show a bank-conflict/transaction hypothesis.
   No arbitrary tile or swizzle sweep.
4. Reuse a compatible F16 prompt cache from another admitted task only if its
   conversion and memory cost are measured. Otherwise keep candidate-only F16
   operands and include conversion in complete attention and P4096 wall time.
5. Preserve full causal attention, rotary positions, Q/K normalization,
   attention scale, output gate, candidate/committed KV visibility, and exact
   atomic publication. Keep strict references and unrelated translation units
   unchanged.

## Acceptance and stop rule

- The matched base primitive must beat the shipping OPT-079 `kv_once` control
  before integration. Then require at least 20 ms/P4096 complete-attention
  saving with a positive paired 95% interval and a strictly faster P4096 point
  estimate within the existing 2% regression bound.
- Quality, causality, state, prompt-to-decode handoff, graph, and memory gates
  must pass. If the base path loses, do not test the XOR candidate. If only the
  XOR candidate loses, retain the base winner only if its complete and
  end-to-end gates pass.

unmeasured swizzle/tile search, speculative decoding, decode-cache redesign,
current llama HEAD as authority, or new benchmark semantics.
