# OPT-049 — Share decode FFN staging and fuse gate/up

Status: pending. Dependencies: OPT-046, OPT-047, OPT-048.
Primary target: D2048. Read [the shared protocol](PERFORMANCE-RECOVERY-2026-09-10.md).

## Test execution contract (mandatory)

The test author must define `smoke`, `correctness`, and `acceptance` commands
in this dossier and make the new GPU test require `QW38_CUDA_TEST_TIER`, failing
closed when it is missing. Smoke is limited to compile/small probes, correctness
uses reduced samples without model-scale P/D oracles, and acceptance alone may
record performance evidence; each tier must list its phases, sample counts,
model loads, and skipped work. Reuse cached builds/binaries and emit phase
timestamps so implementation loops cannot launch the expensive default.

## Change

Optimize `cuda/full_scheduler.cu::execute_ffn` in two independently measured
steps. First stage normalized input once and call gate/up prequant launchers;
today both calls to `launch_quant_mmv` stage the same vector again. Second add
a paired gate/up Q4_K launcher sharing activation loads and computing SwiGLU
in its epilogue. Both projections have independent accumulators and scales.
Keep the residual/norm and down leg on their already accepted kernels.

Use the same admitted SwiGLU function and preserve the single BF16 rounding
before down activation quantization. A later epilogue may directly produce the
down Q8_1 stage only if it first reproduces this BF16 rounding, then performs
each 32-value maximum/sum with correct ownership. No storing a partial group
before every value is available. Compare paired-only against paired-plus-stage
fusion; increased registers can outweigh saved traffic. Do not add a separate
gate/up weight copy merely to concatenate matrices: a two-pointer kernel is
enough for this model.

References: pinned llama `mmvq.cu` optional fusion argument/GLU epilogue;
ds4 `cuda/mmq/ds4_mmq_d2r.cuh` fused gate/up/down-stage pattern. Borrow the
data-flow idea only; ds4 routing weights, sanitization and clamps are not Qwen
semantics. OPT-043 determines whether llama actually uses its fusion here.

## Acceptance

Retain separate-leg selected kernels as the control, and compare all three
projections plus stage/SwiGLU/residual/norm as one complete FFN. Test actual
layer activations, every BF16-to-Q8 boundary, graph/eager equality within each
path, and candidate-state isolation. Recapture the 64 decode FFN graphs after
changing their nodes. Apply OPT-044 and full P/D guards. Add task fixture/pin,
`tests/test_opt049_decode_ffn_fusion.py`, and
`evidence/optimization/opt049-decode-ffn-fusion/`. Run new host/native test,
`tests/test_cuda_fusion.py`, `tests/test_cuda_graph.py`,
`tests/test_cuda_full_scheduler.py`, and production-numerics.
