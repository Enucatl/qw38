# OPT-129 — Compare matched Quartz and llama decode-attention components

Status: done. Dependencies: OPT-125. Coupled IDs: none.
Priority: P1.

## Outcome

Determine whether decode attention itself is slower, by how much, and why.
The OPT-124 0.620× number is a whole-workload ratio with a timing issue; it is
not an attention ratio. This task changes diagnostics only and leaves
`hybrid_crossover@1024` shipping.

## Implementation

1. Inspect current `cuda/attention_decode.cu`, dispatch in
   `cuda/full_scheduler.cu`, and the pinned llama revision's actual
   `ggml/src/ggml-cuda/fattn*` consumers. Local sibling HEAD may inform source
   analysis but must not silently replace authority
   `cc83d7b4824f73cfdda4dfbb47ee39804f71b328`. Record actual launched
   implementation; flash-attn auto configuration alone is not proof.
2. Build a bounded replay harness from identical Q/K/V values and populated
   cache prefixes for representative attention layers 3/7/63. Freeze head
   counts/dimensions, GQA grouping, causal mask, scale, strides, alignment,
   query position, capacity and output semantics. Measure attention core
   separately from normalization/RoPE, KV insertion, gating and output
   projection; then measure that enclosing attention branch.
3. Native Quartz BF16 KV and llama f16/f16 are not identical representations.
   Provide a common-input/common-dtype/common-layout comparison supported by
   both consumers, with conversion setup explicitly excluded only from the
   labeled kernel replay. If neither can consume a common layout without an
   adapter, implement a diagnostic adapter and report its cost separately and
   in the enclosing path. Also retain native-layout/native-dtype measurements
   and quantify numerical differences; never call those identical arithmetic.
4. Freeze prefixes 128, 1023, 1024, 2048, 8192 and 32768 with boundary neighbors
   where dispatch needs them. One populated near-128K check is resource
   conditional. Match visible prefix and allocated capacity. Use repeated
   resident replay to measure components and normal state evolution to check
   cache warmth bias. Authenticate inputs/outputs by hashes and tolerances.
5. Attribute launch count, merge/reduction cost, KV rereads, GQA reuse, actual
   DRAM/L2 traffic where counters permit, occupancy and dispatch topology.
   Explain the 1024 crossover on the current combined stack. No unbounded
   tile search and no precision change to production.
6. Rank at most two causal transfers into OPT-130: estimated removable branch
   milliseconds and enclosing request benefit, required layout/workspace,
   numerical risk and source/license provenance. If attention is not material,
   publish that result and make OPT-130 an explicit no-opportunity outcome.

## Acceptance

Deliver replay inputs or reproducible generation, per-shape raw component
and enclosing timings, actual kernel identities, numerical comparison and
`evidence/optimization/opt129-matched-attention/REPORT.md`. Distinguish native
engine comparisons, matched-layout comparisons and adapter-inclusive cost.
A unavailable common-layout baseline limits the conclusion; it must not be
reported as a matched result. No production selector change or speed claim.
