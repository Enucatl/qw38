# OPT-068 — Measure scoped optimized CUDA compilation

Status: pending. Dependencies: OPT-059, OPT-061. Coupled IDs: none.
Primary target: the single most promising remaining projection family.
Read [the batch protocol](PERFORMANCE-RECOVERY-2026-09-11.md).

## Scope

The Makefile still uses `-O2 --fmad=false` for every CUDA TU. Explicit FMA keeps
do not prove that compiler scheduling, invariant hoisting or contraction elsewhere
are optimal. Compare a small, isolated build set; never enable fast-math for
host code, strict references, finite checks or the entire engine.

## Implementation

1. Use OPT-061 to choose **one** family: cooperative Q4 decode, Q8 decode, or
   Q4 prompt MMQ. Record the choice before compiling variants. Prefer an existing
   focused TU; if prompt MMQ is chosen, extract only its optimized instantiations
   and launch wrappers to a new TU. Do not move all of `quant_mmv.cu` or include
   device template definitions in `full_scheduler.cu`.
2. Compare exactly three builds: existing `-O2 --fmad=false`, `-O3 --fmad=false`,
   and `-O3 --fmad=true`. Same architecture, algorithm, tile, launch dimensions
   and input bytes in all three. Do not add `--use_fast_math`, FTZ, approximate
   reciprocal/divide/sqrt or `-maxrregcount` in this experiment. Explicit
   `__fmul_rn`/`__fadd_rn` remain noncontracting; state that if it limits changes.
3. Give binaries/object directories unique identities and use OPT-057 flag
   invalidation. Link otherwise identical engine configurations. Record exact
   flags and selected object hashes in each result, rather than mutate one
   shared object while tests run. Strict object flags and symbols stay unchanged.
4. Inspect ptxas/SASS for FMA scheduling, register count, spills and code size.
   An instruction count decrease is a hypothesis, not acceptance. If O3 makes
   no code/performance difference, retain O2; no flag change for cosmetic reasons.
5. Test numeric outputs on reference-only/held-out OPT-059 inputs. Contraction
   may change rounding and needs production admission; O3 with unchanged
   arithmetic should normally preserve output but still gets tested. Install
   a scoped Make rule only for an accepted family, with its strict control
   retained for diagnostics and future regression checks.

## Fast tests and commands

Target `build/qw38-cuda-opt068-codegen-test` with three distinct object variants;
pytest `tests/test_opt068_codegen.py`. Host tests verify selected flags/objects,
strict isolation and rebuild-on-flag-change. Smoke: one tiny family case,
three builds, one sample each. Correctness: three builds ×two small patterns
and 16 rows × 4 held-out captures at the chosen production K, shared references.

Screen: three builds ×one chosen rotating family set ×(1 warmup+3 paired
samples). Compilation counts against the 300-second feedback budget; first-time
compilation setup is reported explicitly. If three compiles exceed that budget,
compare the two noncontracting builds first, then the FMA build as a separately
named phase. Do not repeatedly compile unchanged candidate objects.

```sh
uv run pytest -q tests/test_opt068_codegen.py
uv run python tools/run_optimization_task.py --task OPT-068 --mode feedback
uv run python tools/run_optimization_task.py --task OPT-068 --mode acceptance
```

## Acceptance and stop rule

Use the batch component gate and corresponding P4096 or D2048 target. Require
complete cost improvement, v2 quality and no hidden changes to strict/host
objects. Deliver contract/fixture and
`evidence/optimization/opt068-scoped-codegen/REPORT.md`. Record rejected flags
and retained control. No unbounded compiler-flag search and no wholesale
performance claim from SASS or a smoke timing.
