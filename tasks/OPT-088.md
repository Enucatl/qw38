# OPT-088 — Combined post-reset production gate

Status: pending. Dependencies: OPT-079, OPT-085, OPT-086, OPT-087. Coupled IDs: none.
Priority: P0. Target: freeze the new combination under the new contracts.
Read [the post-080 protocol](PERFORMANCE-RECOVERY-POST-080.md).
Quality risk: interactions among accepted arithmetic and `kv_once`.
Instrumentation: reuse; throughput is uninstrumented on the release sitting.

## Outcome

Freeze the final production combination from:

- selected Q4 path (OPT-085);
- resolved Q8 path (OPT-086);
- resolved MMQ path (OPT-086);
- OPT-079 `kv_once` unless this sitting's full-model quality exposes an
  interaction (revert `kv_once` only with a documented quality/performance
  failure, not a missing OPT-074 envelope);
- any candidate formally kept in OPT-087.

Run the full new quality suite and final performance gates. Report
independent kernel-parity, model-quality, Quartz-vs-baseline quality delta,
Quartz-vs-llama quality delta, recurrence/state, P4096, D128, D2048, decode
p95, llama parity, OPT-056/+5% if that historical target remains active, and
release eligibility.

Do **not** reinterpret OPT-080. OPT-080 remains the historical final gate for
the previous batch and previous validation policy. This task supersedes it
only for the new production combination.

## Implementation

1. Each dependency needs a concrete keep/reject/no-go, or an explicit
   `no_additional_reopen`. Never treat missing kernel-parity or quality
   infrastructure as an acceptable rejected dependency.
2. Freeze current source/build/flags, actual launch selectors, model/token
   identity, kernel-parity status per modified arithmetic family, graphs,
   buffers, and read-back power. Rebuild/recapture only changed artifacts.
3. Cheap preflight: two same-path graph/eager tokens, full finite logits,
   OPT-083/084 quality alarm subset (32 held-out + eight functional parsed
   answers), one D2048+32 control/candidate pair if any selector changed.
   Failed required quality stops release execution. Absolute task-accuracy
   fail inherited from the OPT-084 baseline does not by itself block if the
   combination does not regress that baseline; a new regression does.
4. Publish distinct fields: `kernel_parity_pass` per family;
   `model_quality_pass`; `quartz_vs_baseline_quality_delta`;
   `quartz_vs_llama_quality_delta`; `recurrence_state_status`;
   `performance_pass`; `production_kept`; `release_eligible`. A combination
   may be quality-pass/performance-fail or the reverse. Do not relabel
   historical OPT-056/016.
5. Once eligible, run the full OPT-083 suite with `--quality`. Then unchanged
   OPT-021 cold P4096 (0 warmups, 3 replicates), OPT-032 D128/D2048 (3
   warmups + 30 runs of 256 predetermined tokens per prefix/engine), and
   original OPT-016 2K protocol. All timed configurations use consistent
   publication/copy/state semantics. Compute parity as Tq−Tl and +5% as
   Tq−Tl/1.05, separately from raw p95.
6. Checkpoint, cancellation, 128K post-graph fit, and relevant long-context
   recurrence/attention quality on the final combination. Internal component
   wins cannot substitute for no-worse decode p95 or the ≥5% outcome
   requirement. Reports and fixtures must agree.

## Acceptance

- Independent status for every modified arithmetic family (Q4, Q8, MMQ, and
  any OPT-087 keep) plus `kv_once`.
- OPT-080 report unmodified. OPT-016 and OPT-056 stay blocked unless their
  **owning** conditions actually pass under their original rules.
- Host tests reject incomplete family parity, quality reduced to one boolean,
  OPT-074-unadmitted as a blocker, and historical-gate relabeling.

explicit long-mode plan and is never reached from smoke/correctness/screen.

or declare success. No automatic next optimization sweep.
