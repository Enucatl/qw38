## Why and when

Prompt FFN already stages Y once, but `full_scheduler.cu` still launches gate
and up MMQ separately and writes both FP32 matrices before SwiGLU/Q8 staging.
Pairing can reuse loaded Y and avoid those two global outputs, at the cost of
more accumulators and possibly lower occupancy. This is conditional: use
OPT-061 traffic/timing to estimate a saving of at least5 ms/prompt. Otherwise
record a no-go without writing a large fused kernel.

Read prompt FFN flow in `cuda/full_scheduler.cu`, `quality_mma_process_tile`,
the existing `launch_swiglu_quantize_mmq_q8_1` path in `quant_mmq_mma.cuh`, and the
OPT-065 resource table. Preserve the original GGUF layout and shared-Y staging.

## Detailed implementation

1. Add a focused paired-Q4 kernel with two weight pointers and one staged-Y
   pointer. Use I64/J64 for the initial paired candidate to bound accumulator
   registers; compare against the best existing separate implementation from
   OPT-065, not an artificially small separate tile. Add no other paired tile
   unless the first compiles and screen succeeds within budget.
2. Reuse the existing Q4 load/scale/min and MMA fragment mappings. Extract only
   the small internal load/accumulate helper needed to call the same arithmetic
   for gate and up; preserve the original separate kernel as control. Maintain
   `gate_sum[I*J/256]` and `up_sum[I*J/256]` per thread. For each K block, load Y
   once, unpack gate into the existing X tile and update gate_sum, barrier,
   then reuse X storage for up and update up_sum. Y remains live for both.
3. Use the control's FMA semantics and accumulation order for each leg. Do not
   combine gate and up sums, round them early, or use integer accumulation
   across differently scaled K groups. Test fragment ownership with distinct
   gate/up inputs so swapping them is detectable.
4. At each owned `(prompt,row)` output, apply existing SwiGLU and write one
   BF16 activated value. Use the existing separate Q4 MMQ activation quantizer
   afterward, preserving the prior BF16 rounding boundary. This avoids the two
   FP32 output matrices without inventing cross-CTA32-channel quantization.
   Compare its extra standalone staging launch to the existing fused
   SwiGLU+Q8 stage as part of complete cost.
5. Keep synchronous guarded output/prompt tail handling with all CTA threads
   participating in barriers. Use a small explicit FFN prompt selector; paired
   decode and prompt selectors are separate. Diagnostic taps may use the
   separate control to expose gate/up, with that fallback labeled.
6. Do not remove global workspace buffers in this task; other paths still need
   them. Report avoided traffic, actual additional shared/register bytes,
   occupancy, spill traffic, launch count and actual scratch high-water mark.
   Combining OPT-066's new X pipeline with this new kernel belongs in a later
   separately measured configuration, not an untested default combination.
