## Implementation decisions

Keep decode `q8_mmv_bf16` / `launch_quant_mmv` unchanged. Keep large mixer Q8 GEMMs on OPT-022 I=128 / J=128 quality MMA with shared residual D4 Y. Keep `launch_q8_mmq_bf16_reference` as the row-wise kernel and `launch_q8_mmq_bf16_variant` as the OPT-009 tiled kernel. Do not route production Q8_0 through `launch_quant_mmq` or `launch_quant_mmq_mma`. Rank-1 `launch_q8_mmq_mma` stays callable and non-production.

### Skinny predicate

```
output_rows > 0 && output_rows < 128 && prompt_rows >= 8 && kind == kQ8_0
```

Production hits: GDN α and β only (`output_rows=48`, `columns=5120`). Attention key/value at 1024 stay on I=128. Do not special-case the name `alpha`; the predicate is shape-based so any future mixer Q8 with `output_rows < 128` follows the same path.

Export `bool skinny_mixer_q8_output_rows(std::size_t output_rows) noexcept` and `const char* selected_skinny_mixer_path()` from `cuda/quant_mmv.h`. Pin the A/B winner string in `pins/opt023_skinny_mixer_contract.json` as `selected_skinny_mixer_path` and hard-code the same enumerator in the dispatcher.

### Paired CUDA-event A/B (required)

Run on exclusive RTX 5090 inside `cuda/quant_mmv_test.cu` (or a sibling diagnostic compiled the same way). Shape is production α/β: `prompt_rows=4096`, `output_rows=48`, `columns=5120`, Q8_0. Protocol: 0 warm-ups, 3 CUDA-event replicates, arithmetic mean of the three samples, occupancy ≥ 1, zero non-finites. D4 Y for MMA candidates is quantized once **outside** the timed region (production already has that Y for packed_qkv/value_gate). Write every sample to `evidence/optimization/opt023-skinny-mixer/skinny-ab-raw.txt`.

Candidates (fixed set; do not add PromptTile sweeps or I=16):

| id | Path | Activation | Notes |
|---|---|---|---|
| `mma_i128_j128` | current `launch_q8_mmq_quality_mma` | prequantized D4 Y | baseline; I=128 Fallback |
| `mma_i32_j128` | quality MMA, templated I=32, J=128 | same D4 Y | small-tile MMA; 48 → two I-tiles (32+16 Fallback) |

Winner rule: lowest arithmetic mean among candidates that launch, occupancy ≥ 1, zero non-finites, and meet the numeric gate below, **and** that mean is **strictly less** than the `mma_i128_j128` mean. Equality or a slower candidate is not a win. If no skinny candidate strictly beats the baseline, A/B loses: do not install skinny production dispatch.

Do not time decode `q8_mmv_bf16` in a 4096-launch loop. Do not vendor llama.cpp MMVQ. Do not change production J for large GEMMs.
