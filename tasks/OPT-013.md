## Goal and boundaries

Replace the production prompt GDN path's sequential 64-token window loop with a
chunkwise associative scan: all windows of a prompt chunk run the existing
gated-delta arithmetic from a zero initial state in parallel (one CUDA block
per value-head × window) and store each window's affine operator `(A_w, B_w)`,
then a 48-block exclusive prefix of those operators (one `A_w S + B_w` matvec
per window, not a 4,096-token homogeneous replay) produces each window's
incoming `S_in`, then a second value-head × window grid replays the existing
sequential gated-delta body from that prefix. Keep GDN-002's sequential window
kernels as the byte-exact reference. Parallel versus
sequential results must stay inside the frozen GDN-002 envelopes (maximum
absolute error `5e-8`, maximum RMS `5e-9`, zero non-finite values) across
internal 64-token windows and outer 4,096-versus-64-row chunk boundaries.
Committed convolution/recurrent bytes and the frontier stay unpublished during
prepare. A paired CUDA-event A/B at production 4,096 tokens must show a strictly
lower parallel mean than sequential.

- Constraints: keep C++17, CUDA 13.0.2, `sm_120`, `--fmad=false`, BF16
  activation/KV storage, FP32 residual and GDN recurrence, production
  `GdnConfig{16, 48, 128, 128, 4}`, GDN-002 `kScanWindow = 64`, OPT-008
  `kPromptChunkRows = 4096` and `prompt_chunk_rows_ = min(4096, capacity)`,
  OPT-011 fused overlapped production plus retained unfused serial path,
  OPT-012 prompt FFN graphs (GDN stays outside graphs), SES-002
  candidate-versus-committed isolation, and all frozen GDN-001/GDN-002/SCH-002/
  OPT-008/OPT-011/OPT-012 numeric and exact-state gates on the algorithms they
  originally admitted. Do not add a persistent session or workspace
  `cudaMalloc`; parallel scratch overlays `prompt_projected_bf16_` only.
  Workspace byte formula `160,380,416 + 96*C + 404,992*R` stays unchanged. Do
  not edit `Makefile`; build the new diagnostic with the same explicit pinned

## Implementation decisions

Keep decode one-token GDN, GDN commit, sequential window kernels, MMQ, attention,
prompt FFN graphs, `kPromptChunkRows`, workspace byte formula, checkpoint
pack/unpack, and public APIs unchanged. Add an associative prompt scan beside
the sequential kernels: overlay scratch holds `(A_w, B_w)` pairs on existing
prompt BF16 (`W_fit(4096) = 22`), a 48-block `A S + B` prefix replaces the
failed 4,096-token homogeneous inter, and a `[value_heads, W]` from-state
grid replays sequential window arithmetic. Wire production prompt chunks to
the parallel path when one pair fits.

### Affine operator (must match `prepare_recurrence_window`)

For one value head, normalized key `k`, scalar `α = exp(log_decay)`, scalar
`β`, and value row `v`:

```text
S_t = α (I − β k kᵀ) S_{t−1} + β k vᵀ
y_t = qᵀ S_t
```

`q` is L2-normalized then divided by `sqrt(key_width)`; `k` is L2-normalized
without that scale; epsilon is `1e-6f`. Value lanes are independent. The
map `(A, B) = (α(I − βkkᵀ), βkvᵀ)` composes as
`(A2, B2) ∘ (A1, B1) = (A2 A1, A2 B1 + B2)`.

Materialize each window's dense `A_w` (`value_heads × key_width × key_width`
FP32, production `48 × 128 × 128 = 786,432` floats — equal to `B_w` because
admitted configs have `key_width == value_width`). Do not materialize
per-token `A` or extra session workspace. For a 64-token window starting at
`S = 0`, the sequential gated-delta loop produces `B_window = S_end`. The
same homogeneous body with `v = 0` applied to the identity (one column per
value-lane thread, `lane < key_width`) produces `A_window`. Then
`S_{w+1} = A_w S_w + B_w` is one `__fmul_rn`/`__fadd_rn` matvec per window
(64 iterations at 48 blocks), not 4,096 homogeneous token steps.

After that prefix, replay `prepare_recurrence_window` arithmetic from `S_in`
on grid `[value_heads, W]` so `y` uses the sequential window FMA order.
Do not add a homogeneous 4,096-token correction on grid `[48, 1, 1]`.

Homogeneous `v = 0` (for `A` accumulation only) must be the existing body
with `value[lane]` replaced by `0.0f`, including `__fmul_rn` / `__fadd_rn` /
`expf` / `sqrtf` / `__syncthreads` order.

### API (`cuda/gdn_step.h`)

```text
enum class GdnScanPath : std::uint8_t {
  kSequentialWindows = 0,
  kParallelAssociative = 1,
};

std::size_t gdn_scan_window_count(std::size_t token_count) noexcept;
std::size_t gdn_scan_operator_values(const GdnConfig& config) noexcept;
std::size_t gdn_scan_scratch_floats(const GdnConfig& config,
                                    std::size_t token_count) noexcept;
```

`gdn_scan_window_count` is `ceil(token_count / 64)` for `token_count > 0`,
else 0. `gdn_scan_operator_values` is
`value_heads * key_width * key_width` (0 if the config is invalid).
`gdn_scan_scratch_floats` is
`gdn_scan_window_count(token_count) * (gdn_recurrent_values(config) +
gdn_scan_operator_values(config))` (0 if the config is invalid). Peak scratch
holds all `B_w` then all `A_w` for the batch.

Extend `launch_gdn_prepare_chunk` and `launch_gdn_prepare_chunk_tiled` with
three optional trailing arguments:

```text
GdnScanPath path = GdnScanPath::kSequentialWindows,
float* scratch = nullptr,
std::size_t scratch_floats = 0
```

`launch_gdn_prepare` and `launch_gdn_prepare_tiled` keep calling the chunk
launcher at `token_count == 1` with the sequential default. Existing GDN-001/
GDN-002/scheduler-primitive callers stay byte-identical.

Validation additions for `kParallelAssociative`:

- `token_count == 0`, null pointers, or aliased committed/candidate still
  return `cudaErrorInvalidValue` (same as today).
- `scratch == nullptr` or
  `scratch_floats < gdn_recurrent_values(config) + gdn_scan_operator_values(config)`
  returns `cudaErrorInvalidValue` (need at least one `(A, B)` pair).
- `path` not in `{kSequentialWindows, kParallelAssociative}` returns
  `cudaErrorInvalidValue`.
- Sequential path ignores scratch.

### Sequential path (unchanged arithmetic)

`kSequentialWindows` keeps today's host loop over 64-token windows:
`prepare_convolution_window` then `prepare_recurrence_window`, first window
from committed, later windows from candidate. Do not change those two
kernels. GDN-002 chunk-versus-tokenwise `memcmp` remains true.

### Parallel path

For `kParallelAssociative` and `token_count > 1`:

1. **Convolution (one launch for the whole chunk).** Add
   `prepare_convolution_chunk_parallel` with grid
   `dim3((channels + 255) / 256, token_count)` and 256 threads. Thread
   `(channel, token)` computes the width-4 causal ring from committed
   history plus `input[0..token]`:

   ```text
   committed = [h0, h1, h2, h3]  # oldest → newest
   token t history[i] = (t + i + 1 >= 4)
       ? input[(t - (3 - i)) * channels + channel]
       : committed[i + t + 1]
   ```

   for `convolution_width == 4`; generalize as
   `history[i] = (t + i + 1 >= width) ? input[t - (width - 1 - i)] : source[i + t + 1]`.
   Dot with `__fmul_rn`/`__fadd_rn`, SiLU `x / (1 + expf(-x))`, store
   token-major output. Only `token + 1 == token_count` writes the ending
   ring to `candidate`. This is data-parallel FIR, not a scan, and is
   byte-exact versus the serial ring because each token's four inputs are
   the same values.

2. **Recurrence, `num_windows == 1`.** After convolution, launch the
   existing `prepare_recurrence_window` once (committed → candidate). One
   window has nothing to compose; two-pass would add work and change ULPs
   for 2–64-token tails. Occupancy stays 48 blocks; the 4,096-token case
   is the occupancy win.

3. **Recurrence, `num_windows >= 2`.** Let
   `pair = gdn_recurrent_values(config) + gdn_scan_operator_values(config)`
   and `W_fit = scratch_floats / pair` (≥ 1 by validation). Batch windows
   in strides of `W = min(W_fit, remaining)`. Layout for a batch:

   ```text
   B[w] at scratch + w * recurrent_values
   A[w] at scratch + W * recurrent_values + w * operator_values
   ```

   After the prefix kernel, `B[w]` is overwritten in place with `S_in[w]`.
   `A[w]` is dead after that window's matvec. Partial last windows use
   `min(64, remaining tokens)`.

   **Intra kernel** `prepare_recurrence_windows_zero`:
   grid `dim3(value_heads, W)`, block 128 threads (same lane mapping as
   today). `blockIdx.y` is the batch-local window. Each block runs the
   existing sequential gated-delta loop over its window tokens with state
   starting at **0**, working storage `B[local_window]` (ends as
   `B_window`). Fuse `A` accumulation in the same token loop: thread
   `lane` owns column `lane` of `A` when `lane < key_width`, starting from
   `I`, using the homogeneous `v = 0` body; write `A` to the A slice at
   window end (registers for the column, not a 64 KiB `__shared__` tile —
   that occupancy drop is forbidden in this fat grid). Do not write session
   candidate. Skip stores to `recurrent_output` (overwritten by the
   from-state kernel). Honor `value_is_tiled` with the same `source_head`
   mapping as `prepare_recurrence_window`.

   **Prefix kernel** `scan_window_prefix_states`:
   grid `dim3(value_heads)`, block 128 threads. 64 iterations of
   `A @ S + B`, not 4,096 token steps. Running `S` starts as committed
   recurrent for batch 0, else the candidate written by the previous
   batch. For each local window, each lane (one value column):

   ```text
   s ← S column
   b ← B[local] column
   store s into B[local]          # S_in overwrites B
   S column ← A[local] s + b      # __fmul_rn / __fadd_rn, k_in inner
   ```

   After the last local window, write `S` to candidate recurrent (the
   from-state kernel overwrites this with sequential-window FMAs from
   `S_in`; the prefix write is only the chain input for a following batch).
   Do not use 64 KiB shared `A` or `S`. Do not load `q` or update `y`.
   Do not rebuild `A` from `k, α, β` in this kernel (that reintroduces
   4,096 serial steps at 48-block occupancy).

   **From-state kernel** `prepare_recurrence_windows_from_state`
   (replace `apply_window_operators`):
   grid `dim3(value_heads, W)`, block 128 threads. `blockIdx.y` is the
   batch-local window. Source is `B[local]` (`S_in`). Working state is
   that same slice in place (same `__syncthreads` token loop as
   `prepare_recurrence_window`). Write `y` into `recurrent_output`. The
   last local window of the batch writes ending `S` to candidate
   recurrent. This is the occupancy win that serial inter lacked.

   Production `R = 4096` overlay yields `W_fit = 22`, so a 4,096-token
   layer is three batches (22 + 22 + 20): one convolution + three intra +
   three prefix + three from-state versus today's 128. Diagnostic-owned
   scratch sized for 64 windows is one batch: one conv + one intra + one
   prefix + one from-state. The speedup A/B uses that diagnostic 64-window
   scratch, not the overlay 3-batch path.

   Envelope rule: `S_in` from `A S + B` is allowed to differ in ULPs from
   a homogeneous token chain; `y` and candidate `S` then follow sequential
   window FMAs from that `S_in`. Parallel versus sequential must still
   meet `5e-8` / `5e-9` / zero non-finite (current headroom at 4096 was
   `max_abs = 2.23517418e-8`). If a first repair pass exceeds the
   envelope, only retune the prefix matvec loop order to match the
   homogeneous `key_lane` `__fmul_rn`/`__fadd_rn` association. Do not
   restore `apply_window_operators` on grid `[48, 1, 1]`. If envelopes
   still fail after that one retune, stop: that is a block, not an
   in-scope fallback.
