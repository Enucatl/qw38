# OPT-151 — Make long-decode QK and PV use the pinned MMA organization

Status: pending. Dependencies: OPT-135, OPT-150. Coupled IDs: none.
Priority: P1. Plan impact: none; authoritative BF16 KV retained.

## Outcome

Implement one actual tensor-core long-decode consumer, replacing OPT-137's
scalar QK/PV dataflow with output-producing MMA. Target D8192 and D32768;
closer organization is a falsifiable performance hypothesis, not a parity claim.

Read OPT-150's report and compiled dataflow, OPT-137's dossier and evidence,
OPT-111/147's existing prompt MMA implementation, pinned llama
`fattn-mma-f16.cuh`, `cuda/mma.cuh`, and the shared testing strategy. Reuse
working fragment/load/reduction helpers where they fit; do not blindly enable
`mma_qk_eight`, whose fragment mapping and precision were never established by
its zero-weight contribution.

## Candidate and boundary

Candidate ID: `decode_attention_qk_pv_mma_v2`. Freeze one D256/GQA6 design and
the parent left by OPT-149 before timing. Primary files are
`cuda/opt137_dense_mma_decode.cuh`, `cuda/attention_decode.cu`,
`cuda/attention_decode_path.cuh`, and necessary graph/workspace integration.
Reuse current runners and quality/state/memory hooks; add a focused native
correctness check, task contract/provenance and evidence, without a new backend.

- Map six real query heads into eight GQA columns sharing K/V tiles. Both
  QK scores and probability-times-V output must consume MMA accumulators.
  Use pinned tiled online-softmax rescaling and fragment organization, with
  FP32 accumulation and explicitly recorded operand/probability rounding.
  No scalar full-QK/PV duplicate or dummy MMA as a substitute for the new core.
- Adapt pinned load/stage organization to dense BF16: convert each loaded
  tile once to F16, reuse across heads, preserve Quartz physical strides and
  the in-flight candidate row. Reuse bounded existing staging facilities;
  preserve required synchronization and tail masks. No whole-cache conversion
  per token, persistent F16 shadow, cache/checkpoint dtype change or quantization.
- Record actual threads, shared bytes, registers, stages, tile size, padded
  heads and partition formula versus pinned llama. Start with its applicable
  specialization; do not assume OPT-137's eight warps match native geometry.
  Freeze graph-bucket partitions before screening, preserving live frontier,
  prebuilt segment topology and cancellation checkpoints. Keep the existing
  position>=8192 boundary for this arithmetic experiment.
- Include query preparation, conversion, all partials, merge and output gate
  in family cost. Preserve prefill, short decode and state semantics. Retain
  file-level MIT attribution and identify all adaptations.
