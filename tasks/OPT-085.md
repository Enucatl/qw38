## Implementation

1. Every OPT-083/084 dependency needs keep/reject/no-go, or an explicit
   blocked outcome with a working unchanged production control. Never treat
   missing llama GPU coverage or unresolved selected arithmetic as an
   acceptable rejected dependency.
2. Cheap preflight: two same-path graph/eager tokens, finite logits, 32
   held-out targets, eight functional cases (≤16 generated tokens), one
   D2048+32 control/candidate pair, parsed quality outcomes, v3 admission
   records. Any required **regression/PPL/recurrence/hard-correctness**
   failure stops release execution. Absolute quality-v2 remaining failed
   does not by itself forbid recording kernel keeps already pinned, but it
   does block OPT-056/release claims and must stay visible.
3. Engine-level llama differential with limits frozen before this sitting's
   candidate outputs (hidden taps, logits, top-1, continuation, reset/replay).
4. If preflight regression quality passes, run full selected quality then
   unchanged OPT-021 P4096 (0 warmups, 3 cold replicates), OPT-032 D128/D2048
   (3 warmups + 30 × 256 predetermined tokens), and original OPT-016 2K.
   Uninstrumented timing. Checkpoint, cancellation, 128K post-graph fit on
   the final combination.
5. Parity is `Tq-Tl`; +5% is `Tq-Tl/1.05`; decode p95 is separate. Report
   same-sitting llama. Internal component wins cannot substitute for those
   gates.
6. If original absolute quality remains blocked, deliver that preflight
   verdict plus an explicit diagnostic performance plan; do not run a
   futile release or declare success. No automatic next sweep.
