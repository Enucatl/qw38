## Entry condition

Every candidate dependency has an explicit keep, rejection or justified no-go.
A rejected candidate leaves a working production control. No nonfinite or
invalid quality baseline may be carried into a performance release claim.
This task is the deliberate long sitting; it does not fit the five-minute loop.
Cheap preflight must stop it before the long work when the combination is invalid.

## Implementation and evaluation

1. Freeze the combined configuration: all effective selectors, per-family
   staging/admission, tile/row grouping, compiler object flags, graph choices,
   batch size and relevant workspace bytes. Capture actual launch records once
   using OPT-060 and verify gate/up/down all execute the intended Q4 path.
   Disable instrumentation for timing. Compare against the most recent accepted
   whole configuration, with original OPT-056 results retained as history.
2. Resolve combinations rather than assume independent wins multiply. In
   particular, prompt pairing and packed-X pipelining may be alternative kernels;
   select the measured complete winner. Do not default to their untested product.
   Graphs must be rebuilt for the final configuration and output-buffer addresses.
3. Run a cheap preflight: same-path graph/eager replay, finite logits, functional
   v2 cases,32 held-out teacher-forced targets and one short D2048 control/candidate
   pair. Run affected checkpoint/cancellation/allocation smoke checks. Failed
   preflight stops release immediately and points to the smallest failing
   configuration/captured input. No automatic baseline/tolerance rewrite.
4. Run complete v2 quality: the two 1024-target spans against actual pinned
   llama references, the short/long recurrence pair, all eight functional cases,
   full-vocabulary finite checks and teacher-forced logit/margin diagnostics.
   Keep strict reference primitive checks separate. Report legacy QLT-001 and
   OPT-056 functional verdicts as historical/current legacy results alongside
   v2; do not treat a corrected prompt suite as retroactive passage of the old one.
5. Run unchanged OPT-021 P4096 and OPT-032 D128/D2048 protocols on both engines,
   exclusive GPU and same read-back power/clock conditions. Original P uses
   zero warmups/three cold replicates; original decode uses 3 warmups+30 runs
   of256 predetermined tokens at each prefix. Reuse reference image/model
   authentication and compiled binaries; preserve exact workload semantics.
   Quartz control/candidate comparisons alternate whole runs or short blocks;
   avoid thousands of correlated tokens masquerading as independent samples.
6. Add matched-token full-engine diagnostic results only as separate records.
   Report P/D mean throughput, paired uncertainty where applicable, token p95,
   run-mean p95 and current same-sitting llama numbers. Recompute equivalent
   milliseconds carefully: parity gap is `Tq-Tl`; +5% throughput gap is
   `Tq-Tl/1.05`. Do not label the parity gap as the gap to the +5% bar.
7. Run original OPT-016 2K parity and the existing128K post-graph allocation,
   checkpoint and atomic cancellation checks on the final combination. These
   are release boundaries, not another task's per-edit work. Rerun long-context
   quality when state/attention/GDN arithmetic changed or its existing release
   evidence no longer covers the selected combination.
8. Report three distinct outcomes: internal improvement with quality, parity
   versus current pinned llama, and the unchanged OPT-056 requirement of >=5%
   throughput lead with no worse decode p95 and its own quality conditions.
   Keep OPT-056/OPT-016 blocked unless their actual respective gates pass.
   If legacy functional requirements need formal replacement by v2, propose
   that as an explicit versioned outcome with reasons; do not mark old passage.

the 300-second feedback deadline and is not release evidence.

```sh

uv run python tools/run_optimization_task.py --task OPT-069 --mode feedback --phase preflight

```

Release dry-run must enumerate all engines/configurations, prefixes, warmups,
replicates and output tokens. At the old28 ms/token, Quartz decode output alone
costs about237 seconds per prefix/configuration before prefill, graph setup or
llama. Budget and report the full sitting in minutes; never advertise this as
a five-minute check. Resume completed, identity-matched phases if interrupted;
do not mix timings from unrelated hardware states into a same-sitting claim.
