# OPT-120 — Evaluate physically packed 8-bit and 4-bit KV caches

Status: pending. Dependencies: OPT-115, OPT-116. Coupled IDs: none.
Priority: P1. Primary target: long-context decode; D128/D2048 remain guards.

## Outcome and source evidence

Reduce actual persistent attention-cache bytes and decode reads, including
quantization metadata and append/conversion work. The current 16-layer GQA
cache occupies 8 GiB at 131072 tokens; it is much smaller at D128/D2048.
Capacity savings alone therefore do not predict the headline decode gain.
Read [OPT-115](OPT-115.md) and [OPT-116](OPT-116.md).

At ds4 revision `c238077a87186381bf626cc531bccffe1fef79e7`,
`fp8_kv_quantize_row`, `fp8_kv_quantize_store_rows_kernel` and
`indexer_hadamard_fp4_kernel` in `../ds4/ds4_cuda.cu` quantize numerically but
write floats; the raw-cache API validates `sizeof(float)` storage. These are
not ready-made 8/4-bit resident caches. DeepSeek's compressed/indexed attention
is model-specific. Inspect llama's `ggml/src/ggml-cuda/fattn-vec.cuh` quantized
K/V specializations at both the pinned revision and source-inspection HEAD.
[KIVI](https://arxiv.org/abs/2402.02750) supplies a research precedent for
asymmetric K/V quantization; its other-model/batched results do not establish
Qwen quality or single-session speed.

## Implementation

1. Freeze a maximum of three candidates after baseline traffic inspection:
   a block-scaled 8-bit K/V cache; 8-bit K with 4-bit V; and 4-bit K/V only
   if the prior stages pass quality and show plausible total savings. Choose
   FP8 or integer 8-bit once from consumer feasibility, not a format sweep.
   Predeclare grouping, scales, clipping and any bounded high-precision recent
   window. Calibration inputs are disjoint from quality admission cases.
2. Specify physical bytes and append layout for Qwen's 24 query heads, four
   KV heads, 256 head width and 64 rotary dimensions. Evaluate K/V sensitivity
   separately. Preserve post-RoPE semantics and all causal positions; no token
   eviction, learned compressor, sparse indexer or dropped attention heads.
3. Store packed bytes/scales as the authoritative cache. Prompt append,
   short/long decode and prompt attention over an existing prefix must consume
   the same format with fused unpack into registers/shared memory. No full
   cache expand-to-F16/F32 before each token, nor persistent dense shadow.
   Include scales, padding, tails, append kernel and a recent window in both
   memory and traffic accounting.
4. Test independent quantize/dequantize references, outliers, zeros, saturation,
   incomplete blocks, split groups at chunk boundaries and crossover 1024.
   Run actual cache-reading NLL and free-running long-context cases from
   OPT-116, including 131040+32 and retrieval across the whole prefix.
5. Define format/version compatibility for in-memory state and checkpoints;
   save packed values and scales losslessly and restore identical continuation.
   A legacy checkpoint may use an explicit conversion or be rejected before
   mutation; never silently interpret an old dense payload as packed state.
   Cover append rollback, divergent-prefix replay and graph pointer updates.
6. Measure fresh post113 A/B at D128/D2048/D8192/D32768 and the bounded 128K
   workload, plus P4096 and prompt-to-decode. Record quantize/dequantize cost,
   actual byte reads, p95 and peak allocation. Select at most one full cache
   design. Preserve short-context behavior unless the common guard passes;
   any context-dependent switch must include conversion cost and correctness.

## Acceptance and artifacts

Require shared keep gates and complete successor quality/state/128K evidence.
Publish throughput and memory verdicts independently: a smaller cache with no
speed benefit is not an E2E speedup. Stop a precision stage on quality failure;
do not loosen OPT-116 or add an unplanned fourth variant. Deliver format and
checkpoint checks, byte/timing/quality records and
`evidence/optimization/opt120-packed-kv/REPORT.md`.
