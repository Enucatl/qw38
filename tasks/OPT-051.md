## Change in bounded stages

Work in a focused optimized sibling of `cuda/fattn_mma_f16.cuh`, retaining the
current dual-F16 stream-K implementation. Reference pinned llama's
`fattn-mma-f16.cuh` KQ_C/VKQ_C fragments, softmax reductions, `nstages` and
`flash_attn_ext_f16_load_K`/mask loaders. Preserve exact causal/GQA semantics.

1. Using prepared Q from OPT-050, compare conventional F16 Q and probability
   operands (FP32 score/output accumulation) with the current hi+lo path.
   Keep BF16 persistent KV; convert loaded KV to the admitted operand format.
   This can remove the extra QK/PV correction MMA operations, but only OPT-044
   quality results can admit it. Avoid making the entire pipeline depend on
   single-F16 admission: hi+lo remains a valid fallback.
2. Assign each warp complete score/output fragments. Keep online max, denominator
   and output fragments in registers. Warp-reduce score maxima/sums across
   their actual fragment layout; replace the current one-thread-per-query
   serial scan and shared score round trips where possible. Use the standard
   online update `m'=max(m,max(s)); l'=exp(m-m')*l+sum(exp(s-m'));
   O'=exp(m-m')*O+exp(s-m')*V`, finally `O/l`. If exp2 is used, convert score
   scale by log2(e) consistently; do not mix exponent bases. Handle wholly
   masked tiles/empty KV partitions without NaNs or division by zero.
3. Start with 32 KV rows, then measure 64/128. Compare one-stage to two-stage
   asynchronous global-to-shared copies with explicit wait/barrier ownership.
   Inspect supported SM120 instructions; do not assume SM100 TMA/tcgen support.
   Budget doubled shared memory and record occupancy/spills. Loading the next
   tile may overlap compute only after all readers of the old buffer finish.
4. Compare the existing three serial pairs of GQA heads with one CTA sharing
   a KV tile across six query heads. Bound query rows to 8/16/32 and require
   complete-cost wins; six heads can increase registers enough to lose.
   Keep existing two-partition scheduling initially. Revisit persistent work
   scheduling only if new counters show tail imbalance after these changes.

Test/admit each stage before combining it. A failed stage is omitted while an
independently faster, numerically valid stage can be retained. Do not conflate
new arithmetic with OPT-041's historical byte-equal ownership optimization.
