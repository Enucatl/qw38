## Implementation decisions

### Payload policy (exact; no sampling)

Headers cannot produce distributions. Implementation **must** read every in-scope payload.

1. **Coverage.** Stream **every one of the 1199 tensors**, including deferred vision. Vision is coarse in markdown, not skipped on disk. Embeddings and `lm_head` are in-scope in detail.
2. **No sampling.** Do not subsample elements, tensors, layers, or shards. Exact **MEASURED** statistics are required and feasible: 55.6 GiB sequential I/O is minutes of disk; 27.78e9 BF16 values fit a one-pass stdlib histogram plus directional reductions; 31 GiB RAM is enough for 8 MiB chunks, not for a 52 GiB load. Therefore sampling is **not** required by disk, RAM, or time, and is forbidden. No seed, no fraction, no approximate labelling.
3. **Read strategy.** For each shard: parse the safetensor header with TASK-01 `_parse_safetensor_header` (payloads unread at that step). For each tensor, `seek` to file offset `8 + header_len + data_offsets[0]` and read the payload in successive chunks of `CHUNK_BYTES = 8 * 1024 * 1024` (8,388,608 bytes; last chunk shorter). Do not `read()` an entire shard or an entire tensor (embed/lm_head are 2.54 GiB each). Do not `mmap` a whole shard.
4. **Memory bound.** Peak extra allocations per tensor: one chunk buffer (≤ 8 MiB), the 65,536-bin signed BF16 histogram (`list` of 65,536 Python ints, reused), a 65,536-entry float64 LUT (process-global), and directional float64 vectors of length `d_out` and `d_in` (embed worst case: 248,320 + 5,120 values). Never retain more than one tensor’s streaming state. Do not decode the full tensor to float32 in RAM.
5. **BF16 decode.** Safetensors BF16 is little-endian uint16. Assert `sys.byteorder == "little"`. Interpret each pair of bytes as `uint16` via `array.array("H")` (or `memoryview(...).cast("H")`). Convert with the IEEE 754 **binary32** bit layout that matches BF16: 1 sign bit, **8-bit exponent**, 7-bit mantissa, then 16 zero mantissa bits:
   `struct.unpack("<f", struct.pack("<I", (u16 & 0xFFFF) << 16))[0]`.
   Build one process-global LUT of 65,536 `float` values at startup (`lut[u] = bf16_bits_to_f32(u)`). This is exact for every finite BF16, including subnormals, ±0, Inf, and NaN. Not IEEE binary16 (5-bit exponent). Stdlib only (`struct`, `array`); **no numpy**.
6. **Exact global stats from the 65,536-bin histogram.** Every uint16 code increments `hist[u]`. Global statistics that depend only on the multiset of values (n, min, max, absmax, mean, mean_abs, rms, std, zeros, |w| percentiles, outlier counts) are computed from `hist` and `lut` after the tensor is fully read. This is **order-independent** and **MEASURED exact** for BF16’s finite alphabet. Do not emit the 65,536 bins in JSON.
7. **Non-finite values.** After the histogram is complete, count codes with BF16 exponent 255 (`(u & 0x7F80) == 0x7F80`) as Inf/NaN. Assert `n_nonfinite == 0` on every tensor (exit 1). Weights with Inf/NaN are a checkpoint error, not a distribution to summarize.
8. **Missing checkpoint.** Directory, `config.json`, `model.safetensors.index.json`, or any of the 18 shards absent → print the missing path on stderr and **exit 2**. Same `MissingCheckpoint` contract as TASK-01. Verifier treats exit 2 as blocked, not a content fail.
9. **First pass on headers.** Call `inventory_checkpoint(checkpoint)` before payload I/O. Reuse TASK-01 fail-closed asserts (family partition, dtypes, shapes, occupancy, byte totals). Then stream payloads. Do not treat the header inventory as a substitute for payload stats.

### Statistics lock — requested global and directional

All payload-derived numbers below are **MEASURED**. Do not compute reconstruction/quantization error, NLL, KL, cosine reconstruction, or bit-width scores.

#### Global (per tensor, then exact family/global pools)

Computed from the signed 65,536-bin histogram and the LUT:

| Key | Definition |
| --- | --- |
| `n` | element count (`numel`) |
| `min` | minimum signed finite value |
| `max` | maximum signed finite value |
| `absmax` | `max(|w|)` |
| `mean` | `sum(w) / n` |
| `mean_abs` | `sum(|w|) / n` |
| `rms` | `sqrt(sum(w²) / n)` |
| `std` | **population** std: `sqrt(max(0, sum(w²)/n − mean²))` |
| `n_zero` | count of ±0 (`uint16` `0x0000` and `0x8000`) |
| `fraction_zero` | `n_zero / n` |
| `p50_abs`, `p90_abs`, `p99_abs`, `p99_9_abs`, `p99_99_abs` | percentiles of **\|w\|** at 50, 90, 99, 99.9, 99.99 |
| `n_out_6x`, `frac_out_6x` | count / fraction with `|w| > 6 × p50_abs` |
| `n_out_10x`, `frac_out_10x` | count / fraction with `|w| > 10 × p50_abs` |
| `n_nonfinite` | always `0` after the assert; include in pooled JSON as `0` |

**|w| percentile method (locked):** nearest-rank on the magnitude histogram of finite codes. Magnitude bin `mag = u16 & 0x7FFF` for finite values (`mag ≤ 0x7F7F`). Let `N = n` (equals `n_finite` after the non-finite assert). For percentage `p`, `rank = min(N, max(1, ceil(p/100 × N)))` (1-based). Walk `mag` from `0` to `0x7F7F` accumulating counts until the cumulative count is `≥ rank`. The percentile is `lut[mag]` (non-negative). This is **not** the average of two central values. JSON keys use underscores: `p99_9_abs` is 99.9, `p99_99_abs` is 99.99.

**Outlier thresholds** use that same `p50_abs`. If `p50_abs == 0`, every nonzero finite value counts as above `6×` and `10×`; zeros do not.

**Family and grand-total global stats** are **exact pooled** histograms (sum of member `hist` arrays), not averages of per-tensor percentiles. Percentiles of a family are the percentiles of the concatenated weights.

#### Directional (rank-2+ weights only)

Transformers / plan convention: \(W\in\mathbb{R}^{d_\text{out}\times d_\text{in}}\) stored as shape `[d_out, d_in]`, C-contiguous, axis 0 = rows = `d_out`, axis 1 = columns = `d_in`, `y = Wx`.

During the same sequential pass, maintain float64 vectors:

- `row_absmax[d_out]`, `row_sumsq[d_out]`
- `col_absmax[d_in]`, `col_sumsq[d_in]`

Initialize absmax to `0` and sumsq to `0`. For linear index `i` in row-major order: `row = i // d_in`, `col = i % d_in`, `v = lut[u]`, `a = abs(v)`; update those four running values. After the tensor:

- `row_rms[r] = sqrt(row_sumsq[r] / d_in)`
- `col_rms[c] = sqrt(col_sumsq[c] / d_out)`

Report **summaries of those vectors**, not the vectors themselves (except family-level max/median **ratios** per layer, which are scalars):

| Key | Definition |
| --- | --- |
| `n_rows`, `n_cols` | `d_out`, `d_in` |
| `row_absmax_min/median/max` | min / median / max of `row_absmax` |
| `row_rms_min/median/max` | min / median / max of `row_rms` |
| `col_absmax_min/median/max` | min / median / max of `col_absmax` |
| `col_rms_min/median/max` | min / median / max of `col_rms` |
| `row_absmax_max_over_median` | `row_absmax_max / row_absmax_median` (scale variation) |
| `row_rms_max_over_median` | `row_rms_max / row_rms_median` |
| `col_absmax_max_over_median` | `col_absmax_max / col_absmax_median` |
| `col_rms_max_over_median` | `col_rms_max / col_rms_median` |

**Median of a small float vector** (row/col absmax/rms of length `d_out` or `d_in`, and the list of per-tensor absmax/rms across layers): Python `statistics.median` (even length → mean of the two central values). This is **only** for these short vectors, never for |w| percentiles.

**Zero-median ratio:** if median `== 0` and max `== 0`, ratio `= 1.0`. If median `== 0` and max `> 0`, JSON `null` (not Inf).

**Rank-1** (all language/MTP norms, `linear_attn.A_log`, `linear_attn.dt_bias`, `linear_attn.norm`, `self_attn.q_norm`, `self_attn.k_norm`, matching MTP rank-1 tensors): `directional.applicable = false`. No row/col reductions.

**Rank-3 `linear_attn.conv1d`:** checkpoint shape `(10240, 1, 4)` = `(C_out, C_in/groups, K)`. Squeeze axis 1 (always 1). Treat as rank-2 `(10240, 4)`: axis 0 / `d_out` = 10,240 qkv channels, axis 1 / `d_in` = 4 kernel taps. C-contiguous layout already groups the last two dims as 4 consecutive BF16s per output channel, so the rank-2 walker with `n_rows=10240`, `n_cols=4` is correct without a copy.

**Rank ≥ 3 other than squeezed conv1d** (vision patch embed `(1152, 3, 2, 16, 16)` and similar): no directional stats. Vision is coarse; skip directional I/O reductions for **all** `vision.*` families even when a vision tensor happens to be rank-2.

#### Layer comparison within each major family

**Major families** are the language level-2 ids whose occupancy is 64, 48, or 16:

- 64 layers: `input_layernorm`, `post_attention_layernorm`, `mlp.gate_proj`, `mlp.up_proj`, `mlp.down_proj`
- 48 layers: `linear_attn.A_log`, `linear_attn.conv1d`, `linear_attn.dt_bias`, `linear_attn.in_proj_a`, `linear_attn.in_proj_b`, `linear_attn.in_proj_qkv`, `linear_attn.in_proj_z`, `linear_attn.norm`, `linear_attn.out_proj`
- 16 layers: `self_attn.q_proj`, `self_attn.k_proj`, `self_attn.v_proj`, `self_attn.o_proj`, `self_attn.q_norm`, `self_attn.k_norm`

Layer index is the integer in `model.language_model.layers.{i}.…`. Assert the 64-set is `{0,…,63}`; the 48-set is `{i: i % 4 != 3}`; the 16-set is `{3,7,11,15,19,23,27,31,35,39,43,47,51,55,59,63}`.

For each major family, from the per-tensor `absmax` and `rms` lists (aligned with `layer_index`):

- `absmax_min` / `absmax_max` / `absmax_median` (`statistics.median`)
- `absmax_min_layer` / `absmax_max_layer` — layer index of the extrema; **ties → lowest layer index**
- same six fields for `rms`

JSON also stores the full `layer_index`, `absmax`, and `rms` arrays so markdown can cite extrema without dumping 64-row tables. For rank-2 (and squeezed conv1d) major families, also store per-layer `row_absmax_max_over_median` and `col_absmax_max_over_median` (JSON `null` allowed) plus the max of those ratios and the layer that attains it (ties → lowest index).

Do **not** claim that a layer is a quantization winner. Extrema identify variation, not policy.

MTP families have occupancy 1: `layer_comparison` is JSON `null`. Report the single tensor under MTP headings. Embed, `lm_head`, `final_norm`: occupancy 1, `layer_comparison` null, dedicated markdown section for embed/`lm_head`.

#### Family rollup (both, frozen)

1. **Exact pooled** global stats from the merged histogram (authoritative for family n/min/max/absmax/mean/mean_abs/rms/std/zeros/percentiles/outliers).
2. **Unweighted mean** of per-tensor `absmax` and of per-tensor `rms` (`unweighted_mean_absmax`, `unweighted_mean_rms`).
3. **Parameter-weighted mean** of the same: `sum(stat_i * n_i) / sum(n_i)` (`weighted_mean_absmax`, `weighted_mean_rms`).

For uniform-shape language families, (2) and (3) coincide; still emit both. Do **not** average percentiles across tensors.

Keys: `n_layers` (int), `layer_index` (int array), `absmax` (float array), `rms` (float array), `absmax_min`, `absmax_min_layer`, `absmax_median`, `absmax_max`, `absmax_max_layer`, `rms_min`, `rms_min_layer`, `rms_median`, `rms_max`, `rms_max_layer`. Rank-1 major families omit those eight directional keys.

**directional** object:

- Rank-1 language/MTP, and every vision family: `{"applicable": false}`
- Rank-2 language/MTP and squeezed conv1d: `applicable` true, plus `n_rows`, `n_cols` (ints), the twelve min/median/max keys for row/col absmax and rms, and the four max/median ratio keys (float or `null`). For major families, those per-tensor directional summaries are **not** all stored; the family `directional` object stores **unweighted means** of the per-tensor ratios (`unweighted_mean_row_absmax_max_over_median`, `unweighted_mean_col_absmax_max_over_median`, `unweighted_mean_row_rms_max_over_median`, `unweighted_mean_col_rms_max_over_median`) together with `n_rows`/`n_cols` (uniform per family) and `applicable: true`. Per-layer ratio arrays live under `layer_comparison`. For occupancy-1 rank-2 families (`embed`, `lm_head`, MTP rank-2), `directional` holds the single tensor’s full twelve min/median/max values plus four ratios (no unweighted-mean keys).
